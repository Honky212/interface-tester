🧪 InterfaceTester

一站式 HTTP(S) 接口测试工具 — 写 YAML → 自动转 pytest → 发请求 → 断言 → 出报告
📦 v5.0.1 🐍 Python ≥ 3.8 📜 Apache-2.0 🔄 派生自 HttpRunner v4.3.5 🖥️ 纯命令行 · 无 Web 界面

💡 一句话理解

你的 xxx.yml
─ hrun ─►
xxx_test.py
─ pytest ─►
发请求 + 断言
─►
终端结果 / HTML 报告
核心思想：YAML 描述"调哪个接口、带什么参数、期望返回什么"， 框架自动完成剩下的全部工作。不用写 Python，不用管 pytest 怎么串。

⚡ 核心能力一览

🌐 HTTP 全方法 开箱即用

GET / POST / PUT / DELETE / PATCH / HEAD / OPTIONS，支持 JSON / 表单 / 文件上传 / 代理 / 客户端证书 / 流式读取。

🎯 断言（22 个内置算子）开箱即用

相等/数值/长度/包含/正则/类型/JSON Schema 契约断言、XPath/XSD XML 断言、自定义算子。

🔗 变量与函数 开箱即用

$var / ${func()} / ${ENV(名)} / ${parameterize(csv)}，自定义函数放 debugtalk.py 即可。

📊 数据驱动 开箱即用

列表 / CSV / 函数，多组参数做笛卡尔积。一条用例自动跑多组数据。

🔐 认证 OAuth2 内置

OAuth2 Client Credentials 内置；Basic / 签名 / 加密 / JWT 可写 debugtalk.py 实现。

🔄 用例复用 开箱即用

testcase: 引用其他用例 + export 导出变量；步骤级 hook（发请求前后插逻辑）；步骤级重试。

🗄️ SQL 查询 可选扩展

RunSqlRequest（MySQL），可 extract + validate，验证接口写入是否真落库。

📦 导入器 hconvert 开箱即用

curl / HAR / Postman / OpenAPI → 标准 YAML 用例（自动脱敏 + 自动断言）。

📈 报告与日志 开箱即用

--html 单文件报告（离线可看）、--junitxml（CI）、logs/*.run.log、summary.json。

🤖 AI 协作 进阶

haify gen（从接口文档生成草稿）、analyze（失败诊断）、fix（自愈建议）、review（人工确认门）。

🔬 Thrift / SOAP 实验性

Thrift RPC（仅 Linux/macOS）；SOAP/XML 请求 + XPath/XSD 断言（需 xml extra 或零依赖退路）。

⚠️ 能力边界：HTTP 4xx/5xx 不会自动判失败——成败完全由你的 validate 决定，每个步骤都要写断言！ 不支持：WebSocket、gRPC、MQ（Kafka/RabbitMQ）、TCP/UDP、UI 自动化、性能压测。详细清单见 能力清单.md。

🧱 你自己建项目只需 3 个文件

照着 examples/quickstart/ 抄即可：

文件作用能不能省
debugtalk.py 🏠 门牌号：框架靠它认出项目根目录。所有相对路径（schemas/、data/、上传文件）都以它为基准。顺带放自定义函数。 强烈建议别省（哪怕空文件也行）
.env 📝 环境信息（接口地址、账号密码），用例里用 ${ENV(名字)} 取。换环境只改这一个文件。 可选
testcases/xxx.yml 🧪 用例本体：config（全局配置）+ teststeps（步骤列表）。 必须
为什么 debugtalk.py 这么重要？没有它，项目根目录会退化成"你敲命令时所在的目录"——换个目录跑就报"找不到文件"。这是一个空文件就够，但删了就会出问题的东西。

🔄 核心工作流

1. 拿到接口文档
→
2. Postman/curl 手工调通
→
3. 写 YAML（或 hconvert 导入）
4. hrun 跑一遍
→
5. 失败→看日志→改 YAML→重跑
→
6. 全通过→出报告

⚡ 新手三条铁律

① config.name 和每个 step 的 name 必填

缺了直接报 TestCaseFormatError。

② 每个请求步骤都要写 validate

HTTP 4xx/5xx 不会自动判失败！没有断言的步骤，"请求返回 500"也算通过。

③ *_test.py 是生成物，永远不要手改

改了下次 hrun 会被覆盖。要改就改 .yml。

📦 内核模块职责（interfacetester/）

模块职责关键入口
cli.py 命令行入口：注册 hrun / hmake / hconvert / interfacetester 四个命令，解析参数并分发到对应子流程 main(), main_hrun_alias(), main_convert_alias()
loader.py 用例加载引擎：读取 YAML/JSON → 变量渲染（$var / ${func()} / ${ENV()}）→ 参数化展开 → 输出结构化 TestCase load_testcase(), load_project_data()
parser.py 表达式解析器：递归解析变量引用、函数调用、环境变量；处理字符串模板与嵌套结构 parse_variables_mapping(), parse_parameters()
make.py 代码生成器：将结构化 TestCase 转成 pytest 测试脚本（*_test.py），调用 black 格式化；含覆盖保护（防止误改手写文件） make_testcases()
runner.py 执行调度器：编排步骤顺序、管理会话级状态（提取变量传递）、汇总结果 InterfaceTester.run()
step_request.py HTTP 请求步骤：发送请求 → 提取（jmespath）→ 断言分发 → 记录日志 RunRequest.run()
step_testcase.py 用例引用步骤：testcase: path 的加载、export 变量导出、嵌套执行 RunTestCase.run()
step_sql_request.py SQL 步骤（可选 extra sql）：MySQL 查询 + extract + validate RunSqlRequest.run()
step_thrift_request.py Thrift RPC 步骤（仅 Linux/macOS）：二进制协议请求 + 字段类型转换 RunThriftRequest.run()
models.py Pydantic v2 数据模型：TConfig / TStep / TRequest / TValidate 等结构化定义，驱动全链路类型校验 TConfig, TStep, TRequest
response.py 响应对象封装：统一 body / status_code / headers / elapsed / cookies 访问接口 ResponseObject
client.py HTTP 客户端：requests.Session 封装，处理 TLS / 代理 / 证书 / 流式 / 重试 HttpClient
config.py 全局配置：项目根目录定位（debugtalk.py 锚点）、.env 加载、base_url 合并 Config
builtin/comparators.py 22+ 内置断言算子：equal / contains / regex_match / jsonschema_match / xpath_match / xml_schema_match 等 comparator_*()
builtin/functions.py 内置工具函数：get_timestamp() / sleep() / environ() 等 builtin_functions
converters/ 导入器（4 个适配器）：curl / HAR / Postman / OpenAPI → IR → YAML；含脱敏、自动断言生成、黄金文件校验 curl_adapter, har_adapter, postman_adapter, openapi_adapter
compat.py 兼容性层：生成文件识别、旧格式迁移、跨版本兼容 is_generated_conftest()
exceptions.py 异常体系：ParamsError / TestCaseFormatError / ValidationFailure 等，区分「用户写错」（failed）与「框架故障」（error） —
utils.py 通用工具：文件读写、路径解析、日志配置、数字安全转换 ensure_int_value(), _ensure_string_shaped()

🔗 五条主链路

① 加载链

YAML/JSON → loader（变量渲染 + 参数化）→ models.TConfig/TStep 结构化对象

② 生成链

结构化对象 → make（Jinja2 模板 + black 格式化）→ *_test.py pytest 脚本

③ 执行链

pytest 收集 → runner 调度 → step_request 发请求 → response 封装 → comparators 断言

④ 汇总链

步骤结果 → session 级变量传递 → summary.json + HTML 报告 + JUnit XML + logs/*.run.log

⑤ 导入链

curl/HAR/Postman/OpenAPI → converters/*_adapter → IR → emit_yaml → 标准 YAML（自动脱敏 + 断言）

⚙️ AI 协作层（haify）运行期配置

AI 层配置只从环境变量读取，不读项目 .env（那份是用例侧的）。未配置时退出码 2 并打印指引，绝不会静默出网。

环境变量用途必填
INTERFACETESTER_AI_BASE_URLOpenAI 兼容 API 根地址（如 Ollama: http://127.0.0.1:11434/v1）✅ 是
INTERFACETESTER_AI_MODEL模型标识（如 qwen2.5:14b）✅ 是
INTERFACETESTER_AI_API_KEYAPI Key（回环地址可留空，Ollama 类无需 key）云端必填
INTERFACETESTER_AI_SANDBOXL3 安全闸门开关（默认关，设为 on 启用）推荐开启
INTERFACETESTER_AI_ALLOW_HOST非回环主机白名单（L3 只放行回环 + 此列表中的主机）非回环时必填
产物落点：草稿默认落在 .ai/draft/（不是 cases/）。 要进 CI 跑的 cases/ 必须经 haify review --approve 人工确认转正，并在 .ai/reviews/ 留痕。 带 TODO_ 占位符的草稿会被拒绝转正。

🏛️ 技术栈与设计特点

Pydantic v2 数据模型

全链路类型校验由 TConfig / TStep / TRequest 等 Pydantic v2 模型驱动，加载阶段即拦截格式错误。

pytest 生态原生兼容

生成的 *_test.py 是标准 pytest 用例，可直接使用 pytest-html / pytest-randomly / pytest-xdist 等插件。

防御性设计与护栏测试

2500+ 回归用例守护每条修复；基线数字有唯一事实来源（docs_consistency_test 对账）；假通过 / 假失败均有防线清单逐条标注。

Apache-2.0 合规

明确标注 HttpRunner v4.3.5 衍生关系；LICENSE + NOTICE 随 wheel 分发；pyproject.toml 用 SPDX 声明。
