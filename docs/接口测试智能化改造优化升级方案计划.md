# 接口测试智能化改造优化升级方案计划

> 计划版本：1.0  
> 编制日期：2026-09-26  
> 依据：[《接口测试智能化改造项目评审分析.md》](接口测试智能化改造项目评审分析.md)、`interfacetester_ai/` 当前源码、`tests/` 现有测试及 `bench/golden/` 评测材料。  
> 计划性质：实施路线与文件级改造清单；本文件不表示下列改造已实施。

## 1. 目标与不做事项

### 1.1 目标

分两层提升 AI 生成接口用例的可用性：

- **第一层：可复核初稿。** 输出结构合法、来源能定位、覆盖和未知项完整展示的候选用例；默认停在 `.ai/draft/`，经人工审核后才转入 `cases/`。
- **第二层：受限范围内自动契约测试。** 对被明确支持的契约格式和隔离环境，证明用例能运行、能检出已知契约偏差；只有所有硬门槛通过时才具备自动晋级资格。

改造要把“模型返回了 JSON”“框架能生成 pytest”“目标服务执行成功”“测试能检出契约缺陷”分成不同状态和指标，不能再由单个 `ok` 或退出码代替。

### 1.2 不做事项

- 不承诺任意自然语言文档都能无人审核生成完整、正确的测试。
- 不把模型自报置信度作为自动晋级判据。
- 不允许生成或验证流程默认请求生产服务；不新增自动修复 YAML 的能力。
- 不修改 `interfacetester/` 内核实现来承载 AI 业务逻辑。OpenAPI 优先复用现有转换器公开能力；确需内核变更时另立变更和兼容性评审。
- 不把 L2、人工 golden YAML 通过率、缓存命中率、模型产出率中的任何一项单独当作语义正确率。

### 2.1 当前需要优先收口的行为

`assembler.assemble()` 在结构与闸门通过且没有 `TODO_` 时，会将 YAML 复制到 `cases/`。这与“第一层是待复核初稿”的目标冲突。**P0 必须将生成默认落点改为 `.ai/draft/`，并将进入 `cases/` 限定为有明确审核记录的转正操作。** 不应通过给旧的 `ok` 改名来掩盖这项行为差异。

## 3. 架构目标和建议接口

### 3.1 新增纯数据模型

新增 `interfacetester_ai/contract.py`，只定义文档契约和证据数据类型，不读写文件、不调用模型。建议首版公开对象：

```python
@dataclass(frozen=True)
class SourceRef:
    source_id: str
    document_sha256: str
    start_line: int
    end_line: int
    quote: str
    evidence_kind: str  # normative / example / condition / explanation

@dataclass(frozen=True)
class ContractField:
    name: str
    location: str      # path / query / header / cookie / body / response
    type_name: str = ""
    required: Optional[bool] = None
    enum_values: Tuple[Any, ...] = ()
    minimum: Any = None
    maximum: Any = None
    condition: str = ""
    source_refs: Tuple[SourceRef, ...] = ()

@dataclass(frozen=True)
class EndpointContract:
    method: str
    path: str
    operation_id: str = ""
    auth: Tuple[str, ...] = ()
    request_fields: Tuple[ContractField, ...] = ()
    response_fields: Tuple[ContractField, ...] = ()
    source_refs: Tuple[SourceRef, ...] = ()
```

实现要求：`source_id` 从文档摘要、范围和证据类型确定性派生；不让 LLM 自己编造 ID。模型仍可输出兼容现有 `source_quote` 的 JSON；`gen.py` 在装配前把引文绑定到唯一证据节点，零命中/多义命中均记录为 `needs_review`，不能随便绑定第一个相似字段。

### 3.2 新增质量状态模型

新增 `interfacetester_ai/quality.py`，定义稳定的状态常量、状态转换校验和聚合结果：

- `generated`：已得到可解析草稿。
- `static_valid`：schema、生成/加载和静态安全闸门通过。
- `needs_review`：存在语义未知、仅协议断言、条件/认证/依赖未决等人工事项。
- `runtime_verified`：在明确环境和数据配置下执行完成并通过。
- `auto_promotable`：来源格式受支持，关键未知为零，覆盖、运行和变异门槛均达标。
- `rejected`：结构不合法、关键冲突或危险静默形态。

状态必须和历史 `ok` / `skipped` / `failed` 分开，避免破坏旧调用方。`auto_promotable` 是资格，不代表自动 apply；是否将产物转正仍由单独的策略开关和审计流程控制。

## 5. 分阶段实施工作包

实施采用顺序工作包，每个工作包先加失败测试，再实现，再跑局部测试；阶段边界允许评审/暂停。时间为初步工程估算，不含模型耗时、产品决策等待和业务接口联调。

### 阶段 0：固定评测口径与质量状态

**预计：2-3 人日。依赖：无。目标：第一层质量状态可表达、评测数据不再自相矛盾。**

#### WP0.1：评测 oracle 与离线评测器

**文件：** 新增 `bench/golden/expected_contracts.json`、`bench/generation_eval.py`、`tests/generation_eval_test.py`；修改 `docs/模型基线测量方案.md`。

**实现内容：**

1. 为现有 `bench/golden/*.md` 建立稳定样本 ID、SHA-256、接口片标注、人工期望的 endpoint、关键字段/位置、明确枚举/范围/条件、禁止猜测项和已知变异项。
2. 记录评分数据来源：模型 ID/实际版本、prompt 版本、采样参数、运行时间、输入样本摘要、是否命中缓存、生成路径、每片状态。敏感信息不得进入 oracle 或报告。
3. `generation_eval.py` 读取生成目录和 oracle，计算端点绑定精度、关键字段覆盖、断言语义判定、未知项召回、无产出和误拒；任何空分母必须显示 `null`/“不可计算”，不得被算作 100%。
4. 报告分开展示：接口片分母、非接口 skip、文档体检拒绝、模型格式/结构失败、静态拒绝、待人工、运行失败和 L2 失败。
5. merge on/off 对照必须来自同一轮、同一份模型响应缓存和同一 oracle；另保存单独重复运行结果，不直接比较不同样本数的百分比。

**测试：**

- 空样本、缺 oracle、重复样本 ID、无效摘要、所有切片被跳过时不允许误报满分。
- `passed + failed + needs_review + skipped == total`；`produced` 不得超过有效接口片分母。
- 人工 golden YAML 的 L2 结果只写 `static_l2_rate`，不得进入 `assertion_precision`。

**命令：**

```powershell
.\.venv\Scripts\python.exe -m pytest tests\generation_eval_test.py tests\golden_baseline_test.py -q
.\.venv\Scripts\python.exe bench\generation_eval.py --help
```

**验收结果：** 可以从机器报告还原当前两轮 13/15 与 13/14 的来源，并明确标为不可直接比较；未经人工 oracle 的样本不能产出“语义准确率”。

#### WP0.2：显式质量状态

**文件：** 新增 `interfacetester_ai/quality.py`、`tests/quality_test.py`；修改 `gen.py`、`assembler.py`、`cli.py`、`tests/gen_pipeline_test.py`。

**接口建议：**

```python
class QualityStatus:
    GENERATED = "generated"
    STATIC_VALID = "static_valid"
    NEEDS_REVIEW = "needs_review"
    RUNTIME_VERIFIED = "runtime_verified"
    AUTO_PROMOTABLE = "auto_promotable"
    REJECTED = "rejected"

@dataclass(frozen=True)
class QualityAssessment:
    status: str
    blockers: Tuple[str, ...] = ()
    warnings: Tuple[str, ...] = ()
    evidence_ids: Tuple[str, ...] = ()
```

**实现内容：**

1. 为 `GenResult` 和 `AssemblyResult` 增加 `quality: QualityAssessment`；保留 `.ok()` 和 `outcome()` 作为兼容字段，但文案不得再把 `.ok()` 解释成“可自动使用”。
2. 新增纯函数校验转换：例如未运行不能到 `runtime_verified`，有关键 blocker 不能到 `auto_promotable`，已拒绝不能再转 `static_valid`。
3. 把 `protocol-only`、存在关键 `unknowns`、字段覆盖未达门槛、TODO、method/path 歧义分别转为稳定 blocker/warning code，而不只拼中文字符串。
4. CLI 对每个用例显示质量状态和下一步；汇总把生成、skip、静态拒绝、待人工、运行结论分列。

**测试与验收：** 对每个合法/非法状态转移做单测；旧 exit code 测试继续通过；缺少 runtime 记录时绝不能打印 `runtime_verified`。运行：

```powershell
.\.venv\Scripts\python.exe -m pytest tests\quality_test.py tests\gen_pipeline_test.py tests\ai_cli_exit_codes_test.py -q
```

### 阶段 1：默认产草稿、人工确认后转正

**预计：2-4 人日。依赖：WP0.2。目标：第一层的安全边界变成默认运行行为。**

#### WP1.1：拆分“装配”与“发布”

**文件：** 修改 `interfacetester_ai/assembler.py`、`interfacetester_ai/gen.py`、`interfacetester_ai/cli.py`；测试修改 `tests/assembler_test.py`、`tests/gen_pipeline_test.py`、`tests/ai_cli_exit_codes_test.py`。

**实现内容：**

1. 将 `assemble()` 的默认模式改为只写 `.ai/draft/`，包含 emitted YAML、草稿 JSON、coverage、unknowns 和质量摘要。不得因“无 TODO + L2 通过”直接复制进 `cases/`。
2. 删除默认生成路径中直接进入 `cases/` 的步骤；如需保留旧行为，只能提供显式、默认关闭且文案含风险的兼容开关，并在一个版本周期后删除。推荐不增加该开关，以免旁路自动写入继续成为生产默认。
3. `GenResult.ok` 暂保留代表“生成/装配流程完成”，新增 `quality.status` 和 `draft_path`；CLI 退出码 0 表示没有不可恢复流程错误，不表示案例可直接在 CI 中使用。
4. 让 `haify gen --assertions-only` 也按相同草稿规则落点；避免确定性路径反而绕过审核策略。

4. 文档/契约摘要与证据 ID 一致，样本处于评测过的输入格式范围。
5. L1、L2、静态闸门全过，隔离参考/测试环境运行通过，重复执行稳定。
6. 变异检出率达到项目批准阈值；关键契约变异不得存活。
7. 审计报告完整，目标环境非生产；自动晋级策略显式启用并可一键关闭。

即便满足以上条件，第一版建议只标为 `auto_promotable`，仍由独立的发布命令/策略决定是否转正；不自动修改已有文件，不自动 apply 修复。

**验收：** 白名单外输入、缺认证、条件未建模、只有状态码断言、变异 surviving、运行证据缺失、环境 profile 指向生产域时均不能产生 `auto_promotable`；所有拒绝都有稳定 reason code。

### 阶段 7：扩大样本、CI 与交付

**预计：3-5 人日（持续评估工作另计）。依赖：阶段 0-6。**

**文件：** 修改 `bench/golden/expected_contracts.json`、`bench/generation_eval.py`、`.github/workflows/test.yml`、`docs/模型基线测量方案.md`、`docs/未做完的待决策项.md`、`docs/能力清单.md`；按实际变化更新 `tests/`。

**实现内容：**

1. 评测样本扩到不少于 30 份独立真实接口文档，覆盖单/多步、认证、条件字段、数组嵌套、错误码、XML、编码、不同 Markdown 表格模板以及不完整/矛盾文档；训练/调 prompt 用样本与最终验收样本分开。
2. 每次 prompt、模型、解析器和 oracle 变更记录版本；CI 跑离线解析、状态机、装配、mock 执行和 mutation harness；模型调用及云端验证仅通过明确手动 workflow 运行。
3. 对语义样本双人盲审，保存原始判定、未知、分歧和仲裁；以文档为统计簇报告，避免把同一接口 10 条断言当 10 个独立样本夸大置信度。
4. 更新能力清单，将“已实现”“有评估证据”“只对某白名单承诺”“未实测”分开列出。

**验收建议：**

- 第一层：来源可追溯率 100%；双审断言精确率至少 90%；关键未知召回率至少 90%；unknown/blocker 均能在审核清单中定位。
- 第二层自动晋级样本：method/path 唯一绑定 100%；关键契约语义错误 0；关键字段覆盖不低于 95%；有效变异检出率至少 90%，关键变异不得漏；同环境重复执行稳定率至少 99%。
- 语义判断至少 100 条有效断言，覆盖不少于 10 份文档与 3 种契约/文档形态；双人独立标注并仲裁。达不到样本量时只报观察值，不发布阈值承诺。
- CI 不依赖外网、模型服务或密钥；写盘边界扫描通过；生成 job 零残留；完整核心测试套件通过。

## 6. 依赖关系与推荐顺序

```text
WP0.1 固定评测 oracle ───┐
                         ├─> WP2.1 共享契约解析 ─> WP2.2 证据绑定 ─> WP3.1 条件 ─┐
WP0.2 质量状态 ─> WP1.1 草稿默认 ─> WP1.2 审核记录 ────────────────────────────┼─> WP4 覆盖/审核
                                                                                 └─> WP3.2 枚举/WP3.3 依赖
WP4 + 隔离安全评审 ─> WP5.1 候选执行 ─> WP5.2 参考服务/变异 ─> WP6 自动晋级白名单 ─> WP7 扩样本与 CI
```

建议按此顺序推进，不要先上 UI 或大规模改 prompt。先让输出不冒充已审核用例，再改善契约理解，最后才引入自动执行和自动晋级。

## 7. 跨文件影响范围与回归要求

### 7.1 行为兼容面

- `haify gen` 的默认落点从 `cases/` 改为 `.ai/draft/`，这是用户可见的行为变更；CLI 输出、退出码解释、手册、CI 示例都要同步。
- `AssemblyResult.ok()` 与 `GenResult.ok` 保留一段兼容期，但新代码不得使用它们决定自动晋级。
- `haify review --approve` 需重新验证，可能拒绝以前可直接复制的草稿；错误需返回明确的 blocker code 和建议动作。
- `jobs.run_job()` Web 路径保持 `cases/` 白名单，不允许为方便验证而接受 `.ai/draft` 任意路径或 pytest 参数。
- OpenAPI converter 是 `interfacetester` 内核能力，AI 层只消费公开转换面/新增映射；新增内核需求应单独审批、增加 converter 一致性测试和 wheel 验证。

实际实施时按仓库当前 CI 排除外网依赖测试的正式命令执行，不因本计划而把公网测试加入本地参考服务验收。

## 8. 风险、控制与回滚

| 风险 | 控制措施 | 回滚/降级 |
| --- | --- | --- |
| 默认草稿落点改变导致现有脚本找不到 `cases/` 用例 | 同版本更新 CLI 文案、README、deploy 和示例；先在测试固定 exit code 和输出 | 在发布前可整体回滚 WP1；不要保留默认直写 `cases/` 的隐式旧行为。 |
| 共享解析器迁移破坏文档体检或断言推导 | 先增加契约 parser golden tests，再让 `doc_quality`/`assertions` 逐步薄封装 | 解析器按输入类型开兼容路径；不回退来源/条件安全门槛。 |
| 条件或枚举判据太严格，导致产出率下降 | 产出率按接口片记录；未知项是预期安全降级，不以牺牲正确性换产出率 | 保留确定性映射和模型原稿；可回滚具体解析器规则，但不能静默移除 blocker。 |
| 参考 mock 与 oracle 共用逻辑产生循环自证 | oracle 人工维护；参考服务实现独立于 CaseDraft/YAML；mutation 预先定义 | 若不能证明独立，停止自动晋级评估，只发布第一层初稿能力。 |
| 候选执行造成任意代码/生产请求 | 子进程、固定命令、固定 cwd、L3 allowlist、非生产 profile、超时和数据清理 | 默认关闭 verify；检测到未授权域名/路径/参数时在启动前拒绝。 |
| 评分样本过少或人工评分偏差 | 双盲审、仲裁、样本量和文档簇报告；将未判/无法判定与错分开 | 样本不足时保留“未验证”，不把观察值写成承诺阈值。 |

## 9. 发布门槛

### 9.1 可对外说明“生成可复核初稿”之前

- 阶段 0、1 完成；所有生成候选默认在 `.ai/draft/`。
- 每个断言显示原文和稳定来源位置；所有 blockers/unknowns 出现在 CLI 或审核报告。
- 通过结构、装配、闸门、审核哈希与写盘边界测试；定向测试和确定性 CI 通过。
- 文档明确写“需人工审核后转正”，不展示成“AI 自动完成接口测试”。

### 9.2 对限定范围宣称“可自动代表契约”之前

- 阶段 2-7 中与目标格式相关的所有门槛完成，并为支持格式维护白名单和不支持清单。
- 评测 oracle 有独立人工来源；真实模型产物经双审；参考服务正常和 mutation 测试通过。
- 自动晋级状态仅对达标样本出现；任何关键未知、运行证据缺失、变异漏检或生产环境目标均阻断。
- 发布报告同时给出模型/版本、prompt 版本、样本数量、接口片分母、端点准确率、语义精确率、覆盖率、未知召回、运行稳定性和 mutation 检出率。

在这些条件完成之前，交付承诺限定为“生成结构化、可追溯、可复核的候选用例”，不要承诺“无需审核可直接代表接口契约”。

## 10. 首个迭代建议

建议第一个迭代只做 **WP0.1、WP0.2、WP1.1**，先闭合评测事实、明确质量状态、纠正默认落盘边界。完成后再开始共享契约解析和条件/枚举改造。这样第一个迭代就能实质降低误用风险，同时所有后续质量改进都有一致的状态模型和评测分母。
