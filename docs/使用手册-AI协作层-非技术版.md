# AI 协作层使用手册（给不写代码的同事）

> **这份文档给谁看**：不写代码的同事（产品 / 测试 / 业务 / 文档作者）。
> 看完你会知道——这套 AI 工具**替我们做了什么、哪些事必须由人来做、你会被请去做什么**，
> 以及遇到常见问题时该怎么办。
>
> **你不需要会**：编程、命令行、Git。**全文没有一行需要你敲的代码**。
> 想看技术细节（怎么装、怎么配模型、报错码含义），见同目录的
> `使用手册-AI协作层.md`（技术版）；部署与验收见 `deploy.md`。

## 一、先用一句话理解这套东西

我们有一堆**写给人看的接口文档**（"POST /api/login，请求要传 `username`/`password`，
成功返回 200 和一个 `token`"）。这套工具做的事就是：

> **把这种文档，自动起草成"能被机器执行"的测试用例。**

打个比方：它像一位**实习同学**——

| 谁 | 干什么 | 为什么 |
| --- | --- | --- |
| **AI（模型）** | 读文档、**起草**用例、写失败的初步分析 | 读书快、写得快；但会**想当然** |
| **程序（工具本身）** | 检查草稿、**校验**、算数字、跑用例 | 不会累、不会猜、**只认死规矩** |
| **人（你）** | 填文档没写清的地方、**确认**草稿能不能用 | 只有人知道"业务上到底该是什么" |

**两条最要紧的规矩**（记住这两条，后面都不用怕）：

1. **AI 永远不能说"通过 / 失败"**——判定只由程序做。所以"AI 说没问题"**不是结论**。
2. **AI 不能直接改动正式用例**——它只能**起草**和**给建议**；**要人确认**才会转成正式用例。

## 二、你会被请去做哪三件事

### 2.1 填"文档里没写的空白"（最常找你的事）

工具读文档时会遇到**文档没说清**的地方，例如：

- 文档只写"返回用户信息"，没写"`status` 字段可能的值有哪些"；
- 文档写了成功的情况，没写"密码错误时返回什么"。

**它不会猜**，而是把这些列成清单请你回答（清单在"待确认"那一页上，像一张表）：
你只要把答案填进去、点确认即可。**答不出来的就写"暂无"**，它会如实标注"未知"。

> 为什么必须有人答：这类信息只有**产品 / 后端 / 数据**知道。
> 让 AI 猜的结果就是"看起来很完整、其实全是编的"——那是这套工具最想避免的事。

### 2.2 确认"草稿"能不能转成正式用例

AI 起草的用例**先放在"草稿区"**（一个临时区域），里面凡是它**没把握**的地方都会标上
`TODO_`（意思是"这里等人工确认"）。你要做的是：

1. 看草稿：**它引用的文档原句**是不是真的支持这条断言（工具会把引用句显示在旁边）；
2. 填掉 `TODO_`（有些是 §2.1 的空白）；
3. **签上你的名字**确认 → 草稿才会被搬进正式用例区。

> 不签名的确认会被拒绝（系统要找"是谁确认的"）；**确认之后草稿又被改了一行，确认就失效了**
> ——必须重新确认。这是刻意的：否则"签一次、以后怎么改都算签过"，签名就成摆设了。

### 2.3 看结果、看报告

跑完一轮，你会看到（不用自己跑，看文件或在看板页面上看）：

| 你会看到 | 说的是什么 | 你要做什么 |
| --- | --- | --- |
| `reports/summary.md` | 这轮跑了多少、过了多少、哪些用例失败、哪里最慢 | 扫一眼；**数字是程序算的**，模型只写了开头两三句导语 |
| `reports/analysis.md` | 每条失败**为什么**失败（归成六类：真实缺陷 / 用例错误 / 环境问题 / 测试数据问题 / 文档与实现不符 / 未知） | 重点看"**文档与实现不符**"——那说明文档要改 |
| `reports/doc_defects.md` | 从失败里**回流出来**的文档问题清单 | **转给文档作者**（这是这套工具最有价值的出口之一） |
| 用例旁边的 `NEEDS_HUMAN.md` | "这条没生成成功，**人接着要干什么**" | 按上面写的做（通常是"文档缺什么，去补"） |
| "待确认"页面 | 等人回答的清单 + 等人确认的草稿 | 见 §2.1 / §2.2 |

## 三、你看到的"文件夹 / 页面"分别是什么

| 你看到的名字 | 大白话 | 你该做什么 |
| --- | --- | --- |
| **正式用例区**（`cases/`） | 已经确认过、能跑的用例 | ⚠️ 改动要走评审（它进了版本库，像正式代码一样被评审） |
| **草稿区**（`.ai/draft/`） | AI 起草、**还没确认**的用例 | ✅ 你要看的是这里 |
| **待确认清单**（`.ai/pending/`） | 文档没写清、等人回答的问题 | ✅ §2.1 要填的就是它 |
| **失败与"要人做什么"**（`.ai/failed/`） | 没生成成功的原因 + 下一步 | 按 `NEEDS_HUMAN.md` 说的办 |
| **确认记录**（`.ai/reviews/`） | 谁、什么时候、确认了哪一版（含内容指纹） | 只读；**对不上就说明内容被改过** |
| **模型通话记录**（`.ai/manifest/`） | 模型每次**原样**返回了什么 | 怀疑"AI 是不是瞎编"时，工程同学可据此复盘 |
| **看板页面** | 一个网页：运行列表 / 度量 / 审计 / 待确认 / 作业 | ✅ 点"待确认"就能填 |
| 运行日志、报告（`logs/`、`reports/`） | 每次跑完留下的记录 | ❌ 不用管，看结论就行 |

**★ 一条纪律**：`.ai/` 里的东西是**证据**（"当时到底发生了什么"）。**不要手工删除或改写**——
删掉的不是垃圾，是能自证清白的记录。

## 四、你大概率会问的问题

**Q1：它会不会偷偷改我已经写好的用例？**
不会。它对正式用例**只读**；所谓"自愈建议"也只输出"如果改，会长这样"的对照稿（改动前后两版并列），
**要不要改由人决定**。工具里**根本没有"自动改"这个开关**——这不是"还没做"，是**已定案不做**（产品决策 2026-09-26）。

**Q2：AI 会不会编造期望值（比如文档里没有的状态码）？**
两道闸拦住它：① 每条断言**必须引用文档里的原句**，引用不到就**降级为"未知"**（宁缺勿编）；
② 它写的东西**只能先落草稿区**，要人确认才进正式区。所以"编出来的东西"最多出现在草稿里，不会进正式用例。

**Q3：为什么有些字段它干脆不写断言？**
因为文档没写清（例如"这个字段是数字还是文本"）。它选择**留空白让你填**，而不是猜一个。
这正是 §2.1 会来找你的原因。

**Q4：我填的答案会不会泄露密码之类的？**
不用填密码。工具遇到密码/密钥这类信息时，**不要求你写明文**，而是让它"从环境变量里取"。
工具**不允许**明文凭据出现在用例里——这是硬规矩，有专门的检查在把守。

**Q5：要不要装什么软件？我电脑上能跑吗？**
你不用装。跑命令由工程同学做；你要用的**看板**只是一个内网网页，浏览器打开就行。
看板**只能看**（不能在上面跑用例、不能改文件）——触发运行需要额外的安全开关，且只由工程同学开。

**Q6：报告里出现红字，是我的问题吗？**
分两种：① **环境原因**（比如没连上被测系统、跑测试的机器缺个组件）——交给工程同学，工具会明确写出原因；
② **用例真失败**——看 `analysis.md` 的归因：如果是"文档与实现不符"，那要改的是文档（你或文档作者）；
如果是"真实缺陷"，那就是被测系统的 bug（交给开发）。

**Q7：我不管那个"待确认"清单，会怎么样？**
相关草稿**不会**自动转正；而且那页清单会一直挂着、并显示"已等了多久"（设计如此：
**唯一在等人做的事，必须显眼**）。工具不会替你"默认同意"。

**Q8：我填错了 / 想反悔？**
可以改，再确认一次即可。**历史留痕是追加的**（能看到"谁、什么时候、确认了哪一版"），
旧记录不会被抹掉——所以不用担心"改过就说不清"。

**Q9：为什么工具不读我项目里那个 `.env` 文件？**
那个文件是给**用例**用的（属于被测项目，比如被测系统的地址和账号）；
而**工具自己**的配置（用哪个模型、超时多久）是另一回事，走另一套设置——
两者的负责人常常不是同一个人，混在一起就分不清"是工具没配好，还是项目没配好"。

**Q10：模型很慢、经常"超时"，是不是模型不行？**
多数情况下不是模型不行，而是"**等它的最大时长**设得太短"。工具现在默认等 180 秒，
慢的本地模型建议调到 300 秒以上；而且**报错时会直接告诉你该调哪个设置**（不用记）。

## 五、「我该动哪个」速查

| 你想做的事 | 动哪里 | 风险 |
| --- | --- | --- |
| 回答"文档没写清"的问题 | 待确认清单（看板"待确认"页） | ✅ 放心填，填错可改 |
| 确认 / 拒绝一份草稿 | 草稿区 → 确认（要签名字） | ✅ 常规操作 |
| 改正式用例 | 正式用例区（`cases/`） | ⚠️ 走评审（像改代码一样），或先问测试同学 |
| 改接口文档本身 | 文档仓库 | ✅ 鼓励：文档缺什么就补什么（这是根因修复） |
| 删 `.ai/` 里的东西 | —— | ❌ **别动**（那是证据，也是别人的工作依据） |
| 组件装不上 / 命令跑不起来 / 想要"自动改" | —— | ❌ 找工程同学；"自动改"**已定案不做**（不是"以后会有"），不用等 |

## 六、小词典（看懂报告里的词）

| 词 | 大白话 |
| --- | --- |
| **用例** | 一条能被机器执行的测试：请求什么、期望返回什么 |
| **断言** | 用例里的"检查点"：比如"状态码必须是 200" |
| **引用句** | 这条断言**依据的文档原句**（用来回答"你凭什么这么写"） |
| **草稿 / 正式** | 草稿 = 待确认；正式 = 已确认、能跑的 |
| **`TODO_`** | 草稿里的标记："这里等人确认" |
| **降级 / 未知** | 工具**没把握**时的老实做法：不写断言，标"未知"，等人补 |
| **待确认清单** | 文档没写清、等人回答的问题列表 |
| **确认留痕** | "谁在什么时候确认了哪一版"的记录（带内容指纹，改过就失效） |
| **闸门** | 程序里的"检查站"：不合格的草稿**进不了正式区** |
| **体检（文档体检）** | 生成前先看文档够不够用（缺接口地址、字段表、前后矛盾等 → 直接拒，并给出"该怎么改"） |
| **预算** | 单次最多允许塞给模型多少内容；超了就**停下来报错**，不会偷偷截断 |
| **缓存命中** | 同样的问题问过、且答案还能用 → 直接回放，**不再花钱调模型** |
| **出网开关 / 沙盒** | 默认**不联网**；要真的调用模型得由工程同学显式打开 |
| **L2 / L3** | L2 = 生成后的自检（能不能被工具读懂、格式对不对）；L3 = **真跑一次**（会真发请求，默认关闭） |
| **归因六类** | 失败原因的分类：真实缺陷 / 用例错误 / 环境问题 / 测试数据问题 / 文档与实现不符 / 未知 |
