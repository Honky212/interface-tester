# 模型基线测量方案（P0a 生成闭环）

> **用途**：定义"**用哪个模型、跑什么样本、看哪些指标、多少算可接受**"，让 P0a 的验收标准**可证伪**。
> 对应决策：`docs/未做完的待决策项.md` §一 D4 + §二 R11-2（**2026-09-26 已决策**）。
> **一句话口径**：主指标是「**接口片 → 产出用例的产出率**」；「落盘产物过 L2」**不是**模型成绩单
> ——装配器闸门在前，没过闸的根本不落盘，所以那条**恒为 100%**（脚本已在 `out_l2_baseline_*.json` 的
> `l2_note` 字段里自注这一点，引用时**不要摘掉**）。
>
> **谁看这份**：决定"能不能承诺产出率"的人（项目/模型采购）；跑测量的人（工程）。
> **不写什么**：不复制会生锈的仪表盘数字（缓存命中率 / token / 花费看 `.ai/manifest/` 与看板"度量"页）。

## 三、指标定义

| 指标 | 定义 | 在本方案里的角色 |
| --- | --- | --- |
| **接口片产出率** `slice_success_rate` | `slices_produced / slices_with_interface` | **主指标**（唯一用于验收的模型指标） |
| 产出用例数 `cases_produced` | **产物条数** = `.ai/draft/*.yml` + `cases/*.yml`（★2026-09-26 起默认落 `.ai/draft/`，历史轮次在 `cases/` —— 探针两处都收，见 `measure_p0a_l2.py`） | 辅助（一片最多 1 条，多步文档可出多条） |
| 有产出文档数 `docs_with_cases` | 15 篇里出过产物的篇数 | 辅助：看"整篇全灭"（与片级指标互补） |
| 落盘产物 L2 通过率 | 产物过内核加载 + `make` 干跑 + `compile()` 的比例 | ⚠️ **不当作模型指标**（闸门在前 → 恒 100%，`l2_note` 已自注） |
| 无产出篇目的**归因** | exit=4 体检闸 / exit=1 生成期闸，逐篇可点名 | **必查项**：无产出**不许"消失"**，必须能指认是哪道闸 |
| 单篇耗时、模型调用次数 | 秒 / 次 | 成本侧（用于估"跑一轮要多久"） |
| 字段级断言占比、断言语义正确率 | 断言里字段级/协议级的比例、人判语义正确率 | ⏳ **等 C-2**（`gen` + 确定性映射合并）落地才能测（见 §四） |
| **T28 降级率** `drop_rate` | 被 T28 拦下的断言 / **模型提议的断言数**（生成期；`haify gen` 收尾那行 = `coverage.to_dict()["drop_rate"]`） | ★**引用质量**指标（引用句必须**逐字**出现在文档里才算数）——**真人文档上才亮红灯**：2026-09-26 客户文档实测 **30/75 = 40%**，而 15 篇 golden 上 **0%**（★两者**样本不同**，不可直接比大小，只能各自都是\"同口径复跑的可比数字\"） |
| 缓存命中率 / token / 花费 | 来源 `.ai/manifest/` 与看板"度量"页 | 本方案**不复制数字**（口径唯一来源是那边） |

## 四、阈值（2026-09-26 决策）

1. **接口片产出率 ≥ 86.7%**——= 2026-09-25 `gemma4:latest` / 15 篇实测值，**取两轮实测的下界**；
   **同模型同机器复跑应 ≥ 此值**（低于它要先查环境，而不是先怀疑模型）。
   ★**2026-09-26 复跑实测 92.86%**（13/14 接口片；C-2 合并已接线）——**阈值不因此放松**：那一轮的
   分母（14 vs 15）与失败片数（1 vs 2）同时变了，而"**合并**"与"**模型跨运行差异**"两个来源
   **本次无法分离**（见 §六-2）。所以只能登记"复跑实测到 92.86%"，**不能**写成"合并把产出率提高了 6 个点"。
2. **落盘产物 100% 过 L2 / 内核加载**（保留）——但**必须注明**它是"闸门在前"的必然结果、
   不是模型成绩单。
3. **换模型 / 换机器 / 换样本集** → **不属于本阈值适用范围**：必须重跑并**重写基线**（阈值随基线更新）。
4. **断言语义正确率 ≥ 90%**（R11-1）——**C-2 已落地 + 绑定口径已修正（2026-09-26）→ 可以判了**：
   修正后**离线回放**重出的产物含**字段级**断言（`type_match` / `greater_or_equals` / `less_or_equals` / `contained_by`），
   表 A = **52 条**（表在 `probe_p0a_llm/review_sheets/gemma4-latest_mergedfix/A_r11_assertion_review.md`）。
   而**接线后那一轮真模型产出**（未修正口径）仍全是 `equal(status_code)`——**那批测不出**，如实标注。
   **当前状态：待人工判定**；★把修正后的口径写进**正式基线**还需**再跑一次真模型**。
5. 主指标与辅助指标**同时报**，且报告必须带三要素：**模型名 + 日期 + 样本集规模**
   （`temperature=0` **不等于**跨运行可复现，见 §七-2）。

## 五、怎么复跑（逐字可复制）

```powershell
# 前置：Ollama 在跑（默认 127.0.0.1:11434）。回环地址 → 全 API_KEY
$env:INTERFACETESTER_AI_BASE_URL = "http://127.0.0.1:11434/v1"
$env:INTERFACETESTER_AI_MODEL    = "gemma4:latest"
$env:INTERFACETESTER_AI_SANDBOX  = "on"          # L3 闸门：真出网必须显式开
$env:INTERFACETESTER_AI_TIMEOUT  = "300"; $env:INTERFACETESTER_AI_RETRIES = "1"

.\.venv\Scripts\python.exe probe_p0a_llm\measure_p0a_l2.py        # 全 15 篇

# 先跑试点（省时间）：只跑两篇
$env:P0A_ONLY = "login.md,user_info.md"
.\.venv\Scripts\python.exe probe_p0a_llm\measure_p0a_l2.py

# 换模型做对照：按模型分文件命名，**不会覆盖**上一轮取证
$env:P0A_MODEL = "qwen3.8:27b"; Remove-Item Env:\P0A_ONLY
.\.venv\Scripts\python.exe probe_p0a_llm\measure_p0a_l2.py
```

**产物与工作区**（`P0A_MODEL` 会被 slug 化，如 `gemma4-latest`）：

| 路径 | 是什么 |
| --- | --- |
| `probe_p0a_llm/out_l2_baseline_<slug>.json` | **机器记录**：逐篇数字 + `l2_note` + `source_tree_touched`（本方案的引用来源） |
| `probe_p0a_llm/out_l2_baseline_<slug>.recomputed.json` | **从 CLI 日志重算的片级账**（只在原记录缺字段时用；**不覆盖**原文件——见 §七-6） |
| `probe_p0a_llm/gen_all_<slug>.log` | 每篇 stdout 原文 |
| `.tmp_p0a_run_<slug>/` | 15 个隔离工作区（草稿 + 产物 + 失败目录） |
| `.tmp_p0a_l2_<slug>/` | L2 现场（产物复制过去跑，验收⑦"零污染"就靠这里） |

**尺子**：L2 口径**复用仓库自己的** `bench/golden_harness.evaluate_expected_yaml`
（= 内核 `validate_emitted_case`：`load_testcase_file` + `make_testcase` 干跑 + `compile()`）
——所以"模型产物"与"人工 golden 基线（100%）"是**同一把尺子**，不是另立一套。

## 七、测量纪律（六条，其中三条是踩过的坑）

1. **★测量期间不得编辑仓库**。快照排除表只有 `__pycache__ / .ai / cases / logs / reports / probe_p0a_llm`
   与 `.tmp_*` 前缀；`deploy.md`、`docs/*.md` **不在其中**。qwen 那轮 `source_tree_touched` 报了
   **6 项**（`deploy.md`、`docs/interfacetester智能化改造方案8.md`、`docs/矫正后的待办清单0924.md`，
   前后大小都变了）——查明是**测量期间有人在编辑那三份文档**，**不是工具写盘**。
   → 所以"零污染"这个结论**只在"测量期间没人动仓库"时成立**；跑测量前先停手。
2. **单模型单次 ≠ 可复现**。`temperature=0 + seed=0` 不保证跨运行一致（本地模型/服务端实现各异），
   同文档两次跑结果不同已实测到过 → 任何结论都要带"模型 + 日期 + 样本集"三要素。
3. **分母必须说清**：86.7% 的分母是**接口片 15**，不是 70 片、也不是 15 篇文档。
4. **L2 是闸门不是成绩单**：引用该数字时**连 `l2_note` 一起引**。
5. **人判指标不能机器替代**：表 A/B/C 必须人判 + 机器交叉检查，且**单判定人**的结论要显式标注
   （口径级结论宜双人复核）。
6. **★解析外部输出的指标必须自带自检**（2026-09-26 踩到）：`probe_p0a_llm/measure_p0a_l2.py` 用正则
   从 CLI stdout 取片数，而它的 `_SLICES_RE` 把 CLI 那行的 `片产出用例` 误写成 `片产出一用例`
   （**多一个「一」**）→ **两轮日志都是 0 匹配**，聚合出来的 `slice_success_rate` 是 **`-0.0`（假数）**。
   教训两条：① 解析型指标**先自检"解析到几行"**——0 行就**不许报数**（宁缺勿假）；② 事后重算要
   **新写一个只读脚本**（`probe_c2/recompute_from_log.py`）并落**独立文件**（`*.recomputed.json`），
   **不覆盖**机器原始记录（原始 json 里 `slices_*` 仍是 `null`，可对照）。
