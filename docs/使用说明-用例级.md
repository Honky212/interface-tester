# 用例工程「文件与文件夹」使用说明

> **面向谁**：框架已装好（安装/打包/依赖见 [`../deploy.md`](../deploy.md)），准备在**自己的被测项目**里落地用例的人。
> **讲什么**：只讲**用例工程侧**的文件与文件夹——哪些必须、哪些可选、各自怎么用、每个项目要不要单独配、以及容易踩的坑。
> **不讲什么**：框架能/不能做什么见 [`能力清单.md`](能力清单.md)；想读源码/改框架见 [`架构与调用链.md`](架构与调用链.md)；写用例的语法教程见 [`使用教程-项目级.md`](使用教程-项目级.md)。

## 一、先看全景：一个典型用例工程长什么样

```
my-api-tests/                 ← 项目根（RootDir，框架靠 debugtalk.py 认出来）
├── debugtalk.py              ★ 强烈建议：定位项目根 + 放自定义函数
├── .env                      ○ 可选：环境变量（域名、账号、token）
├── conftest.py               ○ 可选：项目夹具（会话准备/回收、登录、skip 规则）
├── case.yml                  ★ 必须：用例
├── login.yml                 ○ 可选：被别的用例引用的公共用例
├── data/
│   └── accounts.csv          ○ 可选：数据驱动
├── schemas/
│   └── login.json            ○ 可选：jsonschema_match 契约文件
├── thrift/
│   └── blob.thrift           ○ 可选：thrift IDL（仅 Linux/macOS）
└── logs/                     （运行期自动生成，不用手建）
```

顶层的其余文件（`pyproject.toml` / `requirements.txt` / `LICENSE` / `README.md` 等）属于**框架仓库**，不是用例工程的一部分；要不要带、带哪些，见 [`../deploy.md`](../deploy.md) 与本文第十节的对照表。

## 二、从零搭一个用例工程（分步示例）

> **目标**：从空目录到第一条用例通过——全程只需要建 **3 个文件**。
> **本节已实测**：按下面 6 步走，得到 `1 passed`，且 HTML 报告可打开。
> **配套示例工程**：[`../examples/quickstart/`](../examples/quickstart/)——照着本节做出来的样子，
> 可直接跑（零配置即可跑通一条；想体验 `.env` 也有一份现成的）。

### 2.1 第 0 步：确认框架已装好

```bash
hrun -V
```

能打印出版本号就说明装好了（**不要求**版本号与本文一致）。
提示「找不到命令」或 `missing dependency tool: black` → 先看 [`../deploy.md`](../deploy.md)。

### 2.2 第 1 步：建一个空目录

```bash
mkdir my-api-tests
cd my-api-tests
```

最终会长成这样（后 3 步逐个补上）：

```
my-api-tests/
├── debugtalk.py     ← 第 2 步
├── .env             ← 第 3 步
└── hello.yml        ← 第 4 步
```

### 2.3 第 2 步：放 `debugtalk.py`（这一步别省）

在 `my-api-tests/` 下新建 `debugtalk.py`：

```python
# my-api-tests/debugtalk.py
# 它的作用首先是「门牌号」：告诉框架「my-api-tests 就是一个项目」。
# 暂时不需要自定义函数，内容留空也可以。
```

> **为什么不能省**：框架靠它定位「项目根」。没有它，`schemas/xxx.json`、`data/xx.csv`
> 这类相对路径会以「你敲命令时**所在的目录**」为基准——换个目录跑就报「文件不存在」。

*怎么确认这步对了*：这步没有输出，「放了就对」。

### 2.4 第 3 步：放 `.env`（放环境信息）

```dotenv
# my-api-tests/.env
# 接口地址、账号等环境信息；用例里用 ${ENV(名字)} 取。
BASE_URL=https://httpbin.org
```

> 本文用公开的 `httpbin.org` 当例子。**换成你自己的接口地址也可以**——唯一的约束是
> 「这个地址能返回 200」。内网/离线环境请改成你能访问的地址。

*怎么确认这步对了*：这步也没有输出，效果在第 4 步能看出来。

### 2.5 第 4 步：写第一条用例

新建 `hello.yml`：

```yaml
config:
  name: 我的第一条用例

teststeps:
  - name: 调一次 GET 接口
    request:
      method: GET
      url: ${ENV(BASE_URL)}/get      # 取 .env 里的 BASE_URL
    validate:
      - eq: [status_code, 200]
```

### 2.6 第 5 步：跑起来

```bash
hrun hello.yml --html=reports/report.html --self-contained-html
```

预期结果：**`1 passed`**，并生成 `reports/report.html`（浏览器可直接打开，**单文件**报告，
不依赖任何外部资源）。

*怎么确认这步对了*：

- 终端最后一行是 `1 passed`（不是 `failed` / `error`）；
- `reports/report.html` 能打开，里面能看到请求的 URL、方法与返回的状态码。

### 2.7 没跑通？按症状查

| 终端上的现象 | 多半是 | 怎么办 |
| --- | --- | --- |
| `'hrun' 不是内部或外部命令` / `command not found` | 框架没装，或没激活虚拟环境 | 先看 [`../deploy.md`](../deploy.md)；激活环境后再试 |
| `path not exist: hello` / `FileNotFoundError` | 不在 `my-api-tests/` 目录里敲的命令 | `cd my-api-tests` 再跑 |
| `EnvNotFound: BASE_URL` | 没有 `.env` / 键名不对 / 文件不在项目根 | 确认 `.env` 与 `debugtalk.py` 同级、键名一模一样 |
| `ConnectionError` / 请求超时 | 网络不通（`httpbin.org` 需要外网） | 把 `BASE_URL` 改成你能访问的地址 |
| `missing dependency tool: black` | 没在虚拟环境里跑 | 见 [`../deploy.md`](../deploy.md) |

### 2.8 第 6 步（可选）：体验「`.env` + `debugtalk.py` + 用例」怎么配合

把 `debugtalk.py` 改成：

```python
# my-api-tests/debugtalk.py
import os


def base_url():
    """把 .env 里的地址包一层，用例里写 ${base_url()}"""
    return os.environ.get("BASE_URL", "")
```

再把 `hello.yml` 的 URL 改成 `url: ${base_url()}/get`，重跑 `hrun hello.yml`，
**仍然是 `1 passed`**。

> 意义：以后要加「登录拿 token」「生成签名」「造测试数据」这类逻辑，就写在
> `debugtalk.py` 里，用例只负责调用——**不用改框架**。

### 2.9 骨架就绪之后

| 接下来想做 | 看哪一节 |
| --- | --- |
| 弄明白每个文件到底干什么、要不要每个项目单独配 | 第三节起 |
| 加账号密码、切测试/预发/生产环境 | 第五节（`.env`） |
| 用 Excel 另存的 CSV 做数据驱动 | 第六节（CSV） |
| 登录一次让所有用例复用；跑完清理数据 | 第四节（`conftest.py`） |
| 校验接口返回的**结构**（字段/类型/必填） | 第七节（`schemas/`） |
| 换台机器 / 交给同事部署 | [`../deploy.md`](../deploy.md) |

## 三、`debugtalk.py`

### 3.1 它是做什么的

两件事，**第一件比第二件重要**：

| 作用 | 说明 |
| --- | --- |
| ① **定位项目根（RootDir）** | 框架从**用例路径**开始**向上查找** `debugtalk.py`，**找到的那个目录**就是项目根 |
| ② 提供自定义函数 | 模块里的 **Python 函数**自动进函数表，用例里用 `${函数名(...)}` 调用 |

> **NOTICE（2026-09-26 实测订正）**：本行原先写「**公开函数**（不以下划线开头）自动进函数表」，
> 与代码不符。实测口径（判据在 `loader.load_module_functions`：`isinstance(item, types.FunctionType)`）：
>
> - **会进表**：自己 `def` 的 Python 函数；**`_` 开头的函数也会进表**（`${_private()}` 实测可调用，
>   **它并不是私有的** —— 别把密钥/开关塞在这类函数里当"隐藏"）；`from mymod import my_py_func`
>   这种**导入进来的纯 Python 函数**同样会进表。
> - **不会进表**：① **模块级常量/变量**（`CONST = "x"` → 用例里 `$CONST` 报
>   `VariableNotFound: ['CONST']`；要共用常量请写成函数，或放进 `.env` 用 `${ENV(NAME)}`）；
>   ② **C 实现的内置函数**（如 `from hashlib import md5`，它不是 `FunctionType`）——在自己函数里包一层即可。
> - **同名优先级**：`debugtalk.py` **优先于**内核内置函数（见 `parser.get_mapping_function`，先查项目函数表）。

### 3.2 RootDir 决定了什么

**所有相对路径都相对 RootDir 解析**，包括：

- `schemas/xxx.json`（`jsonschema_match` 的文件引用）
- `data/accounts.csv`（`${parameterize(...)}`）
- 被引用用例的路径（`testcase: login.yml`）
- 上传文件路径

所以 RootDir 定错 = 上面这些**全部**解析错位。

### 3.3 找不到它会怎样

**RootDir 会退化成「当前工作目录」（`os.getcwd()`）**，于是：

- 换一个目录跑 `hrun`，`schemas/login.json` 就找不到了（报「schema 文件不存在」）；
- CI 里 `working-directory` 不是「含 `debugtalk.py` 的那层」也会中招（见 [`ci/README.md`](ci/README.md) 的「坑 1」）。

> 结论：**哪怕你的项目暂时不需要自定义函数，也建议放一个 `debugtalk.py`**——它的主要价值是「把 RootDir 钉死」，而不是「放函数」。

### 3.4 怎么写

```python
# 项目根/debugtalk.py
import os
import random
import string
import time


def get_token():
    """自定义函数：用例里写 ${get_token()}"""
    return os.environ.get("SERVICE_TOKEN", "")


def get_timestamp():
    """当前秒级时间戳"""
    return int(time.time())


def gen_random_string(length=8):
    """指定长度的随机串"""
    return "".join(
        random.choice(string.ascii_letters + string.digits) for _ in range(length)
    )
```

用例里：

```yaml
- name: 提交订单
  request:
    url: ${ENV(BASE_URL)}/orders
    method: POST
    headers: {X-Request-Id: "${gen_random_string(12)}"}
    json: {order_no: "${get_timestamp()}"}
```

要点：

- **加载时机在 `.env` 之后**（因为函数里常要读环境变量）——所以 `debugtalk.py` 里可以直接 `os.environ[...]`；
- 每次加载都会 `reload`，**改完文件不用重启**；
- 函数名不要以下划线开头（下划线开头的不进函数表）。

### 3.5 每个被测项目要单独配一份吗

| 场景 | 结论 |
| --- | --- |
| 单个项目 | **建议有一份**（见 3.3） |
| 多个项目、一次跑一大片（`hrun 父目录`） | **每个项目根各一份**。框架按「向上**最近**的项目标记」区分项目，各项目的 RootDir / `.env` / 函数集**互不干扰**（这是被专门修过并加了护栏的行为） |
| 嵌套项目（子目录里也有 `debugtalk.py`） | **支持**：子目录形成**自己的** RootDir，不会继承父项目的配置 |

### 3.6 已知边界（如实登记）

框架用**固定模块名** `debugtalk` 导入（`import_module("debugtalk")` + 把项目根置顶 `sys.path`）。若运行环境里恰好存在**同名的第三方包** `debugtalk`、且项目根置顶失效（例如调用方自己动过 `sys.path`），理论上可能加载到**别人的模块**。这是已登记的边缘场景（未复现），彻底修法是改用绝对路径 `spec_from_file_location`，但会改变模块 `__name__/__spec__` 语义，属行为变更，故暂缓。

## 四、`conftest.py`

### 4.1 它有「两种身份」，先别混

| 身份 | 谁写的 | 干什么 |
| --- | --- | --- |
| **框架自动生成的** | `hrun --save-tests` 自动写入 | 装一个会话级夹具，在 pytest 结束时把各用例汇总成 `logs/**.summary.json` |
| **你自己手写的** | 你 | 项目夹具：会话级准备/回收、登录拿 token、起本地 mock、按条件 skip 用例 |

两者是**同一个文件名**（都在项目根）。所以框架有个保护：**只在「文件不存在」或「文件是本框架生成的」时才写它**；你已经手写了一份，框架**绝不覆盖**——它会改写成 `conftest.py.interfacetester-blocked` 并**响亮报错**告诉你怎么合并。

> 判断「是不是框架生成的」看**首行标记**：`# NOTICE: Generated By InterfaceTester.`

### 4.2 框架生成的那份在做什么（了解即可，别抄）

- 内容是一个 `@pytest.fixture(autouse=True, scope="session")`；
- 会话结束时遍历每个用例的 `get_summary()`，累加 `success` / `testcases` / `teststeps` 统计，把明细写进 `summary_path` 指向的 JSON；
- `summary_path` 是**生成时替换进去的绝对路径**；
- **用例路径向上找不到任何项目标记时**，落点会改为「用例自己所在目录」并告警——这是为了防止把 `conftest.py` 写到祖先目录、从而劫持同一目录树下**其它** pytest 会话的汇报输出。

### 4.3 你自己写的那份：三条硬约束（决定只能这么写）

这是最容易踩坑的地方，务必看完——**框架生成的用例方法签名是固定的**：

```python
def test_start(self):          # 没有参数化时
def test_start(self, param):   # 有 parameters 时
```

由此推出三条硬约束：

1. **只有 `autouse=True` 的夹具会生效**。普通 fixture 靠「用例声明参数」注入，而用例签名固定、不接受额外参数 → **注入不进去**。
2. **`autouse` 夹具不能给用例传值**。传值只有两条路：
   - 夹具写 `os.environ[...]` → 由 `debugtalk.py` 的函数读出来 → 用例里写 `${func()}`；
   - 或者直接在 YAML 里写 `${func()}`。
3. 所以 `conftest.py` 的职责是**准备/回收环境**，不是「把数据塞给用例」。

### 4.4 执行顺序（决定了 `os.environ` 谁能覆盖谁）

```
hrun
 └─ 先 hmake（此刻已加载项目 .env 与 debugtalk.py）
     └─ 再起 pytest 会话
         └─ import conftest.py
             └─ 运行 session 夹具
                 └─ 逐用例运行（每个用例前后运行 function 夹具）
```

**关键推论**：`conftest.py` 里写 `os.environ` 的时机**晚于** `.env` 的加载 → 夹具的值**可以覆盖** `.env` 的同名值。这正是「用夹具把测试环境变量改掉」的依据。

### 4.5 最小可用模板

```python
# 项目根/conftest.py
import os
import uuid

import pytest


@pytest.fixture(autouse=True, scope="session")
def prepare_session():
    """会话级准备/回收（autouse=True 是硬要求，见 4.3）。"""
    # 例：登录拿 token，写进环境变量，由 debugtalk.py 的 token() 读出来
    os.environ["SERVICE_TOKEN"] = "real-token-from-login"
    # 例：起本地 mock / 初始化数据库连接
    try:
        yield
    finally:
        # 会话结束后的回收（按本次运行的前缀清理，别全库清）
        pass


@pytest.fixture(autouse=True)
def case_isolation():
    """用例级隔离：给每个用例一个唯一前缀，跑完按前缀回收自己的数据。"""
    os.environ["CASE_PREFIX"] = f"run-{uuid.uuid4().hex[:8]}"
    yield


def pytest_collection_modifyitems(config, items):
    """按条件跳过（例：没装可选依赖时跳过对应用例，避免被误判成“功能坏了”）。"""
    skip_sql = pytest.mark.skip(reason='需要 sql extra：pip install "interfacetester[sql]"')
    try:
        import pymysql  # noqa: F401
        import sqlalchemy  # noqa: F401
    except ImportError:
        for item in items:
            if f"{os.sep}sql{os.sep}" in str(getattr(item, "fspath", "")):
                item.add_marker(skip_sql)
```

配套的 `debugtalk.py`：

```python
import os


def token():
    return os.environ.get("SERVICE_TOKEN", "")


def case_prefix():
    return os.environ.get("CASE_PREFIX", "")
```

用例即可写：`headers: {Authorization: "Bearer ${token()}"}`、`name: "${case_prefix()}-创建订单"`。

> 更完整的实战范例（会话级登录 + 用例级隔离回收 + 生产环境保护闸门）见 [`../examples/data_management/README.md`](../examples/data_management/README.md) 与其 `conftest.py`。
> 只想要「**按条件跳过某些用例**」这一件事的最小例子，见 [`../examples/quickstart/conftest.py`](../examples/quickstart/conftest.py)
> ——它让「故意失败的对照用例」默认 skip、按环境变量才打开（`config.skip` 只能**永远**跳过，做不到这种条件跳过）。

### 4.6 每个被测项目要单独配一份吗

**要**。`conftest.py` 是 pytest **按目录层级**加载的：在**每个项目根**放一份即可，**不必在每个子目录都放**（同名文件会叠加生效，容易互相干扰）。

| 场景 | 结论 |
| --- | --- |
| 单个项目 | 项目根放一份 |
| 多项目各有一套夹具/登录逻辑 | **每个项目根各一份**（各项目互不影响） |
| 只想用框架生成的汇总 | 不用手写；跑 `hrun <用例> --save-tests` 让它自动生成 |

## 五、`.env`（环境变量）

### 5.1 怎么用

用例里用 `${ENV(名字)}` 读取：

```dotenv
# 项目根/.env
BASE_URL=https://api.example.com
USERNAME=alice
PASSWORD=real-password
```

```yaml
config:
  name: 登录
teststeps:
  - name: login
    request:
      url: ${ENV(BASE_URL)}/login
      method: POST
      json: {username: "${ENV(USERNAME)}", password: "${ENV(PASSWORD)}"}
    validate:
      - eq: [status_code, 200]
```

### 5.2 行为要点

| 项 | 行为 |
| --- | --- |
| 位置 | **项目根**的 `.env`（与 `debugtalk.py` 同级） |
| 加载时机 | **在 `debugtalk.py` 之前**（所以 `debugtalk.py` 里能读到 `.env` 的值） |
| 覆盖语义 | **无条件覆盖** `os.environ` 的同名变量（注意：这与你手写 `os.environ` 的先后关系是 `.env` 在前） |
| 读不到 | 抛 `EnvNotFound`（**不是**静默空串）——写错名字会立刻报错 |
| 编码 | UTF-8（带 BOM 也安全） |
| 多项目隔离 | 同一进程切换项目时，会**先撤销上一个项目写进去的键**（只撤销「值仍等于框架写进去的」那些，**不会**误伤你手动覆盖过的同名变量） |

### 5.3 与版本控制的关系（重要）

`.gitignore` **只忽略「就叫 `.env`」的文件**。所以：

- 真实凭据/环境地址 → 放 **`.env`**（不入库）；
- 需要入库的**示例** → 放 **`.env.example`**（或 `examples/.../test.env` 这类带后缀的夹具）。

> 顺带一句：框架自己也不会把凭据写进日志/报告——请求与响应两侧的敏感字段（`Authorization`、`Cookie`、`token`、URL 里的 userinfo 等）都是脱敏后展示的，**但断言与 extract 拿到的仍是真值**。

### 5.4 每个项目要单独配一份吗

**要**。`.env` 是**按项目根**认的（`<项目根>/.env`）：每个项目一份，互不串环境。

---

## 六、CSV（数据驱动）

### 6.1 怎么用

```csv
username,password
alice,111111
bob,222222
```

```yaml
config:
  name: 登录（数据驱动）
  parameters:
    username-password: "${parameterize(data/accounts.csv)}"
teststeps:
  - name: login
    request:
      url: ${ENV(BASE_URL)}/login
      method: POST
      json: {username: "$username", password: "$password"}
```

- 路径**相对项目根**；
- 首行是**列名**；列名要覆盖 `parameters` 里声明的所有参数名；
- 多组参数之间是**笛卡尔积**。

### 6.2 行为要点与常见报错

| 情况 | 行为 |
| --- | --- |
| 值的类型 | CSV 里的值**一律是字符串**（数字/布尔要显式转换，例如 `${int($count)}`） |
| 编码 | 用 `utf-8-sig` 读 → **Excel「另存为 CSV UTF-8」产生的 BOM 已被处理**，列名不会被污染成 `\ufeffusername` |
| 只有表头 / 空文件 | **响亮报错**（不是静默 skip）——空数据集几乎总是「数据还没填 / 环境指错」的征兆 |
| 表头短于参数名 | **点名报错**，指出缺哪个列（不是裸 `KeyError`） |
| 文件不存在 | 报 `CSVNotFound` |

### 6.3 每个项目要单独配一份吗

数据文件是**项目自己的资产**，放各自项目下即可；框架只是按「相对项目根」去找，不要求固定位置（`data/`、`fixtures/` 随你，路径写对就行）。

---

## 七、`schemas/`（JSON Schema 契约文件）

### 7.1 怎么用

`jsonschema_match` 算子支持**文件引用**（相对项目根解析）：

```yaml
- validate:
    - jsonschema_match: ["body", "schemas/login.json"]
```

```json
// 项目根/schemas/login.json
{
  "type": "object",
  "required": ["code", "data"],
  "properties": {
    "code": {"type": "integer"},
    "data": {
      "type": "object",
      "required": ["token"],
      "properties": {"token": {"type": "string", "minLength": 1}}
    }
  }
}
```

### 7.2 要点

| 项 | 说明 |
| --- | --- |
| 引用方式 | **文件路径**（相对项目根）或 `${func()}` 返回的 schema dict |
| 内联写法的限制 | **仅支持「不含 `$` 键」的极简 schema**；`$schema` / `$ref` / `$defs` / `$id` 这类必须走**文件**或**函数**——写错会在 `hmake` 阶段就报错，不会留到运行期 |
| 文件不存在 | `hmake` 阶段即报错并指出路径（不是运行到一半才炸） |
| 依赖 | `jsonschema` 已在**主依赖**里，不需要额外 extra |

> 目录名不必叫 `schemas/`，叫 `contracts/`、`jsonschema/` 都行——**路径写对即可**，这个名字只是仓库示例的约定。

---

## 八、`*.thrift`（IDL，仅 Linux / macOS）

### 8.1 怎么用

```yaml
- name: thrift 调用
  thrift_request:
    idl_path: thrift/blob.thrift
    include_dirs: [thrift]
    service_name: BlobService
    method: get_blob
    params: {id: 1}
```

### 8.2 要点

| 项 | 说明 |
| --- | --- |
| 依赖 | 需装 `[thrift]` extra（cython + thrift + thriftpy2） |
| **平台** | **Windows 不支持**：构造 thrift step 时就会**明确报错**（不是运行到一半才失败） |
| 路径 | `idl_path` / `include_dirs` 支持 config 级与 step 级，step 级优先 |
| 每个项目要单独配吗 | 是，IDL 是项目资产；不同 IDL 会被框架按「IDL 路径 + include 目录」区分缓存，**同名服务不会互相覆盖** |

## 九、运行期目录：`logs/` 与 `reports/`

这两个**不用手建**，框架/参数会自己创建：

| 路径 | 何时产生 | 内容 |
| --- | --- | --- |
| `logs/{case_id}.run.log` | 跑用例时 | 单个用例的完整日志（含请求/响应详情，凭据已脱敏） |
| `logs/**.summary.json` | 加了 `--save-tests` 时 | 汇总结论，供平台聚合 |
| `<你指定的路径>` | 加了 `--html=...` 时 | 单文件 HTML 报告 |
| `reports/junit.xml` | 加了 `--junitxml=...` 时 | CI 聚合用的 junit 格式 |

> `logs/`、`reports/` 都已在框架仓库的 `.gitignore` 里；**用例工程自己也应该忽略它们**。

## 十、一张总表

### 10.1 用例工程里各文件/文件夹的定位

| 文件 / 文件夹 | 必须? | 作用 | 每个项目要单独配? |
| --- | --- | --- | --- |
| `*.yml` / `*.json` 用例 | **必须** | 被测对象 | — |
| `debugtalk.py` | **强烈建议** | **定位项目根（RootDir）** + 自定义函数 | **是**（每个项目根一份，嵌套项目各自独立） |
| `conftest.py` | 可选 | 项目夹具：会话准备/回收、登录、起 mock、按条件 skip | **是**（每个项目根一份，子目录不用放） |
| `.env` | 可选 | 环境变量，用例里 `${ENV(名字)}` | **是**（按项目根认，互不串） |
| `*.csv` | 可选 | 数据驱动 `${parameterize(...)}` | 是（项目资产，位置自定） |
| `schemas/*.json` | 可选 | `jsonschema_match` 契约断言 | 是（项目资产，位置自定） |
| `*.thrift` | 可选 | thrift IDL（仅 Linux/macOS） | 是（项目资产） |
| 上传用文件 | 可选 | `upload:` 的文件路径（相对项目根或绝对路径） | 是（项目资产） |
| `logs/` / `reports/` | 不用手建 | 运行期产物 | 自动生成，建议 git 忽略 |

### 10.2 「必备 / 可选 / 不必带」三条线

| 类别 | 内容 |
| --- | --- |
| **必备**（缺了跑不起来或会解析错位） | 用例文件；**`debugtalk.py`**（钉住 RootDir） |
| **可选**（按能力需要） | `conftest.py`、`.env`、`*.csv`、`schemas/*.json`、`*.thrift`、上传文件；框架侧对应装 `[xml]`/`[upload]`/`[sql]`/`[thrift]`/`[allure]` extra（见 [`../deploy.md`](../deploy.md)） |
| **不必带**（换机器/分发时） | `.venv/`（**绝对不要拷**，Windows venv 硬编码了原机路径）、`__pycache__/`、`.pytest_cache/`、`logs/`、`reports/`、`build/`、`dist/`（除要分发的 wheel 本身）、`.tmp_*`、`.git/` |

## 十一、常见坑速查

| 现象 | 根因 | 怎么办 |
| --- | --- | --- |
| **用例是绿的，但断言其实一条都没执行** | 断言字段名拼错（如把 `validate` 写成 `validates`）→ 框架只**告警**「存在无法识别的字段：['validates']，它们会被忽略」，用例照样 passed | 在输出里搜 `无法识别的字段`；可跑 [`../examples/quickstart/contrast_false_pass.yml`](../examples/quickstart/contrast_false_pass.yml) 看原样演示（它与写对字段名的同名断言一绿一红） |
| 报「schema 文件不存在」/ CSV 找不到，本机却好好的 | 项目根没有 `debugtalk.py`，RootDir 退化成了「当前工作目录」 | 在项目根补一个 `debugtalk.py`；CI 里把 `working-directory` 设成**含 `debugtalk.py` 的那层** |
| 手写的 `conftest.py` 里普通 fixture 「不生效」 | 用例方法签名固定，普通 fixture 注入不进去 | 改成 `autouse=True`；要传值就写 `os.environ` + `debugtalk.py` 函数 |
| 想让用例拿到一个值，但夹具没法 return 给用例 | `autouse` 夹具不能给用例传值 | 夹具写 `os.environ` → `debugtalk.py` 里读 → 用例写 `${func()}` |
| `.env` 里配的值被「上一个项目」的值顶掉/串了 | 历史行为：切到「没有 `.env`」的项目时会继承上一个项目 | 已修复（切项目会撤销上一个项目写进去的键）；升级到含该修复的版本即可 |
| CSV 第一列参数取不到（报找不到列） | CSV 带 UTF-8 BOM（Excel 常见） | 已修复（按 `utf-8-sig` 读）；升级版本即可，无需手工去 BOM |
| `--save-tests` 之后发现 `conftest.py` 被改写了 | 该文件已被框架标记为自己生成的 | 你手写的那份**不会被覆盖**（框架会另存 + 报错）；若要「框架生成汇总」，把 `session_fixture` 合并进你的 conftest 即可 |
| 多项目一次跑，环境互相污染 | 每个项目根都要有自己的 `debugtalk.py` / `.env` / `conftest.py` | 按第 10.1 表逐项配齐 |
