# 接口测试智能化改造项目评审分析

> 评审日期：2026-09-26  
> 评审范围：`interfacetester_ai/` 的接口文档生成链路、现有闸门、模型基线、人工抽检与相关测试。  
> 评审目标：明确从“可复核初稿”到“可自动代表接口契约的测试”还缺什么，并给出能分阶段开发、能通过测试验收的改进方案。

## 一、结论摘要

项目的工程骨架较完整：模型只输出受约束的 `CaseDraft`，随后由代码装配、做文档溯源与静态闸门，再调用 InterfaceTester 的导出校验；已实现脱敏、缓存、审计、失败留痕和人工转正路径。相关实现主要位于 [`gen.py`](../interfacetester_ai/gen.py)、[`schema.py`](../interfacetester_ai/schema.py)、[`assembler.py`](../interfacetester_ai/assembler.py) 与 [`gates.py`](../interfacetester_ai/gates.py)。

但必须把两种“可用”分开：

1. **可复核初稿：有条件可用。** 能生成结构合法、带原文出处、通过框架静态校验的候选用例，并暴露一部分未知项；适合节省编写时间，交给工程师复核。当前仍存在条件字段误报、枚举覆盖不一致等实证问题，不能把 `ok` 或通过 L2 理解为语义正确。
2. **无需审核、直接代表接口契约：尚不可用。** 当前没有足够证据证明每条断言语义正确、覆盖充分、请求前置条件正确，也没有把真实服务运行和缺陷检出能力纳入生成准入。对任意自然语言接口文档，不能承诺无人审核自动入 CI。

近期定向测试实测为 `55 passed, 18 subtests passed`。它证明生成链路和装配闸门的预设行为受到测试保护；测试主要使用 `FakeTransport`，不构成真实模型语义质量或真实接口可运行性的证据。

**建议目标形态：** 普通 Markdown 文档默认产“待审核草稿”；只有来源结构化、契约信息完整、无关键未知项，并通过隔离环境执行与变异验证的受支持文档，才允许进入“可自动晋级”状态。将来是否自动晋级仍应是独立策略开关，不能和“生成成功”混为一个状态。

## 二、现状证据与口径

| 观察 | 证据 | 评审判断 |
| --- | --- | --- |
| 模型输出不是直接落盘 YAML，而是先经过 schema、装配和闸门 | [`schema.py`](../interfacetester_ai/schema.py)、[`gen.py`](../interfacetester_ai/gen.py)、[`assembler.py`](../interfacetester_ai/assembler.py) | 这是正确的隔离与校验边界，值得保留。 |
| 文档引文采用归一化后的包含匹配；字段名和期望值做有限的文本对账 | [`assembler.py`](../interfacetester_ai/assembler.py) 中的 `quote_hits`、`check_field_in_quote`、`check_expect_in_quote` | 能证明“有一段相关原文”，不能证明模型正确理解了条件、字段语义或断言方向。引文命中不能等同语义证明。 |
| 端点检查要求 URL 在全文出现，但 HTTP method 仅检查动词是否在全文出现 | [`assembler.py`](../interfacetester_ai/assembler.py) 的 `check_endpoint_in_doc` | `POST` 和某个路径分别出现，不代表它们是同一个端点；跨接口文档仍可能错配。 |
| `protocol-only`（仅状态码等协议断言）会被记入 `unknowns`，但属于降级信息而不是硬拒绝 | [`assembler.py`](../interfacetester_ai/assembler.py) 的 `draft_to_ircase` | 系统可能产出可加载但业务验证很薄的用例。应让质量状态显式可见，不能只看 `ok=true`。 |
| L2 校验是加载、生成期渲染及 Python 产物检查，不向目标 API 发请求 | [`assembler.py`](../interfacetester_ai/assembler.py) 的 `assemble` | 证明框架接受产物，不证明 URL、认证、测试数据、期望响应或断言符合真实服务。 |
| 15 篇 golden 的 15/15 是人工 YAML 的 L2 通过率 | [`golden_harness.py`](../bench/golden_harness.py)、[`golden_baseline_test.py`](../tests/golden_baseline_test.py) | 是装配/内核的回归基线，不是 AI 从文档生成的准确率。 |
| 真模型 `gemma4:latest` 记录过 13/15（86.7%）和后续 13/14（92.86%）的接口片产出率 | [`模型基线测量方案.md`](模型基线测量方案.md)、[`out_l2_baseline_gemma4-latest.recomputed.json`](../probe_p0a_llm/out_l2_baseline_gemma4-latest.recomputed.json) | 是特定模型、机器、样本和日期下的产出能力记录；两轮分母不同且存在运行差异，不能把差值归因于某个改动。L2 通过率对落盘产物恒为 100%，不能作为模型成绩。 |
| 修正后离线回放生成的 52 条字段级断言，评分 JSON 记为 52/52；抽检表中仍有被人工备注指出的条件字段与枚举缺口 | [`A_r11_assertion_review.md`](../probe_p0a_llm/review_sheets/gemma4-latest_mergedfix/A_r11_assertion_review.md)、[`out_review_scores_gemma4-latest.json`](../probe_p0a_llm/out_review_scores_gemma4-latest.json) | 这是有价值的样本级审查，但不能外推成 100% 语义准确率。评分结果、表中备注和基线文档“待人工判定”状态需要统一。 |

特别要避免三种口径混淆：

- **生成成功率**只表示产物进入指定阶段，不等于语义正确率。
- **L2 通过率**只表示框架能加载/生成，不等于目标 API 能运行。
- **运行通过率**也不自动等于测试有效；一个只断言 HTTP 200 的用例可能稳定通过，却漏掉所有业务错误。

## 三、两层“可用”的准入定义

### 3.1 第一层：可复核初稿

**目标：** 把人工从空白编写转为“核实、补全、批准”，不承诺无人审核使用。

建议初稿必须同时满足：

1. **结构完整。** `CaseDraft` 字段和类型合法，能通过框架导出校验；导出校验状态、模型调用状态、被拒原因分开记录。
2. **来源可定位。** 每个接口、请求字段、响应断言都能指向文档的稳定位置（文件摘要、页/章节、行区间或文本锚点），不能只有一段可碰巧命中的引用文本。
3. **不确定性可见。** 不能确定的条件、认证、前置数据、枚举、字段归属和断言进入 `unknowns`；存在关键未知项时，状态必须是“待人工”，不能显示成普通成功。
4. **覆盖可审查。** 报告并列展示已覆盖字段、未覆盖字段、协议级断言、降级/拒绝项、无断言步骤及依赖关系；不能用断言条数代替覆盖质量。
5. **安全边界明确。** 默认脱敏；生成阶段不调用业务 API；候选产物与已批准用例分区存放；只有显式人工确认才能转正。
6. **复核材料齐全。** 一次生成保存模型与 prompt 版本、输入摘要、原始响应、来源定位、合并决策、静态检查结果和产物摘要，能够重放并解释产物如何形成。

**第一层的验收结果不是“用例可以直接进 CI”，而是“人工能在有限时间内判断每个重要字段和断言是否可信，并能安全地拒绝或修改”。**

### 3.2 第二层：可自动代表契约的测试

**目标：** 在明确支持的输入范围内，自动生成可运行、覆盖有意义且可检测契约偏差的测试。

这一层必须同时有**契约可信度**与**运行有效性**证据：

- **契约可信：** 优先从 OpenAPI 等结构化契约生成；对自然语言文档，只有解析器能明确识别接口、参数位置、必填/可选/条件、类型、枚举、范围、认证和响应约束时才允许自动化。未知或冲突的关键事实一律阻止自动晋级。
- **请求可运行：** 有隔离的目标环境、有效账号/令牌、必要前置数据、可重置数据和清理策略；不能把无法配置环境造成的失败归因于模型，也不能因没有执行就称为可运行。
- **断言可代表预期：** 必填字段、范围、枚举、成功/业务错误响应和条件返回均有明确 oracle；每条断言有可追溯证据；关键业务断言不能退化为只测状态码。
- **缺陷检出得到验证：** 除正常样本通过外，还要在参考服务或受控 mock 上注入已知偏差，证明用例会失败。生成的测试若对预期缺陷没有敏感性，即使绿灯也不能视为有效。
- **可重复且安全：** 在隔离数据上重复执行，确认无偶发依赖、无生产写操作、无跨用例污染；副作用接口要有幂等或专门清理策略。

**自动晋级范围应先限定为结构化契约和项目明确支持的文档子集。任意 Markdown、含歧义的业务描述、需猜测账号/数据/副作用的流程继续停留在第一层。**

## 四、差距与可落实的改进

| 优先级 | 当前缺口 | 具体改进 | 可验证结果 |
| --- | --- | --- | --- |
| P0 | 当前 `ok` 容易被理解为“测试有效”；产出、静态校验、待审核、运行、转正状态耦合 | 定义统一状态机：`generated`、`static_valid`、`needs_review`、`runtime_verified`、`auto_promotable`、`rejected`。CLI 和报告分别展示每一层结果；仅 `auto_promotable` 可按策略进入自动晋级路径 | 对每种状态构造测试，状态转换非法时拒绝；仅 L2 通过不能得到 `runtime_verified`。 |
| P0 | 基线与人工抽检口径不一致；同一模型多轮样本分母变化 | 固定样本清单和文档摘要；同模型、同样本、固定 prompt/配置，分别运行 merge on/off 和重复运行；评分表、JSON、基线文档由同一产物生成。人工抽检需记录判定人、分歧和仲裁 | 同一轮报告能够还原逐篇分母/分子、失败原因、模型版本、prompt 版本和判定状态；不存在 JSON 与文档“一个已判、一个待判”的冲突。 |
| P1 | 引文是文本命中，不是语义关系 | 给字段、请求、响应和接口建立结构化证据节点：`source_id`、位置、证据类型（规范/示例/说明/条件）、解析值；断言引用证据 ID，并显示其关联的路径、方向和算子 | 对“示例值不能当固定值”“字段名相似但不同”“相邻句误引用”等反例，机器必须拒绝或标待人工；报告可回到原文位置。 |
| P1 | 条件/可选字段处理不完整。抽检表明确记录 `avatarUrl` 条件返回却被无条件断言 | 在确定性映射中识别“仅当/如果/视…而定/可选/可能不返回”等条件；无法把条件转为前置条件或条件断言时不生成存在性断言，并写入 `unknowns` | 增加条件返回正反例；条件不满足时生成用例不能因字段缺失误报失败；未识别条件时不得自动晋级。 |
| P1 | 枚举生成覆盖不一致。抽检发现 `status` 行未生成枚举断言，而类似 `event` 行生成了枚举 | 统一枚举抽取器与规范化规则，区分“完整枚举集合”“引用其他表”“示例列表”；集合不完整时标未知，禁止生成不完整 `contained_by` | 同一表达形式在字段表和响应说明中的等价样本得到一致结果；遗漏枚举属于覆盖缺口并阻止自动晋级。 |
| P1 | 端点 URL 与 method 只弱关联；字段位置可能被错误解释 | 将接口识别做成实体级绑定：每个 endpoint 拥有 method、path、参数位置、请求/响应 schema、认证和父子章节；无法唯一绑定时停止自动生成 | 注入两个接口、交叉出现 GET/POST 与路径的文档，生成器不得把动词与错误路径拼接；校验 query/path/header/body 位置。 |
| P1 | 覆盖率能展示漏项，但目前没有阻止“只有状态码”的薄用例进入 `cases/` 的统一策略 | 为业务接口设定最低业务断言要求；允许纯协议断言作为草稿，但强制 `needs_review`；区分协议覆盖与业务字段覆盖 | 只有 `status_code` 的生成结果不会显示为可直接使用；`cases/` 或自动晋级策略按明确状态拦截，而非只在 unknowns 附注。 |
| P2 | L2 未执行真实请求，也没有验证测试能否发现已知缺陷 | 建立隔离的 reference/mock API：按固定契约返回正常与边界响应；让生成用例运行；通过受控变异（删字段、改类型、越界值、错误状态码）检验断言是否能失败 | 测试报告包含运行通过率、变异检出率、失败归因；至少覆盖字段缺失/类型错/枚举越界/范围越界/错误端点等变异。 |
| P2 | 多步链路、认证、状态和副作用对运行有决定性影响 | 把前置步骤、token 提取/传递、测试数据创建与清理、幂等性、重试安全和可并行性建模为显式依赖；不确定时交人工 | 登录后访问、创建后查询/删除等链路在隔离服务重复运行；清理失败与业务失败分开报告。 |
| P2 | 生成质量缺少模型/提示词变更后的稳定回归和广泛人工评估 | 扩展固定真实文档集，按文档类型分层；对关键字段与断言进行双人盲审、分歧仲裁；保存样本和评分版本 | 每次模型、prompt、解析规则升级均运行同一评估；准确率、覆盖率、未知召回率和置信区间一并报告，不只报产出率。 |

## 五、建议的状态与落盘规则

建议在现有结果对象上增加明确的质量状态，而不是继续只依赖布尔 `ok`：

| 状态 | 含义 | 默认落点/行为 |
| --- | --- | --- |
| `generated` | 模型返回了可解析候选 | 仅 `.ai/draft/`，不代表可执行 |
| `static_valid` | schema、框架渲染和已知静态闸门通过 | 仍属于候选；继续检查 unknowns 和覆盖 |
| `needs_review` | 存在语义未知、仅协议断言、条件/依赖/字段位置不确定 | `.ai/draft/` + 审核清单；不能自动进入 CI |
| `runtime_verified` | 在指定、隔离、可重置的目标环境执行通过 | 记录环境/数据/时间/请求摘要；不自动等价于契约正确 |
| `auto_promotable` | 契约来源受支持、关键未知为零、静态与运行及变异门槛均通过 | 仅在显式启用的策略下进入批准/晋级流程 |
| `rejected` | 存在结构错误、危险静默陷阱或关键契约冲突 | 不落生产用例；保留原始证据和拒绝原因 |

保留项目现有“修复不自动 apply”的安全决策。用例晋级与自动修复是两个不同权限，不应因为自动生成通过了某项测试就顺带开放文件修改权限。

## 六、分阶段实施计划

### 阶段 0：先统一事实与质量状态

**目标：** 让团队能准确回答“哪一批模型、对哪些文档、生成到了哪一步、经谁评过”。

1. 对齐 `out_review_scores_*.json`、抽检表、`模型基线测量方案.md` 的状态；若人工已判 52 条，将日期、判定人、分歧备注回填；如果备注指出潜在错误，先复核后再确认计分。
2. 固定一组带内容摘要的评测文档，记录模型名/版本、prompt 版本、采样参数、配置、切片总量、非接口跳过数、接口片数、失败归因和缓存命中情况。
3. 同一批次做 merge on/off 对照，并至少做一次重复运行；不比较不同分母的百分比，不把 L2 通过率当模型质量指标。
4. 在 `GenResult` / `AssemblyResult` 报告中区分“生成、静态通过、待人工、执行通过、变异验证、可晋级”。

**验收：** 一份机器报告即可复现全部统计；非接口跳过、模型失败、静态拒绝、人工待判和运行失败分开计数；没有把“未测”记成 100%。

### 阶段 1：增强证据绑定与文档理解

**目标：** 把“引用存在”提升为“断言与具体契约事实绑定”。

1. 在 Markdown 现有解析器上扩展接口实体和章节归属，优先补齐 method/path 成对绑定、参数位置、响应字段、认证与前置条件。
2. 结构化表示条件返回、可选、枚举、范围、示例和引用型描述；不能可靠解析的表达必须降级为 `needs_review`。
3. 每条断言引用稳定证据位置和证据类型；保留原文快照与文档摘要，避免文档更新后引用失效。
4. 补充对抗测试：条件字段、嵌套字段、字段名相似、两个接口交叉方法、示例值、枚举缺值/跨行、GET 参数与响应字段同名等。

**验收：** 在固定的解析评测集上，关键端点绑定和来源定位达到 100% 机器一致；所有不确定条件都进入人工队列，不能静默降级成无条件断言；枚举/条件字段的误断言对抗样本全部拦截。

### 阶段 2：在隔离服务上证明“可运行、能发现错误”

**目标：** 把框架可加载扩展成真实执行有效性。

1. 为支持的契约建立独立参考服务或可重置 mock。oracle 来自人工确认的契约，不得由同一份 AI 生成用例反向生成，否则会循环自证。
2. 增加执行适配：测试账号/环境变量、依赖数据、token 生命周期、清理钩子、并发隔离和幂等保护；默认禁止对生产环境执行生成产物。
3. 每份测试在正常响应下执行，并对参考服务注入一组可控故障：错误状态码、缺字段、错误类型、枚举越界、边界外数值、端点/方法不匹配。
4. 把失败分成环境/认证/数据准备/请求构造/断言失败/清理失败，不能将它们统称“模型生成失败”。

**验收：** 生成测试在干净参考环境重复运行稳定；对预设契约变异达到建议的至少 90% 检出率；任何未触发的关键变异必须能定位到缺少的断言或未覆盖条件。达到该门槛前，只能标记 `runtime_verified`，不得自动标记契约级可用。

### 阶段 3：限定自动晋级范围

**目标：** 先为低歧义、高结构化输入建立无人审核的窄通路。

1. 第一批自动晋级输入限定为 OpenAPI 或等价结构化契约；Markdown 只在明确列入已验证模板白名单后开放。
2. 自动晋级必须满足：method/path 唯一匹配；参数位置和类型明确；认证与前置数据可配置；关键必填/范围/枚举/条件规则有 oracle；无关键 `unknowns`、`TODO`、冲突或仅状态码断言；静态校验、隔离执行和变异验证均通过。
3. 任一条件不满足，就生成第一层初稿并标明缺项。禁止以“模型自评置信度高”替代任何硬条件。
4. 首批试运行只对非生产、可重置服务开放；记录自动晋级后的人工回滚和误报情况，再决定是否扩大文档范围。

**验收：** 未满足任一门槛的样本自动进入 `needs_review`；达到门槛的样本可重复执行且通过变异集；每个自动晋级案例都有机器可追溯的来源、环境和质量报告。

## 七、建议的质量指标

下面是建议的**新目标门槛**，不是当前已达到的结果。先在固定评测集试运行，按样本规模和误差成本校准后再对外承诺。

| 指标 | 定义 | 第一层初稿目标 | 第二层自动晋级目标 |
| --- | --- | --- | --- |
| 端点绑定准确率 | method/path 与人工标注契约完全匹配的比例 | ≥ 98%，错误项必须可见 | 100%（自动晋级样本） |
| 断言语义精确率 | 人工双审确认正确的落盘断言 / 已判断言 | ≥ 90%（沿用项目已决阈值，但报告分歧） | ≥ 98%，且关键约束错误为 0 |
| 关键字段覆盖率 | 被正确断言的关键契约字段 / 应覆盖关键字段 | ≥ 90%，遗漏逐项列出 | ≥ 95%；遗漏关键必填/边界规则为 0 |
| 来源可追溯率 | 能准确指回契约节点/原文位置的断言 / 全部断言 | 100% | 100% |
| 未知召回率 | 人工标注的歧义/条件/缺失项中被系统标出的比例 | ≥ 90% | 自动晋级样本关键未知为 0 |
| 变异检出率 | 被生成用例检出的受控契约故障 / 全部有效变异 | 先建立基线 | ≥ 90%，关键变异不得漏检 |
| 重复执行稳定率 | 相同隔离条件重复运行得到相同通过/失败结论的比例 | 记录，不作为语义指标 | ≥ 99%，不稳定案例阻止晋级 |

语义精确率至少需 100 条有效断言、覆盖多个文档和接口类型，并由两名审查者独立判定、对分歧仲裁；单一模型、单一文档集、单人 52 条抽检只可作为阶段性观察。除了比例还应报告样本数、未知数、分歧数和置信区间。

## 八、建议先做的具体任务

按依赖关系建议从以下五项开始，不需要重写整套 AI 层：

1. **统一质量状态和基线口径。** 修正“模型成功/导出通过/语义合格/目标环境可运行”混用的问题，并统一人工评分状态。
2. **补齐条件字段与枚举回归测试。** 以抽检表中的 `avatarUrl`、`status`、`event` 为首批固定样本，先保证已知问题不会继续进入自动化状态。
3. **增强端点 method/path 绑定。** 把分散文本匹配改成接口实体与章节的关联，配交叉端点对抗样本。
4. **建立独立参考服务与变异用例。** 将 L2、运行通过和缺陷检出分别报告，避免循环验证。
5. **定义自动晋级白名单。** 初期仅支持信息充分、结构明确、环境可隔离重置的契约；其他输入稳定退回人工复核。

## 九、决策建议与边界

- **近期可以交付：** “AI 生成可复核初稿”的能力，前提是报告明确列出来源、覆盖、未知项和人工审核要求。
- **近期不应承诺：** “任意接口文档均可无人审核生成正确、完整、可直接进 CI 的测试”。现有模型产出率与静态闸门不足以支持该承诺。
- **不建议优先做：** 继续堆 prompt 规则或仅扩大模型调用次数。若没有更好的证据绑定、真实执行和变异评估，更多调用只会扩大产物数量，不会证明正确性。
- **保留现有安全立场：** 默认不打真实业务服务、不自动修复或覆盖人工文件；自动晋级只对明确白名单范围开放，并保留退出开关与审计轨迹。
- **阶段门槛：** 阶段 0 和 1 达标后，可以对“可复核初稿”作明确承诺；阶段 2 和 3 达标后，只能对已验证输入范围承诺自动契约测试，不能外推到任意自然语言文档。
