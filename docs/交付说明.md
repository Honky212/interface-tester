# 交付说明（InterfaceTester 内核 + AI 协作层）

> 版本：`interfacetester` **5.0.1**（内核，Apache-2.0 + NOTICE）｜`interfacetester-ai` **0.1.0**（旁路包）
> 日期：**2026-09-27**｜本文是**一页**交付说明：**能不能用、在什么前提下用、哪些地方**没**验过**。
> 每条结论都能指认依据（文末 §十 索引）；要细节看 `README.md` / `deploy.md` / `docs/能力清单.md`。

---

## 一、承诺边界（先看这一句）

**承诺**：把 **Markdown 接口文档**变成**可复核的用例初稿**——生成 → 闸门 → **人工转正** → 真跑。
适用形态是**内部少量文档 + 人工复核**；这是本仓**唯一有证据支撑**的承诺。

**不承诺**：**「任意自然语言文档 → 无人审核自动进 CI」**。按当前路径**不成立**，而且这是
**承诺范围**问题、不是"再优化几轮"能解决的（依据：`docs/未做完的待决策项.md` §九 停止条件与 §四 M-1/M-2）。

两条结构性保险（不是靠"记得去点确认"）：

- **判定永远在内核**：AI 只产"草稿 / 报告 / 建议"，执行、断言、判定、汇总全在内核；
- **草稿进 `cases/` 必须人工转正**：`haify review --approve` 是唯一通道（带**内容哈希绑定**——
  确认后又改一行，留痕失效，必须重确认）；`haify fix` 只给 diff，`--apply` **永不存在**。

## 二、交付物构成

| 件 | 是什么 | 入口 | 装法 |
| --- | --- | --- | --- |
| `interfacetester/` | **内核**：HttpRunner 4.3.5 衍生（34 模块）；执行/断言/判定/报告 | `hrun` / `hmake` / `hconvert` | `pip install -e .` |
| `interfacetester_ai/` | **AI 协作层**（旁路包，**内核 0 改动**）：生成/分析/建议/看板 | `haify` / `python -m interfacetester_ai`（同一份 `cli.main`） | `pip install -e interfacetester_ai`（★**独立发行版**：只装内核**不会**有 `haify`；删包即回滚） |
| `tests/` | **机器判据**（76 文件，2.3 MB）：含成对判据、元护栏、文档一致性 | `pytest tests` | 见 `deploy.md`（支持 `-n auto` 并行） |
| `probe_p2_prep/` | **实测探针 + 证据产物**（`out_*.txt`） | `python probe_p2_prep/routine.py` | 无需额外依赖 |
| `docs/` | 方案 v8 / 能力清单 / 架构与调用链 / 使用教程 / **未做完的待决策项** / **ARCHIVED**（废弃文档登记） | — | — |

> **AI 层与内核的关系**（一句话）：内核负责"**跑**"，AI 包负责"**生成 / 分析 / 建议**"；
> AI 包只 import 内核的**公开面**，**内核永不 import AI 包**（红线①，判据
> `tests/interfacetester_ai_pkg_test.py::TestKernelIsolation`）。

## 三、环境前提（少一样就会红，而且都是**响亮**的红）

| 前提 | 取值 / 做法 | 少了会怎样 |
| --- | --- | --- |
| `INTERFACETESTER_AI_BASE_URL` | OpenAI 兼容端点，**Ollama 必须带 `/v1`**（例：`http://127.0.0.1:11434/v1`） | 退出码 **2**（配置缺失），**绝不隐式出网** |
| `INTERFACETESTER_AI_MODEL` | 模型名（见 §四 矩阵） | 同上 |
| `INTERFACETESTER_AI_API_KEY` | 远端需填；**回环地址可省** | 远端缺 → 退出码 2 |
| `INTERFACETESTER_AI_SANDBOX` | 真发请求前必须 `on`（**即使 base_url 是回环**） | 被 **L3 闸门**拒（`l3_refused`），一个请求都不发 |
| `INTERFACETESTER_AI_TIMEOUT` | 本地大模型建议 **300 起**（默认 180s） | 超时类失败；报错文案会**点名**这个变量 |
| `INTERFACETESTER_AI_ALLOW_HOST` | 非回环目标要**显式列名** | 被 L3 拒（响亮，不静默降级） |
| `INTERFACETESTER_AI_ENABLE` | 全局开关（`off` 即短路 AI 层） | — |
| `INTERFACETESTER_AI_MERGE_ASSERTIONS` | 确定性断言并入模型草稿（默认开，`off` 回滚） | — |
| `filetype`（`.[upload]`） | 上传类用例的**核心**依赖 | 缺它就**响亮报错**，不静默降级 |
| `lxml`（`.[xml]`） | XML/XPath 编排算子 + XSD 契约 | 相关算子报可操作的安装提示；**本机未装**（见 §六） |

## 四、模型支持矩阵（**实测**出来的，不是"应该能"）

| 能力 | 结论 | 证据 |
| --- | --- | --- |
| `generate`（文档 → 草稿） | 真实模型上跑通；提示词 A/B 实测 v2.4 修掉 `contains: [body, 'FILE_xxxx']` 这类形态 | `out_model_path.txt` / `out_model_yaml.txt` / `out_e2e_run.txt` |

| `fix`（修正建议） | **规则引擎（不调模型）** → 不受模型非确定性影响；CLI 级真跑拿到补丁 | `tests/fix_test.py`（45 条）+ `docs/未做完的待决策项.md` §9.25 |
| `summary`（结果摘要） | 数字全部由代码渲染，模型只写导语（且导语里的数字过**白名单复核**） | `interfacetester_ai/summary.py` + 判据 |

> `python probe_p2_prep/routine.py --with-models` → 结论落在 `probe_p2_prep/out_analyze_models.txt`。
> 「**Fake 全绿 ≠ 真模型能用**」是本仓的硬纪律（单测全是 `FakeTransport`，它证明不了模型可用）。

## 九、例行维护（别让「哪个模型能用」再次失忆）

```powershell
python probe_p2_prep/routine.py                 # 确定性探针（不调模型、不出网）→ out_routine.txt
python probe_p2_prep/routine.py --with-models   # 再加「按模型统计 analyze 可用性」（真出网）
```

- **什么时候跑**：换模型、换文档、换机器/网络环境之后 —— 以及**交付前**；
- **分类纪律**：每个 `probe_*.py` 必须进 `routine.py` 的 `ROUTINE` / `MODEL_STEPS` / `EXCLUDED`（附理由），
  否则 `tests/docs_consistency_test.py::TestProbeRoutineCoversEveryProbe` 会**红**；
- **模型步骤不参与退出码**：断网 / 没配模型都算正常环境，它只负责**把结论写下来**。
