# 新手快速上手：不会写 YAML，也能跑起第一条用例

> **这份文档给谁看**：刚接触 InterfaceTester、**以前没写过 YAML 用例**的人（手工测试转自动化同样适用）。
> **它解决什么**：把散在各处的「第一步该做什么」串成一条**照做清单**——每一步都给**命令**、给**成功的样子**、给**没成功怎么办**。
> **它不重复什么**：细节都在别的文档里，本文只**指路**（第七节是学习顺序）。
> **它不给什么**：不承诺用例一定绿——**绿 ≠ 测到了**（见第五节坑 3）。

预计时间：约 90 分钟（跑通 3 条命令 + 改通 1 个用例）。

---

## 一、先认清三件事（不然会白费力气）

1. **它没有 Web 界面**，全程在终端敲命令。链路是：

   ```
   你的 xxx.yml  ──hrun──►  xxx_test.py  ──pytest──►  发真实 HTTP 请求 + 断言  ──►  终端结果 / HTML 报告
   ```

   所以「写 YAML」= 描述**调哪个接口、带什么参数、期望返回什么**，不用写 Python。

2. **用例写在你自己的「用例工程」里**，不要塞进框架仓库。
   框架仓库指的就是本仓库根目录（`interfacetester/` 与 `interfacetester_ai/` 这两个包所在的地方）——
   那边有一条「谁能写盘」的机器扫查（`bench/write_boundary_scanner.py`）和一堆文档一致性护栏，
   往里丢用例会被判违规。**照着 `project-two/` 的样子，在你自己项目里建一套就行。**

3. **`*_test.py` 是生成物，永远不要手改**——下次 `hrun` 会覆盖它。要改需求就改 `.yml`。
   （框架会认自己生成的标记；你手改过又删掉标记，它会**拒绝覆盖**并提示你把生成物整个删掉重跑。）

## 二、三条路线，先选一条（别同时上）

| 路线 | 用什么 | 适合谁 | 本节 |
| --- | --- | --- | --- |
| **A. 抄**（推荐起步） | `examples/quickstart/`（最小 3 文件）、`project-two/login_flow.yml`（离线两步链路）、`examples/unifsp/`（真实平台范例） | 完全没写过 YAML | 第三节 第 2~3 步 |

三条路线的产物是**同一种 YAML**，可以混用：先用 B/C 生成骨架，再按 A 的写法补断言。

## 三、照做清单（第 0~5 步）

### 第 0 步：装好并激活（一次性）

```powershell
# 在仓库根目录下（Windows）
D:\interface-tester\.venv\Scripts\Activate.ps1
# macOS / Linux： source .venv/bin/activate

hrun -V          # 验证：能打印出版本号就说明装好了
```

- **成功的样子**：打印出版本号。**不要求**与本文档或任何文档里的数字一致——
  版本唯一事实来源是 `interfacetester/__init__.py` 的 `__version__`（部署细节见 [`deploy.md`](../deploy.md)）。
- **没成功**：`'hrun' 不是内部或外部命令` → 没激活 venv；
  `missing dependency tool: black` → 同样是没激活（`hrun` 结束时会调 `black` 格式化生成物）。

### 第 1 步：跑通一个「零依赖」示例（证明环境没问题）

```powershell
interfacetester run examples/data_management -q
```

- **成功的样子**：最后一行出现 `passed` 且**没有** `failed`。这个示例自带本地 mock，**不联网**也能跑。
- **没成功**：先按 [`docs/ci/README.md`](ci/README.md) 的「验证清单」排；这一步没通，先别急着写用例。

### 第 2 步：抄一个最小骨架（核心就 3 个文件）

```powershell
cd examples\quickstart
hrun hello_func.yml            # 地址来自 debugtalk.py 的默认值，不需要先配 .env
```

> ⚠️ **这个示例默认指向公网**（`https://httpbin.org`），所以**能上外网**时零配置即可跑通；
> 内网 / 离线环境请先用**第 1 步**（`examples/data_management`，自带 mock）或**第 3 步**（`project-two`，自带 mock）练手。

**你自己的用例工程只需要这 3 个文件**（照 [`examples/quickstart/`](../examples/quickstart/README.md) 抄）：

| 文件 | 作用 | 能不能省 |
| --- | --- | --- |
| `debugtalk.py` | **门牌号**：框架靠它认出「项目根（RootDir）」，所有相对路径（`schemas/`、`data/`、上传文件）都以它为基准；顺带放自定义函数（**怎么写见 4.4**） | **强烈建议别省**（哪怕是空文件） |
| `.env` | 环境信息（域名、账号）；用例里用 `${ENV(名字)}` 取 | 可选 |
| `hello.yml` | 用例本体 | 必须 |

> 为什么「门牌号」重要：没有它，RootDir 会退化成**你敲命令时所在的目录**——换个目录跑就报「文件不存在」。

### 第 3 步：拿一个离线练习场试手（强烈建议）

`project-two/` 是一份现成的**两步链路**示例，**自带 mock 服务**，不联网也能跑：

```powershell
cd D:\interface-tester\project-two
python mock_server.py      # 终端 A：常驻（模拟「登录发 token → 校验 token」两个接口）
hrun login_flow.yml --html=reports/login.html --self-contained-html   # 终端 B
```

- **成功的样子**：终端 `passed`，且 `reports/login.html` 双击就能离线打开（单文件报告）。
- 这条用例做的事：第 1 步登录 → 用 `extract` 把响应里的 token 存成变量 → 第 2 步把它放进 `Authorization` 再请求。
  **这就是「步骤之间传参」的全部秘密**——看懂它，你已经会写大部分接口用例了。
- 想看**结构化**的运行结果：加 `--save-tests`，框架会把汇总写进 `logs/**.summary.json`
  （`project-two/logs/` 里已经有现成的可以对照）。里面逐条记着请求、响应、每条断言的
  `check_result`（`pass`/`fail`）——**排查失败时先看它，比猜快**。

### 第 4 步：要写别的接口？优先「转」，其次「生成」

**有 Postman / curl / HAR / OpenAPI 资产（推荐，最省事）**：

```powershell
hconvert --from postman --in postman_collection.json --out converted/
hconvert --from curl    --in curl_commands.txt       --out converted/
hconvert --from har     --in demo.har                --out converted/
hconvert --from openapi --in api.yaml                --out converted/
hrun converted\xxx.yml
```

生成的是**和你手写完全同构的 YAML**，而且：凭据（Cookie / Authorization / token）**一律占位**成 `${...}`；
HAR/Postman 用录制响应、OpenAPI 用契约 schema **自动生成断言**；落盘时默认**导出即验证**。
每个源支持哪些写法、哪些会被降级告警，逐条见 [`docs/convert/README.md`](convert/README.md)。

**只有接口文档（没有请求资产）**：让 AI 起草，**人工确认**之后才进正式用例区：

```powershell
# 先在终端 cd 到你想让 cases/ 与 .ai/ 出现的那个目录（本机 = 框架仓库根 D:\interface-tester），再敲：
python -m interfacetester_ai gen interfaces.md          # 接口文档 → 草稿（落 .ai/draft/）
python -m interfacetester_ai review --list               # 看有哪些草稿、缺什么
python -m interfacetester_ai review --approve <用例名> --approver 你的名字   # 签名确认 → 才搬进 cases/
```

> **两条新手必读**（都实测过）：
> 1. **本机没有 `haify` 命令**（`.venv\Scripts\haify.exe` 不存在）→ 上面用等价的
>    `python -m interfacetester_ai`；`haify` 只是装了 AI 包之后**多出来的别名**。
> 2. 这些命令**必须在"工作根目录"下跑**：`cases/`、`.ai/`、`reports/` 全是**相对当前目录**的，
>    换目录跑就会"找不到草稿"或把产物建到别处。详见 **4.5**。

先记住两条硬规矩：**带 `TODO_` 占位的草稿进不了 `cases/`**（缺的期望值必须人工填，不填就是"人工待办伪装成用例"）；
**确认之后又改了一行，确认立刻失效**（要重新签名）。完整说明见 [`docs/使用手册-AI协作层.md`](使用手册-AI协作层.md)。

### 第 5 步：自查 + 出报告

```powershell
cd D:\my-api-tests        # ← 先 cd 到你的用例工程根，再敲下面三条
hmake cases\login.yml                                # 只编译不运行（看生成的 pytest 代码）
python check_case.py cases\                          # 自写用例的体检脚本（见第六节）
hrun cases\ --html=reports\report.html --self-contained-html
```

- `hmake` = **只编译不运行**：能抓「算子名写错 / 必填字段缺失 / 内联 schema」这类生成期问题，改用例时用它最快。
- `hrun` = 编译 + 真跑；`--self-contained-html` 出的是**单文件**报告，双击可离线看。
- **失败了先分清三种「红」**：① 值不对；② 类型不对（`"200"` 是字符串、`200` 是数字）；
  ③ **用例自己没跑起来**（如 `EnvNotFound: XXX`）。第 ③ 种先去查用例和 `.env`，**别去怀疑接口**。
- 细节在 `logs/<case_id>.run.log`；结构化结果在 `logs/*.summary.json`（**加 `--save-tests` 才有**）。

## 四、抄写模板（可直接复制）

### 4.1 最小用例：一个 `config` + 一串 `teststeps`

```yaml
config:
    name: 登录并查询用户信息          # 必填
    base_url: ${ENV(BASE_URL)}       # 从 .env 读，别硬编码
    verify: false                    # 测试环境 https 不校验证书

teststeps:
  - name: 登录获取 token             # 必填
    request:
        url: /api/login              # 相对路径，自动拼 base_url
        method: POST
        headers:
            Content-Type: application/json
        json:
            username: ${ENV(USERNAME)}
            password: ${ENV(PASSWORD)}
    extract:                         # 提取成变量 $token（建议写 dict 形式，见第五节坑 4）
        token: body.data.token
    validate:
        - eq: [status_code, 200]
        - eq: [body.code, 0]

  - name: 带 token 查用户信息         # 步骤从上到下顺序执行，前一步的变量后一步能直接用
    request:
        url: /api/user/info
        method: GET
        headers:
            Authorization: "Bearer $token"
    validate:
        - eq: [status_code, 200]
        - eq: [body.data.username, admin]
```

**三条铁律**：`config.name` 与每个 step 的 `name` **必填**；变量用 `$变量名`、函数用 `${函数名(参数)}`（别混用）；
**每个请求步骤都要有 `validate` 或 `extract`**（为什么，见第五节坑 3）。

### 4.2 字段速查（写错字段名会被**静默忽略**，所以只写白名单里的）

| 层 | 合法键 |
| --- | --- |
| 顶层 | 只有 `config`、`teststeps` 两个 |
| `config` | `name` `base_url` `verify` `variables` `parameters` `oauth2` `timeout` `export` `skip` `db` `thrift` `path` |
| `request` | `method` `url` `params` `headers` `cookies` `json` `data` `upload` `x_path` `timeout` `verify` `allow_redirects` `stream` `proxies` `cert` `req_json` |
| `step` | `name` `request` `extract` `validate` `export` `variables` `setup_hooks` `teardown_hooks` `retry_times` `retry_interval` `testcase` `sql_request` `thrift_request` `validate_script` |

> `validate` 有一个**等价别名** `validators`（历史写法，`hmake` 同样认）——**统一写 `validate`**，
> 别混着用（第六节的自查脚本两个都认，不会因此误报）。

> 上表的**权威来源**是内核本身（`interfacetester/models.py` 的 `KNOWN_*_FIELDS`），
> 想核对当前真实清单可以自己打一份（**别照抄文档，文档会过期**）：
>
> ```powershell
> python -c "from interfacetester.models import KNOWN_CONFIG_FIELDS as c, KNOWN_STEP_FIELDS as s, KNOWN_REQUEST_FIELDS as r; print(sorted(c)); print(sorted(s)); print(sorted(r))"
> ```

### 4.3 断言怎么写

格式固定是 `- 算子: [检查项, 期望值, "可选的自定义失败提示"]`：

```yaml
    validate:
        - eq: [status_code, 200]                       # 状态码
        - eq: [body.code, 0]                           # 响应体字段
        - eq: [body.data.list[0].name, "张三"]          # 数组 + 嵌套
        - contains: [body.data.tags, "vip"]            # 包含
        - gt: [body.data.total, 0]                     # 大于
        - regex_match: [body.data.phone, "^1\\d{10}$"]  # 正则
        - type_match: [body.data.id, int]              # 类型
        - eq: [body.code, 0, "code 应该等于 0"]          # 第三项是自定义失败提示
```

- **常用别名**：`eq`/`equals`→`equal`、`ge`→`greater_or_equals`、`gt`→`greater_than`、`le`、`lt`、`ne`、
  `str_eq`→`string_equals`、`len_eq`→`length_equal`。
  ⚠️ **`gte` / `lte` 不是别名**——写了会被 `hmake` 拒（实测报 `unknown assert comparator: gte`）。
- **算子的完整白名单**（含结构契约与 XML 类）自己打一份，别背：
  ```powershell
  python -c "from interfacetester.make import BUILTIN_COMPARATOR_NAMES as n; print(len(n), sorted(n))"
  ```
  每一项能做什么见 [`docs/能力清单.md`](能力清单.md)。
- **检查项**（`check` 那一位）可用：`status_code`、`body.xxx`、`headers.xxx`、`cookies.xxx`、`text`、
  `elapsed_ms`、`elapsed_s`、`response_size`、`reason`。
  **非 JSON 响应**（bytes）上别写 `body.xxx`，改用 `text` 或 XPath 类算子（见 [`docs/soap/README.md`](soap/README.md)）。
- **期望值类型**：数字写**字面量**（`200`），别写 `"200"`（两侧都是字符串会按**字典序**比较）。
- 变量与函数：`$token`、`${ENV(NAME)}`、`${my_func()}`；**函数参数不能带引号**，
  需要传复杂参数先用 `config.variables` 存好再 `$变量名` 传进去（例子见 [`examples/unifsp/README.md`](../examples/unifsp/README.md) 的签名示例）。

### 4.4 `debugtalk.py`（门牌号）怎么写

**它的第一价值是「定位项目根（RootDir）」，不是「放函数」**：
框架从用例路径**向上查找** `debugtalk.py`，**找到的那个目录**就是项目根——
`schemas/xxx.json`、`data/xx.csv`、上传文件、被引用用例的路径**全都相对它解析**。
找不到时，RootDir 会退化成「你敲命令时所在的目录」（换个目录跑就报「文件不存在」）。

**最小写法：一个纯注释文件就够**（项目还没到写函数的时候，这样就行）：

```python
# debugtalk.py —— 本项目的「门牌号」：告诉框架「这个目录是一个项目」。
# 暂时不需要自定义函数，留空也可以。
```

**什么时候才往里加函数**（其余情况别提前抽象）：

| 场景 | 例子 |
| --- | --- |
| 地址 / 路径拼装 | `${base_url()}`、`${test_dir()}`、`${app_path()}` |
| 动态数据（每次跑都不一样） | 时间戳、随机串、UUID → `${get_timestamp()}`、`${gen_random_string(8)}` |
| 算法类（签名 / 加密 / 编码） | `${md5_sign($sign_params, ${ENV(APP_SECRET)})}` |
| hook | `setup_hooks: - ${log_request($request)}`、`teardown_hooks: - ${log_response($response)}` |

> 一句话：**凡是能用 Python 表达的逻辑，都写在 `debugtalk.py` 里，不用改框架**。

**哪些名字会进「函数表」（实测规则，和你想的可能不一样）**：

| | 会不会进函数表 |
| --- | --- |
| 自己 `def` 的 Python 函数 | ✅ 会 |
| **`_` 开头的函数**（`def _private()`） | ✅ **也会**——它**不是私有**的，别把密钥/开关塞在这类函数里当"隐藏" |
| `from mymod import my_py_func`（**纯 Python** 函数） | ✅ 会 |
| 模块级常量 / 变量（`CONST = "x"`） | ❌ **不会**：`$CONST` 报 `VariableNotFound: ['CONST']`。要共用常量 → 写成函数 `def base_url(): return ...`，或放 `.env` 用 `${ENV(NAME)}` |
| C 实现的内置函数（如 `from hashlib import md5`） | ❌ 不会（它不是 `FunctionType`）——自己在函数里包一层即可 |

**调用规则（写成什么样才跑得起来）**：

- 用 `${函数名()}`；**参数不能带引号**（`${fn('a')}` 不认）。
- 参数里想放变量/字典：先在 `config.variables` 里备好，再 `$名字` 传进去（下面的模板就是这么用签名的）。
- **优先级**：`debugtalk.py` 的函数 **优先于**内核内置函数（同名会覆盖它）→ 内核内置 → Python 内置（**只有纯计算白名单**：`len/int/str/float/bool/list/dict/set/tuple/sorted/sum/...`；`eval`/`exec`/`open`/`getattr` 这类一律拒绝）。
- 函数名写错**不会**在 `hmake` 阶段暴露（生成期它只是个字符串字面量），**只会在 `hrun` 运行时**报：
  `FunctionNotFound: nope_no_such_fn is not found.`（而且**发生在发请求之前**，一次请求都不会发出去）。

**可直接抄的模板**（下面这份**已实测**：配 `project-two/mock_server.py` 跑出 `1 passed`）：

```python
"""debugtalk.py —— 本项目的「门牌号」+ 可选的自定义函数库。

用例里用 ${函数名(参数)} 调用下面的函数（参数不能带引号）。
"""
import hashlib
import os
import random
import string
import time


def base_url():
    """优先读 .env 里的 BASE_URL，没有就回落到默认地址。"""
    return os.environ.get("BASE_URL", "http://127.0.0.1:8000")


def get_timestamp():
    """秒级时间戳（造唯一名字时常用）。"""
    return int(time.time())


def gen_random_string(length=8):
    """随机字母数字串（造不撞名的测试数据）。"""
    chars = string.ascii_letters + string.digits
    return "".join(random.choice(chars) for _ in range(length))


def md5_sign(params, secret):
    """参数按 key 升序拼 k=v&k=v，再拼秘钥 → md5（常见企业签名方式）。"""
    raw = "&".join(f"{k}={params[k]}" for k in sorted(params))
    return hashlib.md5(f"{raw}{secret}".encode("utf-8")).hexdigest()


def log_request(request):
    """hook：发请求前调用（用例里写 setup_hooks: - ${log_request($request)}）。"""
    print("即将请求：", request.get("method"), request.get("url"))
```

配套用例（覆盖上面四类用法，可直接跑）：

```yaml
config:
    name: debugtalk 用法演示
    base_url: ${base_url()}          # ① 地址来自 debugtalk 函数
    verify: false
    variables:
        ts: ${get_timestamp()}                    # ② 动态值
        trace_id: ${gen_random_string(8)}
        sign_params:                              # ③ 签名：复杂参数先在 variables 里备好
            path: /api/login
            ts: $ts
        sign: ${md5_sign($sign_params, ${ENV(APP_SECRET)})}

teststeps:
  - name: 带签名信息登录
    setup_hooks:
      - ${log_request($request)}                  # ④ hook
    request:
        url: /api/login
        method: POST
        headers:
            X-Trace-Id: $trace_id
            X-Sign: $sign
        json:
            username: admin
            password: ${ENV(PASSWORD)}
    validate:
        - eq: [status_code, 200]
        - eq: [body.code, 0]
```

配套 `.env`（和 `debugtalk.py` 同级）：`BASE_URL=http://127.0.0.1:8000`、`APP_SECRET=my-secret`、`PASSWORD=123456`。

**写它的四条纪律**：

1. **别放模块级副作用**（发请求、读大文件、打印一堆）——它会被 `importlib.reload`；
2. **顶层 import / 语法错** → 报 `error occurred in debugtalk.py: <类型>: <消息>`：**当前用例报错、其余用例继续跑**（不会把整轮拖死）；
3. **敏感信息不要硬编码**——用 `os.environ.get("XXX")`，值放 `.env`，用例里 `${ENV(NAME)}`；
4. **一个项目一份**，放项目根；父子目录都有时，框架从用例路径**就近**取（子项目自己的那份优先）。

### 4.5 命令清单 & 在哪个目录下跑（新手最容易错的一步）

**一条总纪律：先 `cd` 到「你想让产物出现的那个根目录」，再敲命令。**

**两组命令，其实是同一件事**：

| 你看到的写法 | 真身（等价） | 谁提供 |
| --- | --- | --- |
| `hrun` / `hmake` / `hconvert` | `interfacetester run` / `make` / `convert` | **内核包**（装了就有 `.exe`） |
| `haify` | `python -m interfacetester_ai` | **AI 旁路包**（★本机没装 exe，用 `-m` 写法） |

**在哪跑 / 产物落哪**（实测口径）：

| 命令 | 干什么 | 在哪跑 | 产物落点 |
| --- | --- | --- | --- |
| `hrun <用例或目录>` | 编译 + 真跑 | **任意目录都能跑**——RootDir 由**用例路径向上找 `debugtalk.py`** 决定，不由 cwd 决定；但**建议先 cd 到项目根** | `*_test.py` 紧挨 `.yml`；`logs/` 落在**项目里**（实测：人在 `D:\interface-tester` 跑别的项目的用例，日志仍写进那个项目）；而 `--html=reports/x.html` 这类**你自己写的相对路径**是相对**当前目录** |
| `hmake <用例>` | 只编译不运行 | 同上 | 同上（只多一个 `*_test.py`） |
| `hconvert --from X --in Y --out Z` | Postman/curl/HAR/OpenAPI → YAML | 任意目录 | 你 `--out` 指的目录（不写则 `./converted`，相对当前目录） |
| `python -m interfacetester_ai gen <文档.md>` | 接口文档 → 用例草稿 | ★**必须在工作根目录** | **只落 `.ai/draft/`**（进 `cases/` 要 `haify review --approve`）；另有 `.ai/{cache,manifest,failed,pending}/` |
| `… gen --assertions-only <文档.md>` | 只做确定性断言映射（**不调模型**） | ★同上 | 同上 |
| `… review --list` | 看 `.ai/draft/` 里有哪些草稿、缺什么 | ★同上 | 只读（实测：在仓库根列出 8 份；换到别的目录，要么报「找不到模块」、要么读到**那个目录自己的** `.ai/draft`） |
| `… review --approve <用例名> --approver <姓名>` | 草稿**转正** | ★同上 | `cases/<用例名>.yml` + `.ai/reviews/<用例名>.json`（留痕） |
| `… analyze <summary.json>` / `… summary <summary.json>` | 失败诊断 / 结果摘要 | ★同上（`reports/` 相对当前目录） | `reports/analysis.md` / `reports/summary.md` |
| `… fix <summary.json>` | 自愈建议（**只给 diff，不落地**） | ★同上 | **零写盘** |
| `… serve` / `… export` | 只读看板 / 离线静态导出 | ★同上 | `serve` 零写盘；`export` 写 `.ai/export/` |
| `… run <cases/xxx.yml>` | 过闸门后真跑（与看板同一个 Core） | ★同上（**只收 `cases/` 下的用例**） | `.ai/jobs/<job_id>/result.json` |

> ★ **为什么 AI 层必须 cd**：它的落点全是**裸相对路径**——源码里就是
> `open("cases/" + stem + ".yml")`、`.ai/draft/...`。**当前目录在哪，产物就在哪**；
> 在内核那边则是「RootDir 说了算」，两者规则不同，别混。

**本机实测的两条边界**（会直接卡住新手，先说清）：

1. `.venv\Scripts\haify.exe` **不存在** → 本机请一律用等价的 `python -m interfacetester_ai`；
2. `python -m interfacetester_ai` **只能在 `D:\interface-tester`（包所在目录）下**跑——在别的目录会报
   `No module named interfacetester_ai`。想在自己的用例工程里用，先装一次：
   `pip install -e interfacetester_ai`（AI 包**零三方依赖**；装完才有 `haify` 命令，也才能在任意目录跑——
   **但仍然要 cd 到工作根**）。

**别背命令，随时自取**（清单以 `--help` 为准，文档会过期）：

```powershell
hrun --help
python -m interfacetester_ai --help
python -m interfacetester_ai gen --help
python -m interfacetester_ai review --help
```

AI 层的**完整命令表 / 开关含义 / 退出码**见 [`docs/使用手册-AI协作层.md`](使用手册-AI协作层.md) §3
（本文不抄第二份——抄一份就多一个会过期的副本）。

**`hrun` 最常用的三个开关**：`--html=reports/x.html --self-contained-html`（单文件报告）、
`--save-tests`（落 `logs/**.summary.json`）、`-q`（少打印）。

## 五、五个新手必踩的坑（报错都是实测原文）

| # | 坑 | `hmake` 能不能替你抓到 |
| --- | --- | --- |
| 1 | **算子名写错**（如 `gte`、`lte`） | ✅ **能**：`FunctionNotFound: unknown assert comparator: gte`，并把全部合法算子列出来 |
| 2 | **漏写 `config.name`**（或 `step.name`） | ✅ **能**：`TestCaseFormatError ... config.name  Field required` |
| 3 | **忘写 `validate`**，或字段名拼错成 `validates` | ❌ **抓不到**：前者 `hmake` 仍然 exit 0；后者只 `WARNING ... 存在无法识别的字段：['validates']`，然后**真的忽略**。两种结果都是**用例是绿的、但什么都没测到** |
| 4 | `extract` 写成 list 形式 `- token: xxx` | ⚠️ **口径不统一**：`hmake`/`hrun` 收；`hconvert` 的「导出即验证」走严格校验，**只收 dict 形式**（实测报 `teststeps.0.extract  Input should be a valid dictionary`）。→ **统一写 dict 形式**，两条路都过 |
| 5 | **期望值类型写错**：`eq: [status_code, "200"]` | ⚠️ 编译期不报，**运行期失败**：失败信息里 `expect_value: 200(str)` —— 两侧都是字符串会按**字典序**比较 |

> 坑 3 是**最危险**的：它不是"用例写错"，而是"你以为在被守护，其实没有"。
> [`examples/quickstart/`](../examples/quickstart/README.md) 第五节专门放了一组**故意写错**的对照用例，
> 可以亲手跑一遍看「红了」与「假通过」各长什么样（默认被跳过，按 README 里的环境变量打开）。

## 六、自查脚本：把坑 3 这类「静默通过」堵上

**它是干什么的**：在 `hmake` 之外，补上框架**故意不管**的四件事——必填字段、字段名拼写、**零断言**、算子白名单。

**放哪**：放进**你自己的用例工程根目录**（和 `debugtalk.py` 同级）。
**不要**放进框架仓库（本仓库有写盘边界扫查，往包里加脚本会被判违规）。

```python
# check_case.py —— 用例工程的体检脚本（用法见文末）
import glob
import os
import sys

import yaml
from interfacetester.make import BUILTIN_COMPARATOR_NAMES, ensure_known_comparators
from interfacetester.models import KNOWN_CONFIG_FIELDS, KNOWN_REQUEST_FIELDS, KNOWN_STEP_FIELDS

TOP = {"config", "teststeps"}
problems = []
files = []
for p in sys.argv[1:] or ["."]:
    if os.path.isdir(p):
        files += sorted(glob.glob(os.path.join(p, "*.yml")) + glob.glob(os.path.join(p, "*.yaml")))
    else:
        files.append(p)

for f in files:
    with open(f, encoding="utf-8") as fp:
        data = yaml.safe_load(fp) or {}
    if not isinstance(data, dict):
        problems.append(f"{f}: 顶层不是映射")
        continue
    extra = sorted(set(data) - TOP)
    if extra:
        problems.append(f"{f}: 顶层只允许 config/teststeps，多出 {extra}")
    cfg = data.get("config") or {}
    if not cfg.get("name"):
        problems.append(f"{f}: config.name 必填（缺了直接报 TestCaseFormatError）")
    for k in sorted(set(cfg) - KNOWN_CONFIG_FIELDS):
        problems.append(f"{f}: config 里不认识的键 {k!r}（会被静默忽略）")
    steps = data.get("teststeps")
    if not isinstance(steps, list) or not steps:
        problems.append(f"{f}: teststeps 必须是非空列表")
        continue
    for i, s in enumerate(steps, 1):
        if not isinstance(s, dict):
            problems.append(f"{f}: teststeps[{i}] 不是映射")
            continue
        if not s.get("name"):
            problems.append(f"{f}: teststeps[{i}].name 必填")
        for k in sorted(set(s) - KNOWN_STEP_FIELDS):
            problems.append(f"{f}: teststeps[{i}] 不认识的键 {k!r}（会被忽略：断言名写错一个字母就静默变少）")
        for k in sorted(set(s.get("request") or {}) - KNOWN_REQUEST_FIELDS):
            problems.append(f"{f}: teststeps[{i}].request 不认识的键 {k!r}")
        # NOTICE：断言字段有两个名字——`validate`（YAML 惯用）与等价的 `validators`
        # （历史别名，`hmake` 认）。漏认后者会让**有断言的用例被误报成"零断言"**——
        # 假报会让真报被无视，所以这里两个都收。
        has_assertions = bool(s.get("validate") or s.get("validators") or s.get("extract"))
        if "request" in s and not has_assertions:
            problems.append(
                f"{f}: teststeps[{i}] {s.get('name')!r} 既没有 validate 也没有 extract "
                "→ 请求返回任何状态码都会算通过（假通过）"
            )
        try:
            ensure_known_comparators([s])
        except Exception as e:
            problems.append(f"{f}: teststeps[{i}] 断言算子有问题：{str(e).splitlines()[0]}")

if problems:
    print(f"\n共 {len(problems)} 处：")
    for p in problems:
        print("  x " + p)
    sys.exit(1)
print(f"OK：{len(files)} 个文件通过（必填字段 / 字段名 / 零断言 / 算子白名单）")
print(f"（内置算子 {len(BUILTIN_COMPARATOR_NAMES)} 个：{', '.join(sorted(BUILTIN_COMPARATOR_NAMES))}）")
```

```powershell
python check_case.py .              # 检查当前目录全部 .yml
python check_case.py cases\ login.yml
```

- **它查**：必填字段、各层字段名是否在白名单内、请求步骤有没有 `validate`/`extract`、算子名是否合法。
- **它不查**：断言**语义**对不对（那要人看）、`.env` 里的变量是否有值、接口是否真返回你期望的东西
  （这些只能靠 `hrun` 真跑 + 看报告）。
- 它**复用的是内核自己的常量**（`KNOWN_*_FIELDS` / `BUILTIN_COMPARATOR_NAMES` / `ensure_known_comparators`），
  所以框架新增字段或算子时它会自动跟上，不需要改脚本。
- 退出码：有问题 `1`，全通过 `0`（可以直接挂进 CI 或提交前钩子）。
- 脚本里的 `yaml` 是内核的**硬依赖**（PyYAML），随框架一起装好了，**不需要额外安装**；
  它**只读**用例文件、不写盘（写 `*_test.py` 的是 `hmake`）。

## 八、八条纪律与边界（踩了会白费力气）

1. **每个请求步骤都要有 `validate` 或 `extract`**——HTTP 4xx/5xx **不会自动判失败**，
   没有断言的步骤"请求返回 500 也算通过"（第五节坑 3）。
2. **用例放在你自己的用例工程里**（`debugtalk.py` + `.yml` 那一套），不要塞进**框架仓库**。
3. **`*_test.py` 是生成物，不要手改**——改了下次生成会被覆盖（或直接拒绝覆盖）；要改就改 `.yml`。
4. **期望值想清楚再写**：想不出来就写 `${ENV(TODO_<语义名>)}` 交人工确认（框架**没有** `??` 语法）；
   凭据/域名一律 `${ENV(名字)}`，明文只留在 `.env`，**别提交到代码仓库**。
5. **数字期望值写字面量**（`200` 而不是 `"200"`）；文档没写的事实**不要**顺手断言——那是臆造。
6. **危险操作**（上传 / 删除 / 打分 / 生产环境）先在测试环境跑；跑生产前先跟负责人确认。
7. **不在能力范围**：性能压测、WebSocket、gRPC、MQ（Kafka/RabbitMQ）、TCP/UDP、UI 自动化。
   （Thrift / SQL 有实验性支持，需要额外依赖，新手先别碰。）逐项见 [`docs/能力清单.md`](能力清单.md)。
8. **排查顺序**：终端逐项断言信息 → `logs/<case_id>.run.log` → `logs/*.summary.json`（`--save-tests` 时）→
   再怀疑接口。**先分清"用例写错了"和"接口真有问题"**。
