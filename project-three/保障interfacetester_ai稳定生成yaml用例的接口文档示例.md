# 保障 interfacetester_ai 稳定生成 YAML 用例的接口文档示例

> **这份文件有两个身份**：
> ① **写作规范**——照着改你的接口文档，工具就能稳定产出「能跑、能判、判得对」的 YAML 用例；
> ② **可运行示例**——本文件自己就是一份合格的接口文档，能过体检闸、能产断言（实测证据见 §7）。
>
> **配套**：口径唯一来源 `docs/使用手册-AI协作层.md`；判据来源是代码（下表每行都注明是哪个模块在哪判）。
> **适用版本**：本工作区当前状态（`interfacetester_ai` 已落地 §9.10~§9.15 的全部闸门）。

---

## 0. 三句话版本（时间不够只看这里）

1. **一节一个接口，标题直接写 `## POST /api/xxx`**（方法 + 路径都要有，**别只写「创建目录接口」**）。
2. **每个接口必备三件套**：一张**请求字段表**（`字段 | 类型 | 必填 | 说明`）+ 一个**标了「成功响应」的 JSON 示例** + **响应侧字段的出处**（响应说明句，或一张**没有「必填」列**的响应数据表）。
3. **期望值必须能从文档里逐字读出来**：枚举写全取值、范围写数字、固定值标「固定值」、状态码写 3 位数。**读不出来的就别写**——工具会明确告诉你「这里没断言」，而不是替你编一个。

---

## 1. 为什么这样写就稳：每条写作要求对应一个闸门

| # | 写作要求 | 谁在判（代码） | 不这么写的**可见后果** |
| --- | --- | --- | --- |
| 1 | 文件是 `.md` / `.txt`；**UTF-8 无 BOM**（GBK 也能读，BOM 只告警） | `cli.py` 的 `gen` 只收 `.md/.txt`；`doc_quality` D4 / `gates.gate_s11_document_encoding` | 坏编码 / 空文件 → **拒生成**（exit 4）；HTML 标签残留（`br` 标签、`nbsp` 实体）→ 告警 |
| 2 | **一节一个接口；节标题里「方法名」必须是标题的第一个词**：`## POST` 后面紧跟空格 + 路径；中文名**再隔一个空格**放到路径之后 | 两类判据：`gen.ENDPOINT_RE`（**严格版**：方法名在行首——决定"这一段算不算接口段"）；`slicer.ENDPOINT_RE`（宽松版，认得标题式 / 表格里写的 / curl 三种写法——决定"这片要不要送模型"） | ① 标题里编号挡在方法名前（如「`## 2.2` 打头」）→ **`--assertions-only` 报「没有识别到任何接口段」**、一条草稿都产不出（实测踩到）；② 中文名与路径**不隔空格** → 中文被并进 URL（实测产出 `url: /api/directory/create（创建目录）`，**跑起来 404**）；③ 只写中文接口名 → 该节被当**非接口片跳过**，报告点名「跳过 N 片」 |
| 3 | **一节的体积 ≤ 约 6.8 KB** | `slicer.effective_budget()`＝`8000 × (1−15%)` | 超了先按空行再切；仍超 → **报错不截断**（宁可让你拆文档） |
| 4 | 全篇必须有：**URL**、**HTTP method**、**至少一张字段表** | `doc_quality` 的 D1（文档级，**REJECT**） | exit 4 + `reports/NEEDS_DOC_FIX.md` 列出缺哪一项，**先改文档再生成** |
| 5 | 字段表表头必须是 markdown 表格（有 `---` 分隔行、每行列数一致） | `doc_quality._TABLE_ROW_RE/_SEPARATOR_ROW_RE`（`assertions` 复用同一套） | 列数不齐 → 告警「表格列数不齐，解析可能漏字段」；缺分隔行 → **整张表被忽略**。★**单元格里不要写竖线**（哪怕转义）——解析器按裸竖线切列，会把列数切乱 |
| 6 | 列头用**这四个语义**：`字段`/`参数`/`名称`/`name`/`key`/`property`、`类型`/`type`、`必填`/`是否`/`required`/`可选`、`说明`/`描述`/`备注`/`含义`/`**取值**`/`**允许值**`/`**约束**`/`desc`/`note` | `assertions._FIELD_COL_RE`、`_TYPE_COL_RE`、`_REQUIRED_COL_RE`、`_NOTE_COL_RE` | 列头换了词 → 那列当没有。★约束列写 `取值范围`/`允许值`/`约束` **都等价**（曾经只认 `说明`，同一句话在两种文档里一种产断言、一种不产，且**不报错**） |
| 7 | 「必填」列的值写成 **`是` / `否`**（或 yes/no/true/false/必填/必须/required/mandatory/1 与 否/n/no/false/可选/选填/optional/0） | `assertions._truthy_required` | 写 `-`、留空、写「看情况」→ 判为「**必填列没写清**」→ 该字段**一条断言都不产**（只记跳过原因） |
| 8 | 类型列写**可判定类型词**：`int/integer/long/float/double/number/decimal/string/str/char/text/bool/boolean/array/list/object/dict/map`、中文 `整数/数字/字符串/布尔/数组/列表/对象/文本` | `assertions._normalize_type` | `number`（int 还是 float？）**不猜** → 不产断言、进 unknowns；全篇可判定率 < 50% → 只建议出骨架 |
| 9 | **同一字段不许两种类型**；**示例里的值必须与字段表声明的类型一致**（含嵌套） | `doc_quality` 的 D2（**REJECT**） | 直接 exit 4。★典型踩坑：表里写 `errorCode: string`，示例里写 `"errorCode": null` → **判冲突**（`null` 不是字符串）→ 要么示例写 `""`，要么表里别声明该类 |
| 10 | **请求体表**首列写「字段」；**查询参数表**首列写「参数」；**请求头表**首列写「头」 | `assertions._PARAM_COL_RE`（首列命中 `参数/query/param` → 归 `params`） | 归 `params` 的字段**不是内核的断言对象**（内核只把响应侧当断言对象）→ 不产断言。这是**预期行为**（请求参数由请求保证，靠断言保证不了） |
| 11 | **成功响应**示例标「成功响应」/「正常」；**失败响应**示例标「失败响应」/「错误」 | `assertions.derive_from_response_examples`（`SUCCESS_HEAD_RE` / `FAILURE_HEAD_RE`） | 成功响应示例的**顶层 bool/null/数字**会成为 `equal` 断言（信封正面半）；**字符串只断类型**（文案会变）；**失败响应示例明确跳过**——它要靠非法请求才触发，塞进正常用例正是「跑不绿」的一大类 |
| 12 | **响应侧字段的三种出处**（择一或都写）：① 没有「必填」列的响应数据表 → 生成一条 `jsonschema_match`；② 响应说明句 `- \`data.total\`：整数，总条数` → 生成 `type_match`；③ 成功响应示例里的**键**（围栏前 200 字内有「响应/返回」）→ 让归属闸门放行 | `assertions.derive_from_response_tables` / `derive_from_response_notes` / `response_field_names`；`assembler.check_response_ownership`（§9.14） | **只在请求表里出现过的字段**（如 `path`）被断言成 `body.path` → **摘掉**（实测：文档「成功响应」写 `data: null` 时，这条断言必失败） |
| 13 | 期望值要**逐字**能从引用句读出来（同一句话里同时出现**字段**和**值/枚举**） | `assembler.check_field_in_quote` / `check_expect_in_quote`（T28 ①②） | 降级并进 `.ai/unknowns.json`：`field-not-in-quote` / `expect-not-in-quote`（"引用句只说『成功响应』"这种**空引用**最容易踩） |
| 14 | **示例值不许当期望值**，除非文档标了 `固定值` / `固定为` / `恒为` | `assembler.check_sample_value_hardcoded`（T28 ④） | 降级 `sample-value-hardcoded`（示例里的 `99.9` 是举例不是契约） |
| 15 | 状态码写成 **3 位数**（`成功返回 200`） | `assembler.check_status_code_conflict`（③）+ `doc_quality` 的 D1 可选要素 | 不写 → 告警「全篇未写状态码」；写了但断言写另一个 → **REJECT**（引用句里恰好一个状态码时才判，避免误报） |
| 16 | **枚举写全取值**（`枚举：fail / overwrite / rename`）、**范围写数字**（`1 ~ 64`、`从 1 开始`、`最多 100`） | `assertions.ENUM_RE/RANGE_RE/MIN_RE/MAX_RE` | 只写「枚举：见错误码表」→ **不产断言**（值没给全就不猜），只记「交人工补全取值」 |
| 17 | **条件返回**的字段（「仅当 … 时返回」「可能不返回」）**不要**写成必须存在 | `assertions.CONDITIONAL_RETURN_RE` | 不产断言（条件没建模，断言必然误报）。★**要断言它就做成独立场景**（见 §2.5：多步 + 带条件参数的请求） |

> **一句话记住**：工具的所有闸门都遵循同一条纪律——**能确定的确定下来，不能确定的响亮点名，判不了就不判**。
> 所以"文档写得越像契约，产出的用例越硬"；含糊处不会变成幻觉，只会变成 `.ai/pending/` 里的一条待办。

## 2. 完整示例（可直接复制，换成你的服务）

> 下面这份示例服务（目录 + 文件元数据 + 重命名）刻意覆盖了：必填/可选、枚举、范围、固定值、
> 条件返回、响应数据表、响应说明句、成功/失败响应、业务错误码、多步依赖。
> ★**下面每一节的标题都以「方法名」开头**（`## POST` 后面紧跟一个空格与 `/api/…`，中文名**再隔一个空格**）——
> 这是工具认端点的**硬形态**：编号与中文名可以放在**路径后面**，但**不能挡在方法名前面**，
> 也**必须与路径间隔空格**（否则中文会被当成 URL 的一部分，实测踩到过）。见 §1 第 2 行。

## 环境地址

写在文档里，生成时用 `--base-url` 显式指定其中一个（内核要求它是**字面量 URL**）：

- 开发环境：`http://127.0.0.1:8899`
- 测试环境：`http://test-file-api.example.com`

## 公共响应格式

所有接口的响应体统一为下面这个信封（**跨接口契约写在"公共"节里，归属闸门才会允许各接口引用它**）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| success | boolean | 是 | **固定值**：`true` 表示业务成功、`false` 表示业务失败 |
| errorCode | string | 是 | **固定值**：无错误时为空串 `""`；有错误时为错误码（见各接口的「失败响应」） |
| message | string | 是 | 提示文案。**易变，不要按值断言**（只断类型） |
| data | object | 是 | 业务数据容器，结构随接口而定 |

统一返回示例：

```json
{"success": true, "errorCode": "", "message": "操作成功", "data": {}}
```

> ★**这一节声明契约**（让各接口的 `body.success` / `body.errorCode` 等有据可依、归属闸门放行）；
> 但**每个接口节里仍要各写一份自己的成功响应示例**——断言是按「**节内**」归属的：
> 公共节里的表**不会**被塞进任何接口的用例（段外断言被丢弃并记入 `unknowns`）。

## POST /api/directory/create （创建目录）

创建目录；同名目录的处理方式由 `conflictPolicy` 决定。

#### 请求头

| 头 | 值 | 必填 | 说明 |
| --- | --- | --- | --- |
| Content-Type | `application/json` | 是 | 请求体是 JSON |
| X-Path | 与请求体的 `path` **完全相同** | 是 | 安全校验头，不一致服务端直接拒绝 |

> ★**首列写「头」**（不是「字段」）：这样它不会被当成请求体字段表，也就不会产出"断言请求头"这种取不到值的断言。

#### 请求体（JSON）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| path | string | 是 | 目录完整路径，长度 1 ~ 200 |
| name | string | 是 | 目录名，长度 1 ~ 64 |
| conflictPolicy | string | 是 | 同名目录已存在时的处理方式，**枚举**：`fail` / `overwrite` / `rename` |
| overwrite | boolean | 否 | **可选**（兼容保留字段，默认 `false`；只在 `conflictPolicy=overwrite` 时生效） |

请求体示例：

```json
{"path": "/app1/documents", "name": "reports", "conflictPolicy": "fail"}
```

#### 成功响应

```json
{"success": true, "errorCode": "", "message": "操作成功", "data": {"dirPath": "/app1/documents/reports", "dirName": "reports", "createdAt": "2026-06-15T14:30:00"}}
```

响应字段说明（**响应侧字段的出处**，`body.<字段>` 的归属就靠它）：

- `data.dirPath`：字符串，新目录的完整路径
- `data.dirName`：字符串，新目录名
- `data.createdAt`：字符串，创建时间（ISO 8601）

#### 失败响应

```json
{"success": false, "errorCode": "FILE_1018", "message": "安全校验头与路径不一致", "data": null}
```

#### 业务规则

- 请求头 `X-Path` 与请求体 `path` 不一致时：**失败响应**返回 `errorCode: FILE_1018`（HTTP 状态码仍为 `200`）
- `name` 为空串时：**失败响应**返回 `errorCode: FILE_4001`
- `conflictPolicy=fail` 且同名目录已存在时：**失败响应**返回 `errorCode: FILE_4002`

> ★成功返回 `200`、参数非法也返回 `200`（业务错误码在信封里）——**状态码要写全 3 位数**，
> 否则 `status_code` 断言只能进 unknowns。

## GET /api/file/metadata （查询文件元数据）

按逻辑路径 + 文件名查询单个文件的元数据。

#### 查询参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| path | string | 是 | 目录逻辑路径 |
| fileName | string | 是 | 文件名 |
| withTag | string | 否 | 传 `true` 时响应里才返回 `tag` 字段 |

> ★**首列写「参数」**：这些是 query 参数，内核不把请求参数当断言对象 → 工具**不会**给它们产断言（预期行为）。

#### 成功响应

```json
{"success": true, "errorCode": "", "message": "操作成功", "data": {"fileName": "report.pdf", "fileVersion": 3, "fileSize": 204800}}
```

#### 响应数据（`data` 的字段）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| fileName | string | 文件名 |
| fileVersion | integer | 版本号，从 1 开始 |
| fileSize | integer | 字节数 |
| tag | string | 仅当 `withTag=true` 时返回（条件返回的字段放在**这里**是安全的：这张表**没有「必填」列** → 生成的 schema **不写 required**，字段缺失不算失败） |

> ★这张表**没有**「必填」列 → 工具判定它是**响应数据表** → 生成**一条** `jsonschema_match` 覆盖整表
> （**不写 `required`**：字段缺失不算失败、存在但类型错才算）。裸字段名会被挂到 `data` 下
> （公共响应格式把 `data` 当业务数据容器）；若业务数据不在 `data` 下，请在表里写**全路径**（如 `result.total`）。

#### 失败响应

```json
{"success": false, "errorCode": "FILE_2003", "message": "文件不存在", "data": null}
```

#### 业务规则

- 文件不存在时：**失败响应**返回 `errorCode: FILE_2003`（HTTP 状态码 `200`）
- `withTag=true` 但文件无标签时：`tag` 字段不出现（**不是**错误）

## POST /api/file/rename （重命名文件）

重命名文件。

#### 请求体（JSON）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| path | string | 是 | 文件所在目录的逻辑路径 |
| sourceName | string | 是 | 原名 |
| targetName | string | 是 | 新名，长度 1 ~ 128 |
| overwrite | boolean | 否 | **可选**，默认 `false` |

#### 成功响应

```json
{"success": true, "errorCode": "", "message": "操作成功", "data": {"fromName": "report.pdf", "toName": "report-final.pdf", "renamedAt": "2026-06-15T14:35:00"}}
```

- `data.fromName`：字符串，重命名前的文件名
- `data.toName`：字符串，重命名后的文件名
- `data.renamedAt`：字符串，重命名时间（ISO 8601）

#### 失败响应

```json
{"success": false, "errorCode": "FILE_4015", "message": "目标文件已存在", "data": null}
```

#### 业务规则

- 原名不存在时：**失败响应**返回 `errorCode: FILE_4013`
- 新名与原名相同：**失败响应**返回 `errorCode: FILE_4014`
- 目标文件已存在且 `overwrite=false`：**失败响应**返回 `errorCode: FILE_4015`

## 跨接口的调用顺序（多步依赖怎么写）

> ★**这一节刻意不写「方法 + 路径」**：它只是流程说明，不产用例——写了端点形态，工具会把它当成一个"接口片"去生成。
> 依赖关系的写法是**引用接口名 + 点名取哪个字段**——模型会把上一步的返回值 `extract` 出来供下一步用。

1. 先调**创建目录**接口（上文那节），成功后从响应里取 `data.dirPath` 作为后续请求的 `path`；
2. 再调**查询文件元数据**接口（`path` 用第 1 步取到的值、`fileName` 用测试数据里的文件名），
   取 `data.fileVersion` 记录当前版本号；
3. 最后调**重命名文件**接口（`path` 同上、`sourceName` 用第 2 步的文件名）；
   重命名成功后第 2 步查到的 `fileVersion` 会 +1（可用它做跨步骤的一致性校验）。

> ★**条件场景（要用到「仅当 … 时」的字段）**：把它写成**独立的一节**（自己的 `## 方法 路径`），
> 在那一节里把条件参数写进请求表/查询参数表，并明确写"本场景 `withTag=true`"——
> 这样"条件返回的字段"在**该场景下**才被断言，而不是在正常路径上无条件断言（后者必然误报）。

## 3. 反面写法对照表（全部是实测或代码判据，不是"建议"）

| # | ❌ 这样写 | 会发生什么 | ✅ 改成 |
| --- | --- | --- | --- |
| 1 | 标题 `## 2.2 POST /api/x`（编号挡在方法名前） | 接口段识别变少（实测 3 → 2）；结构再乱一点就是 0，CLI 报「**没有识别到任何接口段**」 | `## POST /api/x` （2.2 创建目录）——**方法名在标题最前** |
| 2 | 标题 `## POST /api/x（创建目录）`（中文紧贴路径，中间无空格） | 中文被并进 URL：实测产出 `url: /api/directory/create（创建目录）` → **跑起来 404** | 中文名与路径**隔一个空格**：`## POST /api/x （创建目录）` |
| 3 | 表格单元格里写竖线（哪怕转义） | 解析器按**裸竖线**切列 → 列数不齐告警「解析可能漏字段」，严重时整表读不到 | 单元格里用文字描述，或拆成两列 |
| 4 | 表里 `errorCode: string`，示例里 `"errorCode": null` | D2 判「示例值与字段表冲突」→ **拒整份文档**（exit 4） | 示例写 `""`（无错误为空串），或表里不声明该字段的类型 |
| 5 | 响应其实是数组，却把**元素字段**平铺进响应数据表（`sku` / `price` …） | schema 变成「期望 `data` 是 object、实际是 array」→ **必红**（实测 T4_1/T5_2 两条） | 只声明**外层容器**（如 `records: array`）；元素字段改用**成功响应示例**或**响应说明句**表达 |
| 6 | 请求表里的字段名与响应里某字段的**末段同名**（都叫 `dirPath`） | 产出一条取错层级的断言 `type_match: [body.dirPath, str]`（响应里其实在 `body.data.dirPath`）→ **必红**。★**工具侧已修**（§9.32）：归属**按路径**判 → 这条会被**摘掉并点名**「层级取错了：…在 `data.dirPath`」，不再进产物 | 换名（请求用 `path`、响应用 `dirPath`），或让响应侧字段名与请求侧不重名 |
| 7 | 把示例里的值当契约：`type_match: [body.message, "操作成功"]` | T28 ④ 降级 `sample-value-hardcoded`（示例是举例，不是契约） | 文档标「**固定值**」再用；否则只断类型或交人工 |
| 8 | `string_equals: [body, "true"]` / `contains: [body, '"success": true']` / `string_equals: [body.success, true]` | 三条都**永远不可能成立**（整包是对象；`)` 对字典找的是键/元素；`string_equals` 只吃字符串）→ 分别被 §9.15 闸门摘掉 | 整包用 `type_match: [body, dict]` 或 `jsonschema_match`；字段用 `equal: [body.success, true]` |
| 9 | 说明列写「枚举：见错误码表」 | 值没给全 → **不产断言**，只记「交人工补全取值」 | 写全：`枚举：fail / overwrite / rename` |
| 10 | 真可选字段在「必填」列写「是」 | 断言它必然存在/是某类型 → 该字段不返回时**误报失败**（把文档的条件变成"我们的假缺陷"） | 写「否」；条件返回（「仅当…时返回」）的字段放**无必填列的响应数据表**里 |
| 11 | 把「仅当 `withTag=true` 时返回」的字段写进**有必填列**的表 | 条件返回不产断言（设计如此：条件没建模，断言必然误报） | ① 放进**无必填列**的响应数据表（schema 不写 required，缺失不算失败）；② 或单列一个**条件场景节**并在该节请求里带上条件参数 |
| 12 | 依赖说明节里写「方法 + 路径」 | 该节被当成接口片去生成用例（它其实只是流程说明） | 只写**接口名 + 取哪个字段**（「先调创建目录接口，取 `data.dirPath`」） |
| 13 | 只写「成功返回 200」在别的地方，接口节里不写状态码 | 告警「全篇未写状态码」；`status_code` 断言只能进 unknowns | 每个接口节里写明「成功返回 `200`，参数错返回 `400`」（**3 位数字**） |
| 14 | 一份文档里把多个接口塞进同一节 | 只能出一份草稿；归属窗口混在一起 | **一节一个接口**（一节 ≤ 约 6.8 KB，超了按空行再切或拆文档） |
| 15 | 请求头表首列写「字段」 | 被当成请求体字段表 → 产出「断言请求头」这种取不到值的断言（或噪音降级） | 首列写「**头**」（`字段`/`参数`/`头` 三种首列分别对应 body / query / 跳过） |

## 5. 这份写法也管不到的地方（诚实清单）

1. **只收 `.md` / `.txt`**：PDF / Word / Confluence 导出页 / Excel 要先转成带 markdown 表格的 markdown。
2. **确定性通路不写请求参数**：`--assertions-only` 出的产物 `request` 里只有 `method` + `url`（已知缺口），
   `json` / `params` 需要人工补，或改用模型通路（`haify gen`，模型会按请求表把参数写进 `json`/`params`）。
3. **请求头断言**：确定性通路不产（请求头是**发出去**的，不是断言对象）——要断"服务端收到了什么"请人工写，
   或让模型补；**响应头**则可以在文档里写一张**响应头表**（见 §2「三张表怎么起头」）。
4. **数组元素字段**：确定性 schema 表达不了"数组元素的类型"——所以别平铺（见 §3 第 5 行）。
5. **负例（业务错误码）**：失败响应示例只会被**明确跳过**（"要靠非法请求才触发，负例该单列用例"），
   自动断言错误码要靠模型拆独立 step，或人工补。
6. **跨接口依赖**：确定性通路不产多步用例（单接口一段）；多步依赖要靠模型通路 + 文档里的调用顺序说明。
7. **纯文本 / 二进制响应**（下载类）：要在接口节里写明（`Content-Type: application/octet-stream`、`Body: 文件二进制流`），
   否则"整包按字符串断言"这类写法会被语义闸门摘掉。
8. **判据是正则级的**：非 markdown 表格（HTML 粘贴、制表符分隔）、极端排版会读不到——
   先把表规整成标准 markdown 表格。
9. **模型通路还要看预算**：单次输入预算 8000 字节（切片留 15% 余量 → 一节约 ≤6.8KB）；一节太大就拆。
10. **模型是非确定性的**：同一份文档两次跑结果可能不同（"温度 0"不等于可复现）——所以**判定永远在内核**，
    草稿必须人工转正。

## 附：一页速查（建议贴到你自己的文档模板最上面）

**标题与结构**

- 一节一个接口；接口节用**顶层**节；标题**以方法名开头**，中文名隔空格放在后面（`##` + `POST` + 空格 + 路径 + 空格 + 中文名）
- 接口节内的子标题顺序：请求头 → 请求体 → 成功响应 → 失败响应 → 业务规则
- 依赖/流程说明**单独成节**，且**不要**写端点形态（只写"先调哪个接口、取哪个字段"）

**三张表怎么起头**

- 请求头表：首列写「头」；查询参数表：首列写「参数」；请求体表：首列写「字段」
- **响应 Cookie 表**：首列写「Cookie」（或 `Set-Cookie`），**不要写「必填」列**；行里给
  「值」列 + 说明列 —— 说明列标「**固定值**」→ 产 `equal: [cookies.<名>, <值>]`；
  写「**取值：A / B**」→ 产 `contained_by`；**两样都没写 → 不产断言、只点名**（不会替你编）
- **响应 Cookie 的"必带"**：另开一列「**必带**」（或说明里写「必带」）且值为「是」→ 产
  `jsonschema_match: [cookies, {required: [...]}]`（服务端不给就是**文档被违反** ✓）；
  ★**别用「必填」**——那个词是**请求侧**的判据（带「必填」列的表会被当成请求表，方向就反了）
- 请求头的**取值来源**（按优先级）：① 本节 curl 示例里的 `-H`；② 头表的「**值**」列；
  ③ 都没有 → 工具写 `${ENV(TODO_<头名>)}` 并在 `unknowns` 里点名（**不静默丢头**）；
  ④ 名字像凭据的（`Authorization` / `token` / `Cookie` …）**只写** `${ENV(名字)}`，**不抄**文档里的示例值；
  并在 `unknowns` 里**告诉你填哪个环境变量、值从哪来**（引用该行「说明」列原文 + 指向文档里讲认证的那一节）
- 响应数据表：**不要写「必填」列**（这是"它是响应表"的判据）；裸字段名会挂到 `data` 下
- **响应头表**：首列写「头」（或 `header`），**不要写「必填」列**（带「必填」的表是**请求头**表，方向就反了），
  且**这张表附近要出现过"响应/返回"字样**（放在「响应」小节里、或写一句"响应头如下"）；
  给「值」列 + 说明列 —— 说明列标「**固定值**」→ 产 `equal: [headers.<名>, <值>]`；
  写「**取值：A / B**」→ 产 `contained_by`；**两样都没写 → 不产断言、只点名**
  （`Date` / `X-Request-Id` 这类值本来就易变，"断言它是字符串"永远为真、没有意义）
- **响应侧的「必带」**（服务端一定会给）另开一列「**必带**」（或说明里写「必带」）→ 产
  `required`，**挂在文档说的那一层容器**上（裸名 → `data` 层）；
  ★别用「必填」（那是**请求侧**）；同一行既标必带又写「仅当…时返回」会被判**矛盾** → 不产、点名

**值怎么写才判得动**

- 必填列只写 `是` / `否`；类型只写可判定词（`string` / `integer` / `boolean` / `array` / `object` …）
- 枚举写全取值、范围写数字、状态码写 3 位数、固定值标「固定值」
- 每个接口都要有自己的**成功响应示例**（断言按"节内"归属）

**别写（会被摘掉/降级/拒）**

- 整包跟字符串比、JSON 片段当期望值、`string_equals` 配布尔
- 数组元素平铺进响应数据表、请求字段名与响应字段末段撞名
- 标题里编号挡在方法名前、中文名紧贴路径
- 可选或条件返回的字段放进"必填"列
