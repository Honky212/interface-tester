# 统一文件服务平台 - 接入应用接口文档

**文档版本**: v1.1  
**最后更新**: 2026-07-20

## 1. 接口概述

本文档描述统一文件服务平台对外开放给接入应用的 RESTful API 接口，包含目录服务、文件服务、元数据服务和版本服务四大类接口。

### 1.1 服务地址

| 环境 | 基础URL                          |
|-----|--------------------------------|
| 开发环境 | `https://localhost:8080`       |
| 测试环境 | `https://unifsptst.cernet.com` |
| 生产环境 | `https://unifsp.cernet.com`    |

### 1.2 认证方式

所有接口均需通过 **OAuth2.0 Client Credentials** 模式进行认证。

**获取 Access Token**:

```bash
POST /oauth2/token
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials
&client_id={your_client_id}
&client_secret={your_client_secret}
```

**响应示例**:
```json
{
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "token_type": "Bearer",
    "expires_in": 3600
}
```

**使用方式**: 在请求头中携带 `Authorization: Bearer {access_token}`

### 1.3 公共请求头

| 头名称 | 必填 | 说明 | 示例值 |
|-------|-----|------|-------|
| `Authorization` | 是 | OAuth2.0 Bearer Token | `Bearer eyJhbGciOi...` |
| `X-Path` | 是 | 请求路径，用于权限校验 | `/app1/documents/` |

> **注意**: `X-Path` 值必须与请求参数中的 `path` 字段完全一致，否则会返回 `FILE_1018` 错误。唯一例外是 **创建目录** 接口，其 `path`（新目录路径）只需以 `X-Path` 开头即可（`X-Path` 为父目录路径）。

### 1.4 统一响应格式

所有接口统一使用 `FileResult` 作为响应体。

#### 成功响应
```json
{
    "success": true,
    "errorCode": null,
    "message": "操作成功",
    "data": { /* 返回数据 */ }
}
```

#### 失败响应
```json
{
    "success": false,
    "errorCode": "FILE_XXXX",
    "message": "错误描述信息",
    "data": null
}
```

**响应字段说明**:

| 字段名 | 类型 | 说明 |
|-------|------|------|
| `success` | Boolean | 操作是否成功 |
| `errorCode` | String | 业务错误码，成功时为 `null` |
| `message` | String | 操作结果消息 |
| `data` | Object | 返回的业务数据，失败时为 `null` |

### 1.5 常见错误码

| 错误码 | 错误信息 | 说明 |
|-------|---------|------|
| `FILE_1001` | 文件列表不能为空 | 上传文件列表为空 |
| `FILE_1007` | 版本ID不能为空 | 版本回滚/查询时未传版本号 |
| `FILE_1008` | 版本不能为空 | 版本参数缺失 |
| `FILE_1010` | 目录路径不能为空 | 路径参数缺失 |
| `FILE_1016` | 最多上传10个文件 | 上传文件数量超限 |
| `FILE_1018` | 路径与Header不一致 | X-Path 校验失败 |
| `FILE_1020` | Header格式错误 | X-Path 格式不规范 |
| `FILE_1021` | 上传文件大小超过限制 | 单文件超过 50MB |
| `FILE_1023` | 部分文件上传失败 | 上传存在部分成功部分失败 |
| `FILE_2001` | 目录不存在 | 指定的目录不存在 |
| `FILE_2003` | 文件不存在 | 指定的文件不存在 |
| `FILE_2005` | 目标版本不存在 | 指定的版本记录不存在 |
| `FILE_4001` | 目录名称必须以/开头并以/结尾 | 路径格式错误 |
| `FILE_4003` | 目录名称不能包含连续的/ | 路径格式错误 |
| `FILE_4012` | 目录下有文件，不能删除 | 删除非空目录 |
| `FILE_4015` | 同一目录下已存在同名文件 | 重命名时文件名冲突 |
| `FILE_4016` | 文件名包含非法字符 | 文件名包含 \/:*?"<>| 等特殊字符 |
| `FILE_4018` | 文件名开头和结尾不能有空格 | 文件名首尾存在空格 |
| `FILE_5001` | 目标版本已是当前版本，无需回滚 | 版本回滚时目标版本即当前版本 |
| `FILE_6004` | 文件存储操作异常 | 服务器内部错误 |
| `FILE_8002` | 开始时间不能大于结束时间 | 元数据查询时间范围无效 |

## 2. 目录服务接口

### 2.1 创建目录

**接口描述**: 创建新的目录

**请求信息**:

| 属性 | 值 |
|-----|-----|
| **URL** | `POST /api/directory/create` |
| **所属文件** | `DirectoryController.java` |

**请求头**:

| 头名称 | 必填 | 示例值 |
|-------|-----|-------|
| `Authorization` | 是 | `Bearer eyJhbGciOi...` |
| `X-Path` | 是 | `/app1/` |

**请求参数** (JSON):

| 字段名 | 类型 | 必填 | 说明 | 示例值 |
|-------|------|-----|------|-------|
| `path` | String | 是 | 新目录的完整路径 | `/app1/documents/reports/` |

**路径格式要求**:
- 必须以 `/` 开头
- 必须以 `/` 结尾
- 不能包含连续的 `//`
- 不能等于 `/`
- 目录名称开头和结尾不能有空格（`FILE_4018`）
- 新目录路径必须以请求头 `X-Path` 中的路径开头

**成功响应**:

```json
{
    "success": true,
    "errorCode": null,
    "message": "操作成功",
    "data": null
}
```

**失败响应**:

```json
{
    "success": false,
    "errorCode": "FILE_4001",
    "message": "目录名称必须以/开头并以/结尾",
    "data": null
}
```

**调用示例**:

```bash
curl -X POST https://unifsp.cernet.com/api/directory/create \
  -H "Authorization: Bearer eyJhbGciOi..." \
  -H "X-Path: /app1/" \
  -H "Content-Type: application/json" \
  -d '{"path": "/app1/documents/reports/"}'
```

| `createTime` | String | 创建时间 |

## 3. 文件服务接口

### 3.1 文件上传

**接口描述**: 上传一个或多个文件到指定目录

**请求信息**:

| 属性 | 值 |
|-----|-----|
| **URL** | `POST /api/file/upload` |
| **所属文件** | `FileController.java` |

**请求头**:

| 头名称 | 必填 | 示例值 |
|-------|-----|-------|
| `Authorization` | 是 | `Bearer eyJhbGciOi...` |
| `X-Path` | 是 | `/app1/documents/` |
| `Content-Type` | 是 | `multipart/form-data` |

**请求参数**:

| 字段名 | 类型 | 必填 | 说明 | 示例值 |
|-------|------|-----|------|-------|
| `path` | String | 是 | 目标目录路径 | `/app1/documents/` |
| `files` | MultipartFile[] | 是 | 文件数组（最多10个） | - |

**业务规则**:
- 单次最多上传 **10个** 文件
- 单个文件最大 **50MB**
- 文件名不能包含特殊字符：`\/:*?"<>|`（`FILE_4016`）
- 文件名开头和结尾不能有空格（`FILE_4018`），文件名中间允许空格
- 仅支持白名单内的文件后缀
- 同名文件会自动覆盖并创建新版本

**支持的文件类型**:
- 文档类：pdf, doc, docx, xls, xlsx, ppt, pptx, txt
- 图片类：jpg, jpeg, png, gif, bmp
- 压缩类：zip, rar, 7z

**成功响应**:

```json
{
    "success": true,
    "errorCode": null,
    "message": "操作成功",
    "data": {
        "success": ["report.pdf", "data.xlsx"],
        "fail": []
    }
}
```

**部分失败响应**:

```json
{
    "success": false,
    "errorCode": "FILE_1023",
    "message": "部分文件上传失败",
    "data": {
        "success": ["report.pdf"],
        "fail": ["large.zip → 文件超过 50MB"]
    }
}
```

**调用示例**:

```bash
curl -X POST https://unifsp.cernet.com/api/file/upload \
  -H "Authorization: Bearer eyJhbGciOi..." \
  -H "X-Path: /app1/documents/" \
  -F "path=/app1/documents/" \
  -F "files=@report.pdf" \
  -F "files=@data.xlsx"
```

### 3.5 文件重命名

**接口描述**: 修改文件名

**请求信息**:

| 属性 | 值 |
|-----|-----|
| **URL** | `POST /api/metadata/rename` |
| **所属文件** | `MetadataController.java` |

**请求头**:

| 头名称 | 必填 | 示例值 |
|-------|-----|-------|
| `Authorization` | 是 | `Bearer eyJhbGciOi...` |

**请求参数** (JSON):

| 字段名 | 类型 | 必填 | 说明 | 示例值 |
|-------|------|-----|------|-------|
| `path` | String | 是 | 文件所在目录路径 | `/app1/documents/` |
| `oldFileName` | String | 是 | 原文件名 | `report_old.pdf` |
| `newFileName` | String | 是 | 新文件名 | `report_new.pdf` |

**业务规则**:
- 原文件名不能为空
- 新文件名不能与原文件名相同（`FILE_4013`）
- 新文件后缀必须与原文件保持一致，不允许修改扩展名（`FILE_4014`）
- 新文件名不能包含非法字符：`\/:*?"<>|`（`FILE_4016`）
- 新文件名开头和结尾不能有空格（`FILE_4018`），文件名中间允许空格
- 同一目录下不能重命名为已存在的文件名（`FILE_4015`）

**成功响应**:

```json
{
    "success": true,
    "errorCode": null,
    "message": "操作成功",
    "data": null
}
```

**失败响应**:

```json
{
    "success": false,
    "errorCode": "FILE_4015",
    "message": "同一目录下已存在同名文件",
    "data": null
}
```

**调用示例**:

```bash
curl -X POST https://unifsp.cernet.com/api/metadata/rename \
  -H "Authorization: Bearer eyJhbGciOi..." \
  -H "X-Path: /app1/documents/" \
  -H "Content-Type: application/json" \
  -d '{
    "path": "/app1/documents/",
    "oldFileName": "report_old.pdf",
    "newFileName": "report_new.pdf"
  }'
```

### 4.1 获取版本列表

**接口描述**: 根据目录路径和文件名获取该文件的所有历史版本列表（精简信息）

**请求信息**:

| 属性 | 值 |
|-----|-----|
| **URL** | `GET /api/version/getList` |
| **所属文件** | `VersionController.java` |

**请求头**:

| 头名称 | 必填 | 示例值 |
|-------|-----|-------|
| `Authorization` | 是 | `Bearer eyJhbGciOi...` |
| `X-Path` | 是 | `/app1/documents/` |

**请求参数** (Query String):

| 字段名 | 类型 | 必填 | 说明 | 示例值 |
|-------|------|-----|------|-------|

### 4.3 版本回滚

**接口描述**: 将指定文件回滚到某个历史版本，该历史版本将成为新的当前版本

**请求信息**:

| 属性 | 值 |
|-----|-----|
| **URL** | `POST /api/version/rollback` |
| **所属文件** | `VersionController.java` |

**请求头**:

| 头名称 | 必填 | 示例值 |
|-------|-----|-------|
| `Authorization` | 是 | `Bearer eyJhbGciOi...` |
| `X-Path` | 是 | `/app1/documents/` |

**请求参数** (JSON):

| 字段名 | 类型 | 必填 | 说明 | 示例值 |
|-------|------|-----|------|-------|
| `path` | String | 是 | 文件所在目录逻辑路径 | `/app1/documents/` |
| `filename` | String | 是 | 文件名 | `report.pdf` |
| `version` | String | 是 | 要回滚到的目标版本号 | `v2` |

**业务规则**:
- `path` 必须与请求头 `X-Path` 完全一致，否则返回 `FILE_1018`
- 若目标版本已是当前版本，返回 `FILE_5001`
- 回滚成功后，原目标版本会被置为当前版本，原当前版本转为历史版本
- 回滚操作会基于目标版本内容生成新版本记录

**成功响应**:

```json
{
    "success": true,
    "errorCode": null,
    "message": "操作成功",
    "data": null
}
```

**失败响应**:

```json
{
    "success": false,
    "errorCode": "FILE_5001",
    "message": "目标版本已是当前版本，无需回滚",
    "data": null
}
```

**调用示例**:

```bash
curl -X POST https://unifsp.cernet.com/api/version/rollback \
  -H "Authorization: Bearer eyJhbGciOi..." \
  -H "X-Path: /app1/documents/" \
  -H "Content-Type: application/json" \
  -d '{
    "path": "/app1/documents/",
    "filename": "report.pdf",
    "version": "v2"
}'
```

### 6.1 请求路径格式规范

所有路径参数必须遵循以下格式：

```
/{application_id}/{directory_name}/[sub_directory_name/]
```

**正确示例**:

- `app1/documents` （缺少开头斜杠）
- `/app1/documents` （缺少结尾斜杠）
- `/app1//documents/` （包含连续斜杠）

### 6.3 常见问题

**Q1: X-Path 是什么？为什么需要它？**

A: `X-Path` 是一个安全校验头，用于验证请求的路径与实际操作的路径是否一致，防止越权访问。请求头中的 `X-Path` 必须与请求参数中的 `path` 字段完全相同。

**Q2: 预览链接为什么有时效和次数限制？**

A: 预览链接是临时访问凭证，设置时效（2小时）和次数（3次）限制是为了安全性考虑，防止链接泄露后被滥用。

**Q3: 上传同名文件会发生什么？**

A: 系统会自动覆盖原文件，并创建历史版本记录，原文件内容可以通过版本管理接口找回。

**Q4: getList 与 getInfolist 接口有何区别？**

A: `getList` 返回精简的版本信息（版本号、大小、MD5、生成时间），适合前端列表展示；`getInfolist` 额外返回文件名、后缀、所属目录等详细信息，适合需要展示文件/目录上下文的场景。

**Q5: 版本回滚后，原当前版本会丢失吗？**

A: 不会。回滚操作不会删除原当前版本，而是将目标历史版本的内容置为新的当前版本，原当前版本转为历史版本，仍可通过版本列表接口查询和再次回滚。

**Q6: 元数据查询接口 list、query、queryPage 有何区别？**

A: 三者区别如下：
- `list`：仅查询当前目录下的文件，不含子目录，返回脱敏 VO
- `query`：递归查询当前目录及所有子目录，返回脱敏 VO 并额外携带 `dirPath`（文件所在目录路径）
- `queryPage`：递归查询并支持分页，返回 MyBatis-Plus `IPage` 结构，`records` 为 `FileMetadataVo` 对象（含 `dirPath`）
