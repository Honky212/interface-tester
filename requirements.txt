# pytest-randomly：随机化用例执行顺序 → 暴露「顺序依赖」。
#   本仓已两次出现这类缺陷，且都只在整仓一起跑时现形（`sub`/`projB3` 裸包名
#   留在 sys.modules、其 __path__ 钉在随后被 rmtree 的临时目录上 → ModuleNotFoundError）；
#   默认（固定）顺序下**永远不暴露**，会表现为"时红时绿"的假抽风。
#   用法：装了就默认生效（每次会打印 seed）；复现某次：--randomly-seed=<seed>；
#         定位问题时关掉它：-p no:randomly。
#   NOTICE: README「六、测试与质量」的基线数字是在**默认顺序**下测的。
#   随机顺序可能让原本侥幸通过的用例变红 —— 那不是回归，是它终于暴露了。
# pytest-xdist：并行跑（-n auto），约 90s → 十几秒，让"改一行跑全量"在本地可行。
#   NOTICE: 并行时每个 worker 是独立进程，**不会**互相污染，但也会**掩盖**
#   只在同一进程内才暴露的顺序缺陷。所以并行用于快速回归，
#   判断顺序问题时请用单进程（或加 --randomly）跑。
# NOTICE: 这三个都是 `==` 锁定形态（S4 判据），离线部署可 pip download 带走。
