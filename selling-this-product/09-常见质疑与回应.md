# 常见质疑与回应（销售/汇报时的标准答法）

> **用法**：被问到就翻到这里，每条都是「先承认边界 → 再给证据」。**空口承诺最伤信任，这个项目的底气恰好是"每条结论都有依据"。**

---

### Q1：「又是一个测试框架？我们已经够多了。」

**不是新框架，是 HttpRunner v4.3.5 的二次开发分支**——写法兼容，你原来的 YAML 经验直接可用。差异化只有一句话：**别的框架解决"能跑"，它额外解决"跑绿了到底测没测到"**（57 条防线逐条登记，见 `docs/架构与调用链.md` §七）。

### Q2：「开源吗？能商用吗？」

内核 `interfacetester` 是 **Apache-2.0**，附 `LICENSE` + `NOTICE`（合规要求：保留声明、注明衍生自 HttpRunner v4.3.5）。**不暗示与上游有官方背书或商标授权关系**。AI 包是独立发行的旁路包，零三方依赖。

### Q3：「我们已经有 Postman 集合了，用不着吧？」

Postman 的痛点是**进 CI 卡、用例没法评审**。我们的答法不是"换掉它"，而是：**`hconvert --from postman` 把集合导成标准 YAML**，走同一套内核；同时它不会假装成功——**迁移不了的写法会逐条告警并给报告**（`--report`）。

### Q4：「AI 写用例？它瞎编怎么办？」

三条结构性保险（**不是靠"记得检查"**）：
1. **每条断言必须带 `source_quote`**，且引用句要**逐字**出现在文档里，否则**降级并记账**（`unknowns` 可见）；
2. **有不确定值（`TODO_`）的草稿只许落 `.ai/draft/`**，**进不了 `cases/`**；
3. **转正要人工点名处置 blocker**，留痕含**内容哈希**——改一行就失效。

> 实测口径可引用：真实客户文档上的引用降级率 40%（golden 文档 0%）——**我们把它报出来，而不是藏起来**。

### Q5：「AI 要联网吗？我们在内网。」

**不联网也能用**：
- 完全离线的确定性通路：`python -m interfacetester_ai gen 文档.md --assertions-only`（**不调模型**、结果可复现）；
- 要用模型就指向**本地 Ollama**（回环地址**免 API key**）；
- **没配就绝不出网**：退出码 2 + 打印配置指引；真出网还要显式开 `INTERFACETESTER_AI_SANDBOX=on`（非回环还得列白名单 `_ALLOW_HOST`）。**拒绝是响亮的，不静默降级。**

### Q6：「会不会把我的接口文档/凭据传出去？」

- AI 层**不读项目 `.env`**（那是被测项目的环境变量来源）；工具配置只从**环境变量**取，**凭据不落文件、不被用例读到**；
- 调用留痕落 `.ai/manifest/`（**原始响应照录**，便于幻觉复盘），落点全部在项目内的 `.ai/`；
- 产物与日志里，`Authorization`/`password`/`token`/`Cookie`/URL userinfo 统一 `******`（**请求侧 + 响应侧**都覆盖）。

### Q7：「谁维护？会不会写完就没人管？」

可运维性写在仓库里：
- **2545 条机器判据**（2026-09-27 本机全量，0 failed）；
- **元护栏**：文档是否覆盖每个模块、退出码表与代码常量是否一致、探针是否都被例行任务收录……都有自动化判据；
- **注入验证**留痕：把修复注掉，护栏必须立刻变红（连"护栏自己打偏"的两次失误都记录在案）；
- **回滚成本极低**：AI 层 `pip uninstall` 即回滚；内核 `git revert`。

### Q8：「团队要学多久？」

- 测试同学：**会写 YAML 就会用**（字段名只有 `config` / `teststeps` / `request` / `extract` / `validate`）；
- 开发同学：`debugtalk.py` 里写函数（签名/加密/造数/自定义算子）；
- 仓库里有**从零搭 6 步教程**、**最小可运行示例**、**零基础版说明**（`docs/使用说明-非技术版.md`，全文不含要敲的代码）。

### Q9：「能测 SOAP 老系统吗？」

能，而且是**两套方案**：
- **内核算子**：`xpath_match` / `xpath_count`（完整 XPath 1.0）、`xml_schema_match`（XSD 契约，支持 `xs:include`，报错给节点路径）——需装 extra `.[xml]`；
- **零依赖退路**：项目级算子（`examples/soap/debugtalk.py` 可直接复制），**装不了二进制 wheel 的内网也能用**。

### Q10：「能测数据库吗？」

内置 `RunSqlRequest`（**仅 MySQL**，需 extra `.[sql]`），用来验证"接口写完是否真的落库"。其他数据源（Redis/Mongo 等）在 `debugtalk.py` 里引库查询 + `validate` 断言返回值即可。

### Q11：「支持压测/并发吗？」

**不支持，也不打算做**——性能压测请用 JMeter/k6/Locust。**并发治理、测试数据管理、报告聚合**按设计属框架之外。我们宁可说清楚，也不做成半成品。

### Q12：「AI 生成的用例能直接进 CI 吗？」

**不能，而且这是设计目标**：草稿必须过 `haify review --approve --approver <姓名>`；带 `TODO_` 的草稿**只许落 `.ai/draft/`**；`haify fix` 只给 diff，**`--apply` 永远不存在**。我们明确**不承诺**"文档丢进去、无人审核自动进 CI"。

### Q13：「那你们到底承诺什么？」

**承诺**：把 Markdown 接口文档变成**可复核的用例初稿**——生成 → 闸门 → **人工转正** → 真跑。适用形态是**内部少量文档 + 人工复核**。
**不承诺**：任意自然语言 → 无人审核自动进 CI。这是**承诺范围**问题，不是"再优化几轮"能解决的（依据：`docs/交付说明.md` §一）。

### Q14：「出了 bug 谁负责？」

**框架自身的缺陷**由维护方按仓库纪律处理（每个修复配回归用例 + 注入验证）。
**这条特别值得讲**：仓库里连"护栏打偏"（测试没守住该守的东西）都有**自纠记录**——说明它的质量口径不是自我表扬，而是可被反驳的。
