# 存量资产迁移：curl / HAR / Postman / OpenAPI → 标准 YAML 用例

> **目标读者**：手里已经有一堆 Postman 集合/抓包记录的团队
> **一句话主张**：`hconvert` 一键把已有资产转成**能进 CI 的 YAML 用例**，并**默认执行"导出即验证"**——生成不出来就宁可不产出。
> **发布建议**：迁移/落地主题文章、PoC 演示第一步（"先把你们现有 Postman 集合导进来看看"）

## 一、四条导入通道

```bash
# curl：一个文件里可以放多条命令（续行 \ 与 # 注释都支持）
hconvert --from curl    --in curl_examples.txt          --out converted/

# HAR：浏览器 DevTools 录制（Network → 右键 → Save all as HAR）
hconvert --from har     --in demo.har                    --out converted/ --report converted/import-report.md

# Postman：导出 Collection v2.1（默认每个顶层 folder 一个用例文件）
hconvert --from postman --in postman_collection.json     --out converted/

# OpenAPI / Swagger：契约 → 骨架用例（默认每个 tag 一个用例文件）
hconvert --from openapi --in petstore_demo.yaml          --out converted/
```

**真实运行记录**（本机实测，curl 源）：

```
INFO | 已生成用例：converted/curl_examples.yml（6 个步骤、0 条断言、0 个 schema 文件）
INFO | 导出即验证通过：load_testcase + hmake 干跑 + 语法检查
WARNING | [curl_examples] curl 命令里没有响应内容 → 本用例只生成了**请求**、没有生成任何断言
          hint: 断言请按被测接口写：JSON 用 jsonschema_match、XML/SOAP 用 xpath_match、简单片段用 contains；
                或者改用能录到响应的 HAR/Postman 源（hconvert --from har）。
WARNING | [curl_examples] [step 3（第 5 行）] Authorization: Bearer 已替换为 `Bearer ${AUTH_TOKEN}`（值从环境变量读取，明文不入库）
WARNING | [curl_examples] [step 4（第 7 行）] `-F` 里既有普通字段又有文件：…由框架统一组 multipart
```

注意最后几行：**"没生成断言"这件事它自己说出来**，并给你下一步怎么做。这比"默默生成一个永远绿的用例"有用得多（也和第 03 篇的"不让你假通过"一脉相承）。

## 二、三条设计原则（决定了它的边界，也决定了它为什么可靠）

1. **输出 YAML，不输出 Python**
   生成物走**现有 `hmake` 链路**，导入器**不碰** `make.py` / `step_*.py` / `comparators.py`。
   → 想改用例就改 YAML，与手写用例**完全同构**；内核升级不会让导入器行为漂移。

2. **IR 字段与 `TRequest` 对齐**
   `KNOWN_REQUEST_FIELDS` 是唯一事实来源（有单测锁住），**不会生成框架不认的字段**——避开了"pydantic 静默忽略未知字段"这个最难查的坑。

3. **导出即验证（默认开）**
   写完盘立刻做 `load_testcase()` + 渲染干跑 + 语法检查 + 项目定位，**任何一步不过就报错**。
   → **生成物一定能被 `hmake` 处理，否则宁可不产出。** 可用 `--no-validate` 关掉（不推荐）。

## 三、它顺手帮你做了三件"人一定会漏"的事

### 1. 敏感信息一律占位，明文绝不进 YAML

```yaml
config:
  variables:
    AUTH_TOKEN: ${ENV(AUTH_TOKEN)}     # 值从环境变量读，明文不入库
teststeps:
  - name: step 3（第 5 行）
    request:
      headers:
        Authorization: Bearer ${AUTH_TOKEN}
```

Cookie / Authorization / token 这类字段被**占位化**，值走环境变量；配合内核的脱敏（日志、报告、summary 里显示 `******`），**凭据既不入库也不上报告**。

### 2. 能自动生成断言，就顺手生成

| 源 | 断言从哪来 |
| --- | --- |
| HAR / Postman | **录制/示例响应** → 状态码 + **JSON Schema（文件引用）** |
| OpenAPI | **契约 schema** → 状态码 + JSON Schema |
| curl | ⚠️ 命令里通常没有响应 → **明确告警"没生成断言"**，并给替代方案 |

### 3. 迁移不了的写法**明确告警**，不装作转换成功

Postman 的 JS 脚本、外部 `$ref`、未知动态变量……都会**逐条告警**并说明。加 `--report converted/import-report.md` 可导出完整清单（**做了什么、丢了什么、要人工补什么**）。

## 四、产物长什么样（HAR 源）

```
converted/
├── debugtalk.py                 # 项目标记（自动创建——见下）
├── demo.yml                     # 用例
├── demo_test.py                 # hmake 产物（导出即验证时生成）
└── schemas/
    ├── demo_01_get_get.json     # 从录制响应推断的「形状」schema
    └── demo_02_post_post.json
```

**为什么要自动建 `debugtalk.py`**：框架靠它定位**项目根（RootDir）**，`schemas/xxx.json` 这类相对路径都以它所在目录为基准。没有它，RootDir 会退化成"你敲命令时所在的目录"——**换个目录跑就报"文件不存在"**。导入器顺手把这个坑堵了。

## 五、常用参数

| 参数 | 说明 |
| --- | --- |
| `--from` / `--in` / `--out` | 源类型 / 输入文件 / 输出目录（默认 `./converted`） |
| `--name` | 用例名（同时决定 YAML 文件名） |
| `--assertions` | HAR / Postman / OpenAPI：`status+schema`（默认）/ `status` / `none` |
| `--single-file` | Postman：整个集合合成一个用例；OpenAPI：所有 tag 合成一个用例 |
| `--include-tags` / `--exclude-tags` / `--methods` | OpenAPI：按 tag / 方法筛选 |
| `--include-hosts` / `--exclude-hosts` | HAR：按 host 子串过滤（先 include 再 exclude） |
| `--no-dedupe` | HAR：保留完全重复的录制（默认去重） |
| `--no-validate` | 跳过"导出即验证" |
| `--report` | 额外输出 markdown 导入报告 |

## 六、推荐迁移路径（一次 PoC 就能验证）

```
① 拿一份你们真实的 Postman 集合或 HAR  →  hconvert --from postman/har
② 打开生成的 YAML 看一眼               →  请求、headers、body、断言是否对得上
③ 补三件事：base_url（换成测试环境）、变量占位（改 config.variables）、业务断言（按接口补）
④ hrun converted/xxx.yml --html=report.html   →  真跑一遍
⑤ 通过 → 纳入 CI（见第 06 篇）
```

**第 ③ 步是无法省略的**——这是"迁移"不是"变魔术"：录制/契约里造出来的骨架值（时间戳、UUID、路径 id、示例值）**必须按业务替换**。生成的 YAML 头部会**明写这条提示**，`--report` 也会把待补项列出来。
