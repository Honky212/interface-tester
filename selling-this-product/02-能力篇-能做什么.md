# 能力全景：一个 HTTP(S) 接口测试的完整闭环

> **目标读者**：测试工程师（关心"我这个需求它支持吗"）、评审人（关心"够不够用"）
> **一句话主张**：写 → 转 → 跑 → 提取 → 断言 → 报告 → 日志 → CI，链路完整；扩展点足够，**大多数需求不用改框架**。
> **发布建议**：内部技术分享、官网/内网产品页的能力矩阵、投标/评审附件

---

## 一、能力分四层（先看这张表）

| 层级 | 含义 | 典型能力 |
| --- | --- | --- |
| **A. 开箱即用** | 写 YAML 就能跑 | HTTP 全方法、JSON/表单/上传、变量与函数、提取与断言、数据驱动、用例引用、hooks、OAuth2、多环境、报告日志 |
| **B. 写 `debugtalk.py` 就能做** | 机制支持，无需改框架 | 签名/加密、其他认证、复杂断言、动态造数、回调验证 |
| **C. 需要改框架** | 改源码才能支持 | gRPC / WebSocket / MQ / 私有 TCP、Thrift（现状实验性） |
| **D. 明确不适合** | 不是本工具目标 | 性能压测、UI 自动化、移动端原生 |

---

## 二、协议与请求（A）

- **HTTP/HTTPS 全部方法**：GET / POST / PUT / PATCH / DELETE / HEAD / OPTIONS；
- **请求字段齐全**：`params` / `headers` / `cookies` / `json` / `data` / `upload`（multipart）/ `proxies` / `cert`（双向 TLS）/ `stream` / `allow_redirects` / `verify` / `timeout`；
- **文件上传**：UTF-8 安全（中文文件名不炸）、**流式编码**（大文件不把内容一次性读进内存）；
- **URL 拼接**：绝对 URL 直接用，相对路径自动拼 `config.base_url`；
- **超时三级可配**：`request.timeout` → `config.timeout` → 环境变量，**默认 120s**，不会"无限等待"。

## 三、变量与函数（A）

| 写法 | 用途 |
| --- | --- |
| `$var` / `${var}` | 变量引用（step 变量 > 上一步 extract > config 变量） |
| `${func()}` / `${func(1,2)}` / `${func(a=1)}` | 调用**项目 `debugtalk.py`** 里的任意 Python 函数 |
| `${ENV(NAME)}` | 读环境变量（`.env` 文件，不把地址/密钥硬编码进用例） |
| `${parameterize(x.csv)}` | 读 CSV 做数据驱动 |
| `${len($x)}`、`${int($x)}` | 常用 Python 内置（**白名单**内可直接用） |

- 内置函数：`gen_random_string` / `get_timestamp` / `get_current_date` / `sleep`；
- **变量嵌套解析**：变量引用变量，多轮收敛；**有环时明确报错，不会死循环**。

## 四、提取与断言（A）—— 22 个内置算子

**提取**：`extract` + jmespath，`body.data.token`、`body.items[0].name`、`body."user-agent"`（特殊字符加引号）。

**断言**：`validate`，短别名自动归一（`eq` = `equal`、`len_ge` = `length_greater_or_equals`）：

| 分类 | 算子 |
| --- | --- |
| 相等性（4） | `eq` / `ne` / `str_eq` / `type_match` |
| 数值比较（4） | `gt` / `ge` / `lt` / `le` |
| 长度比较（5） | `len_eq` / `len_gt` / `len_ge` / `len_lt` / `len_le` |
| 集合/包含（2） | `contains` / `contained_by` |
| 字符串形态（3） | `startswith` / `endswith` / `regex_match` |
| **结构契约（1）** | **`jsonschema_match`**：响应符合 JSON Schema（`$ref`/`required`/`type`/`format` 真强制），schema 走**文件路径**或 `${func()}` |
| **XML（3）** | **`xpath_match` / `xpath_count`**（完整 XPath 1.0）、**`xml_schema_match`**（XSD 契约校验，支持 `xs:include` 多文件、报错给节点路径） |

**检查项还能断这些**：`status_code`、`headers.xxx`、`cookies.xxx`、`body.xxx`（jmespath）、`text`、`elapsed_ms`、`elapsed_s`、`response_size`、`reason`。

**契约断言的价值**（这是"少写一堆字段断言"的关键）：

```yaml
validate:
  - eq: [status_code, 200]
  - jsonschema_match: [body, "schemas/login.json"]   # 结构正确性交给契约，人工只审业务断言
```

**自定义算子**：`debugtalk.py` 里写 `def has_keys(check_value, expect_value, message="")`，YAML 里直接 `- has_keys: [body, [a, b]]` —— **不用改框架**。

## 五、用例组织与复用（A）

- 一个用例 = `config` + 顺序执行的 `teststeps`；
- **引用其他用例**：`testcase: 路径` + `export: [变量]`，被引用用例的步骤结果并入当前用例；
- **步骤级 hooks**：`${func($request)}` 改请求、`${func($response)}` 看响应；
- **步骤级重试**：`retry_times` / `retry_interval`（**仅对断言失败重试**）；
- **用例级 skip**：`config.skip: 原因`（被引用时也真的会跳过，不是只挂个标记）；
- **参数化**：`config.parameters`（列表 / CSV / 函数），多组参数做**笛卡尔积**；
- **v2/v3 旧格式自动升级**到 v4。

## 六、认证与环境（A/B）

| 场景 | 怎么做 |
| --- | --- |
| OAuth2 Client Credentials | `config.oauth2`，自动取 token + 缓存 + 注入 `Authorization: Bearer` |
| 手动登录拿 token | `extract: token` + 后续步骤 `Authorization: Bearer $token` |
| Basic / Digest / JWT / AK-SK / HMAC / RSA / 国密 | `debugtalk.py` 写函数（内置机制，已验证） |
| Cookie / Session 保持 | 同一用例内自动带上 |
| 多环境：`.env` + `${ENV(...)}` | 一键切环境；`.env` 支持 `KEY=value` 与 `KEY: value` |
| 切换环境不改 YAML | `conftest.py` 加 `--env` 开关（pytest 标准机制） |

## 七、报告、日志与 CI（A）

- `--html`（**单文件可交互报告**，`--self-contained-html`）、`--junitxml`（CI 聚合）、`--save-tests`（汇总 JSON）；
- 每个用例一条 `.run.log`（DEBUG 级明细，含请求/响应与断言结果）；
- **敏感信息脱敏**：`Authorization` / `password` / `token` / `Cookie` / URL 里的 userinfo，在日志、报告、summary 里统一显示 `******`（请求侧、响应侧都覆盖）；
- **CI 模板现成**：`.github/workflows/test.yml` + `.gitlab-ci.yml`（内网 GitLab 友好）；
- 退出码可用：失败即非 0。

## 八、扩展协议

| 协议 | 状态 |
| --- | --- |
| **SQL**（仅 MySQL） | 内置 `RunSqlRequest`，用于"接口写完，验证是否真的落库" |
| **SOAP / XML** | 请求照发（`data` 传 XML + `Content-Type`/`SOAPAction`）；响应体是 bytes，用 `xpath_match` / `xml_schema_match` 断言；**装不了 lxml 也有零依赖退路**（项目级算子，仓库里可直接复制） |
| **Thrift** | ⚠️ 实验性且未验证（Windows 不可用） |
| WSDL 驱动生成用例 | ❌ 明确不做 |

## 九、企业常见需求 → 落地方式（速查）

| 需求 | 怎么做 |
| --- | --- |
| 登录一次、后续接口复用 token | `extract` + `$token`，或 `config.oauth2` |
| 一条用例跑多组账号/数据 | `config.parameters` + CSV |
| 链路用例（建目录→上传→删除） | 步骤顺序 + `extract` + `testcase:` 引用 |
| 请求要签名/时间戳/随机数 | `debugtalk.py` + `${func()}` |
| 断言响应符合 JSON Schema | `jsonschema_match` |
| 断言 SOAP/XML（含前缀漂移、XSD 契约） | `xpath_match` / `xml_schema_match`（A2 内核算子）或项目级算子（零依赖） |
| 验证接口写入是否真的落库 | `RunSqlRequest` + `extract`/`validate` |
| 走公司代理 / 双向 TLS | `proxies` / `cert` |
| CI 里跑 + 出报告 | `hrun ... --html=... --self-contained-html` |
