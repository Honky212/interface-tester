# AI 协作层（`haify`）：把接口文档变成「可复核的用例草稿」

> **目标读者**：想用 AI 提效、但**不敢让 AI 直接动 CI** 的团队
> **一句话主张**：AI 负责**生成与分析**，**判定永远在内核**；草稿进 `cases/` 必须**人工转正**且留痕。
> **发布建议**：AI/提效主题文章、管理层汇报（强调风险可控）、demo 演示脚本

---

## 一、我们不做「一句话生成测试」——说清楚为什么

市面上很多"AI 写用例"的叙事终点是：**文档丢进去，用例自动进 CI**。这个仓库明确**不承诺**这条路径，而且写进了交付说明：

> **承诺**：把 Markdown 接口文档变成**可复核的用例初稿**——生成 → 闸门 → **人工转正** → 真跑。适用形态是**内部少量文档 + 人工复核**。
> **不承诺**：「任意自然语言文档 → 无人审核自动进 CI」。这是**承诺范围**问题，不是"再优化几轮"能解决的。

**理由很实际**：模型会编（引用不存在的字段、猜端点、把示例值当期望值）。把它包装成"自动进 CI"，等于把幻觉直接变成生产事故。

**所以这个 AI 层的设计目标是：提效，但每一条产物都可追溯、可复核、可回退。**

---

## 二、它到底做了什么（一条完整链路）

```
文档(md/txt)
  ├─ 1. 文档体检闸（S-10）      要素/矛盾/可判定率/编码 —— 不合格就退出码 4，并给 TODO 清单
  ├─ 2. 脱敏 + 归一化            ANSI/CRLF/全角/编码（GBK、UTF-8 BOM 都能读）
  ├─ 3. 按接口段切片             标题层级 + 行号范围 + 字节预算（超预算不静默截断）
  ├─ 4. 调模型                   OpenAI 兼容接口（本地 Ollama / 云端均可）
  ├─ 5. 结构校验                CaseDraft 契约：字段白名单 + 每条断言**必须带 source_quote**
  ├─ 6. 修正环 ≤2 轮             按报错类型回喂（预算超限**不重试**——重试不会变好）
  ├─ 7. 引用解析与对账           模型的引用句必须**逐字**出现在文档里，否则降级并记账
  ├─ 8. 确定性断言合并           **不调模型**：字段表 → 类型/范围/枚举断言（可复现）
  ├─ 9. 写盘前置闸门             带"静默陷阱"的产物**不落盘**
  └─ 10. 产物                    `.ai/draft/` 草稿 + unknowns（文档没给的值）+ NEEDS_HUMAN（人要做什么）
```

其中两个细节最值得说：

**①「按接口段逐片」**
一份文档里 N 个接口 → **N 条草稿**，每条**只带自己那一段**的字段断言；段外断言被**丢弃并写进该条的 `unknowns`**。
→ 把"断言错位"这种最难发现的静默错误，变成**可见的记录**。

**②「没有必填列的响应数据表」→ 一条 `jsonschema_match`**
字段缺失**不算失败**、存在但类型错**才算**——这是"响应字段"的本义，也避免误报。

## 三、质量控制：状态 + blocker，而不是"✓ 就完事了"

每条产物都会打印**质量状态**，例如：

```
✓ _api_directory_create
    · 断言 4 条 / 覆盖字段 4 个（文档声明字段 5 个）；本次降级/拒掉 0 条
    · 质量状态：needs_review · unknown-critical
    · 草稿    ：.ai/draft/_api_directory_create.yml
    · ⚠ 产物**只在 `.ai/draft/`** —— 进 `cases/` 必须先人工确认
```

**稳定 blocker 码**（未处置就拦住转正）：`structure-rejected` / `protocol-only`（断言全是协议级，测不出业务错）/ `todo-placeholder`（`TODO_` 没填值）/ `unknown-critical`（引用或端点对不上）/ `no-runtime-evidence` / `mutation-not-passed`。

**只有 `auto_promotable` 才算"无需审核可直接用"**——而在没有隔离执行与变异证据之前，它**当前一律不会出现**（宁可保守，也不给"看着没问题"发通行证）。

## 四、转正与留痕：唯一的进 `cases/` 通道

```powershell
haify review --list                                     # 看草稿 + 质量状态 + blocker
haify review --approve login --approver 张三 `
    --resolve-blocker protocol-only                      # 逐条点名处置后再转正
```

- `--approver` **必填**：**"谁确认的"是留痕的全部意义**；
- **必须逐条点名**处置 blocker——自由文本备注"我看了"**不算处置**，否则闸门会退化成橡皮图章；
- 留痕写 `.ai/reviews/<用例>.json`，含**内容哈希**：确认后又改一行 → **留痕失效，必须重新确认**；
- 带 `TODO_`（文档没给的值）的草稿**只许落 `.ai/draft/`**，**不许进 `cases/`**。

**三条硬边界（可直接写进汇报材料）**：

1. **模型永不判定"通过/失败"**——执行、断言、判定、汇总全在内核；
2. **`haify fix` 只给 diff，`--apply` 永远不存在**（自愈建议只建议、不落地）；
3. **AI 层是旁路包，内核 0 改动**——`pip uninstall` 就是**回滚**，`hrun/hmake` 一切照旧。

## 五、其他四个用得上的能力

| 命令 | 干什么 | 是否调模型 |
| --- | --- | --- |
| `haify analyze` | 失败诊断 → `reports/analysis.md`（附证据包：断言本体 + 脱敏请求摘要 + 响应体截断片段） | 要（断网 → 退出码 3，**无部分写**） |
| `haify summary` | 结果摘要 → `reports/summary.md`：**数字全部由代码渲染**，模型只写 2~3 句导语（导语里的数字还要过白名单复核，违规整段弃用） | 可选（**无模型也有模板版**） |
| `haify fix` | 用例自愈建议：**unified diff**，只动那个字面量、保注释；`status_code`/业务码类一律判"疑似真实缺陷、不给改" | **纯规则引擎，不调模型** |
| `haify serve` / `export` | 只读看板（草稿/质量/审批/作业时间线）+ **离线静态导出**（落成一组相对链接的 `.html`，断网也能看） | 不要 |

`serve` 的 L3 闸门值得单独提：**默认只监听回环**，真发请求必须显式开 `INTERFACETESTER_AI_SANDBOX=on`，非回环主机还要显式列白名单——**拒绝是响亮的，不会静默降级**。

## 六、实测数据（带口径，不吹）

| 指标 | 数值 | 口径 |
| --- | --- | --- |
| 接口片 → 产出草稿率 | **86.7%**（基线）／**92.86%**（复跑） | 15 篇 golden 文档、接口片 15/14 为分母；模型 `gemma4:latest`（本地）；**同模型同机器才可比** |
| 确定性通路（不调模型） | **14/14** 端到端真跑通过 | 文档 → 草稿 → 转正 → 真跑 |
| 模型支持矩阵（`analyze`） | `qwen3.8:27b` ✓（未降级 100%、首发即合格）；`gemma4` 系列 ✗（返回特殊 token） | `probe_p2_prep/out_analyze_models.txt` |
| 引用质量（T28 降级率） | golden 文档 0%；**真实客户文档 40%**（30/75） | 引用句必须逐字出现在文档里才算数；**两者样本不同，不可直接比大小** |

> **一条 0 成本的试用路径**（不调模型、不出网、可复现）：
> ```powershell
> python -m interfacetester_ai gen 你的文档.md --assertions-only
> ```
> 它会按接口段逐片产出草稿 + 质量状态 + unknowns，让你先看清"这份文档能不能自动出用例"。

## 七、为什么"AI 层做成旁路包"是个卖点

| 传统做法 | 本项目的做法 |
| --- | --- |
| AI 功能改内核 → 升级风险大、回滚困难 | **内核 0 改动**，`pip uninstall interfacetester_ai` 即回滚 |
| AI 包依赖一堆三方库 | AI 包**零三方依赖**（只用 stdlib + 仓库内已有依赖） |
| 模型能读写任何文件 | **写盘边界登记在册**：只有 `cache/manifest/pending/reviews/export`（仅 `.ai/`）、`diagnosis/doc_quality`（仅 `reports/`）、装配器（`cases/` + `.ai/draft/`）能写；`llm/gen/web/confirm/audit` **一律不写盘**，机器可查（`bench/write_boundary_scanner.py`） |
| 依赖关系混乱 | **只 import 内核公开面**，禁止 import 运行内核；内核**永不** import AI 包（有反向依赖断言） |
