# 选型对比：和 Postman、自研脚本、上游 HttpRunner 比，它强在哪

> **目标读者**：要写选型报告/答辩的人
> **一句话主张**：不是"功能最多"，而是**"结果最可信 + 迁移成本最低 + 能进 CI"**。
> **发布建议**：选型报告、技术评审答辩、竞品对比页

---

## 一、和常见方案比（客观版）

| 维度 | Postman / Apifox（客户端） | 自研 `requests` + pytest 脚本 | 上游 HttpRunner | **InterfaceTester** |
| --- | --- | --- | --- | --- |
| 写用例门槛 | 极低（点） | 高（要会代码） | 低（YAML） | 低（YAML） |
| 链路用例（登录→带 token→操作） | 勉强 | 好 | 好 | 好（`extract` + `testcase:` 引用） |
| 用例可评审/可 diff | 差（JSON/客户端状态） | 好（代码） | 好（YAML） | 好（YAML，产物是 pytest 用例） |
| 进 CI | 卡（要 runner/许可证） | 好 | 好 | 好（`hrun` 一条命令 + 两个 CI 模板） |
| **断言能力** | 脚本/片段 | 自己写 | 基础算子 | **22 个内置算子**（含 JSON Schema / XPath / XSD 契约） |
| **假通过防护** | 无（靠人） | 全靠自己 | 无 | **生成期闸门 + 57 条防线登记**（第 03 篇） |
| 存量资产迁移 | 有（它自己的格式） | 手工 | 手工 | **四源导入**（curl/HAR/Postman/OpenAPI，默认"导出即验证"） |
| 敏感信息 | 客户端里（易泄露） | 看你怎么写 | 看你怎么写 | **占位化 + 日志/报告/响应侧统一脱敏** |
| 离线/内网 | 商业版常需要授权服务 | 好 | 好 | **好**（两 wheel + 锁版本清单，已实测离线安装） |
| AI 辅助 | 有（偏"生成请求"） | 无 | 无 | **有**（文档→草稿，且**判定与转正留给人+内核**） |
| 协议范围 | HTTP + 更多 | 都能写 | HTTP/SQL/… | HTTP 全方法 + SQL（MySQL）+ SOAP/XML；**Thrift 实验性未验证** |

> **一句话选型建议**：
> 你们缺的是"点着方便" → 客户端工具够用；
> 你们缺的是**"用例能进 CI、结果可信、团队能协作维护"** → 这才是本项目的价值区。

---

## 二、和"上游 HttpRunner"比，多出来的东西

继承上游的全部好处（写法兼容、生态与文档熟悉），另外补了三块：

| 补了什么 | 具体 |
| --- | --- |
| **质量工程** | 57 条"假通过/假失败"防线逐条登记；生成期闸门；脱敏覆盖到响应侧与 URL；告警带可操作 hint |
| **断言与契约** | `jsonschema_match`（JSON 契约）、`xpath_match`/`xpath_count`（完整 XPath 1.0）、`xml_schema_match`（XSD 契约） |
| **AI 协作层（旁路包）** | `haify`：文档→草稿 + 分析 + 摘要 + 修复建议 + 只读看板；**内核 0 改动、删包即回滚** |

**并且这些补齐都带机器判据**：2026-09-27 本机全量 **2545 passed / 121 skipped / 6 deselected / 2672 collected / 1826 subtests / 0 failed**。

## 三、什么情况下**不要**选它（我们主动劝退）

| 你的需求 | 建议 |
| --- | --- |
| **性能压测 / 并发压测** | 用 JMeter / k6 / Locust。本项目不做并发治理与报告聚合 |
| **UI / 移动端自动化** | 用 Appium / Playwright 类工具 |
| **gRPC / WebSocket / MQ / 私有 TCP** | 当前不支持，需要改框架 |
| **Thrift 接口** | 内置但**实验性且未验证**（Windows 上不可用）——生产用请自行验证 |
| **想要"文档丢进去、用例自动进 CI、无人审核"** | 明确**不承诺**；本项目的 AI 只产草稿，人工转正才进 `cases/` |
| **需要集中式平台（多团队权限、用例市场、度量大屏）** | 本项目是**框架/工具链**，不是平台；平台层需要另行建设（仓库里的只读看板只覆盖草稿/审批/作业） |
| **需要 HTTP 4xx/5xx 自动判失败** | 不自动——**成败由你的 `validate` 决定**（这是设计选择：有的场景 4xx 才是预期） |

## 四、你们可能会问的"隐性成本"

| 项 | 实情 |
| --- | --- |
| 学习成本 | YAML 语法 + `debugtalk.py` 机制，**一天足够**；仓库里有从零搭的 6 步教程与最小示例 |
| 迁移成本 | `hconvert` 四源导入；**但"骨架值按业务替换 + 补业务断言"这步无法省略** |
| 维护成本 | 有正式 pytest 体系与 CI 模板；改框架前请读 `docs/架构与调用链.md`（守卫着 57 条防线） |
| AI 成本 | 可全本地（Ollama），**回环免 API key**；也有**完全离线**的确定性通路（`--assertions-only`，不调模型） |
| 许可成本 | 内核 **Apache-2.0**（含 NOTICE，衍生自 HttpRunner v4.3.5）；AI 包独立发行（**零三方依赖**） |

---

## 五、可直接引用的三句结论

1. **"这不是又一个 YAML 测试框架，而是把 HttpRunner 4.3.5 的工程化做到了'防假通过'这一层。"**
2. **"它的产物就是 pytest 用例——你的 IDE、CI、既有测试资产全都接得上。"**
3. **"它的 AI 是旁路包：内核 0 改动、删包即回滚、草稿必须人工转正、模型永不判定通过/失败。"**
