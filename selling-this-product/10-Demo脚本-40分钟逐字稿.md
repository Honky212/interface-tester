### 10:00–17:00　③ ★ 假通过对照（全场最重要的 7 分钟）

**【说】**（先讲清为什么有两条对照）

> 现在进入今天最重要的部分。仓库里有两个**故意写坏的**对照用例，它们断的是**同一个东西**，区别只是一个字段名。
> 我先把丑话说在前面：**这两个用例，一个会是绿的、一个会是红的——而绿的那一个是错的。**
> 我们来看看到底哪个更危险。

**【做】**

```powershell
$env:QUICKSTART_RUN_CONTRAST = "1"
$env:BASE_URL = "http://127.0.0.1:18080"     # 指向本地 mock，全程离线
hrun examples\quickstart\contrast_false_pass.yml
```

**【应看到】**（**重点：`1 passed`**）

```
WARNING | teststep '想断 status_code 是不是 404——但断言字段名拼错了' 中存在无法识别的字段：
          ['validates']，它们会被忽略（不会写进生成的用例）。
1 passed, 1 warning in 0.11s
```

> **【说】**：看清楚——**它是绿的，退出码是 0。**
> 为什么？因为断言字段名写成了 `validates`，**多了一个 s**。框架不认识它，于是给了**告警**，然后……**把它忽略了**：那两条断言一个字都没写进用例。
> **告警不是失败。** 这就是"假通过"的标准形态：**你以为在被守护，其实没有。**

**【做】** 再看对照组（同一个断言，字段名写对）：

```powershell
hrun examples\quickstart\contrast_assert_fail.yml
```

**【应看到】**

```
ERROR | assert status_code equal 404(int)  ==> fail
1 failed in 1.32s
```

> **【说】**：同一个断言、同样的环境，**写对了就是红的**。
> 所以真正的结论是：**"用例通过"这个信号本身不可信——除非你能证明它真的断到了东西。**
> 接下来我给你们看这个框架是怎么把这个洞堵上的。

**【翻车预案】**
- 第一条如果报 `1 failed`（而不是 passed）→ 说明请求真发出去了但连不上（`BASE_URL` 没设或 mock 没起）。台词：*"这里失败了，正好说明——**最危险的是它明明该红却绿了**；我们把 BASE_URL 指向本地 mock 再看一次。"* 然后重设变量重跑。
- **千万别在没设 `QUICKSTART_RUN_CONTRAST=1` 时跑**：那样会显示 `skipped`（对照用例默认跳过），**冲击力全没了**。

### 17:00–22:00　④ 生成期闸门：把同类问题**在跑之前**拦死

**【说】**

> 刚才那个"字段名拼错"，在**运行**时只能告警——因为框架分不清"你要断这个字段"还是"你手滑"。
> 但有一大类错误，其实**在转换阶段就能精确判定**，那就没必要等它跑起来。
> 这个框架的取向是：**能判定的，一律响亮报错、退出码非 0，而且不生产物。**

**【做】** 演示一：算子名拼错（`eq` 写成了 `equall`）

```powershell
python -m interfacetester make selling-this-product\demo\bad_comparator.yml
"exit=$LASTEXITCODE"
```

**【应看到】**

```
FunctionNotFound: unknown assert comparator: equall
自定义断言算子请定义在项目 debugtalk.py 里，签名 (check_value, expect_value, message="")
内置断言算子（22 个）: contained_by, contains, endswith, equal, greater_or_equals, ...
exit=1
```

**【做】** 关键一击：**产物根本没生成**

```powershell
Test-Path selling-this-product\demo\bad_comparator_test.py
```

**【应看到】** `False`

> **【说】**：注意三点：报错**点名了用例和步骤**、**把 22 个合法算子列给你**、**并且没有产出任何东西**。
> 也就是说：这类错误**根本进不了 CI**，不会变成一条"看起来正常"的用例。

**【做】** 演示二：最隐蔽的一种——**算子写成了 Python 内置名**

```powershell
python -m interfacetester make selling-this-product\demo\bad_builtin.yml
"exit=$LASTEXITCODE"
Test-Path selling-this-product\demo\bad_builtin_test.py
```

**【应看到】**

```
ERROR | failed to make test file: ...\bad_builtin.yml
FunctionNotFound: 'print' 是 **Python 内置函数**，不能作为断言算子。
exit=1
False
```

> **【说】**：为什么要单独演示这一条？
> 因为**修复前的框架会真的去调 Python 内置的 `print`**——而 `print(...)` 返回 `None`、**不抛异常**，于是断言**静默通过**。
> 一条写错名字的断言，把一个真实的错误变成了绿灯。**现在它在生成期就被拦死了。**
>
> 这一类的洞，仓库里逐条登记了 **57 条**，每条都写明"**谁拦它、哪个用例守着它**"。这是我今天最想让大家带走的东西。

**【翻车预案】**
- 忘了 `chcp 65001`、报错里的中文是乱码 → 现场补一句：*"我们先把编码切一下"*，重跑（**别念乱码**）。
- `$LASTEXITCODE` 不是 1（管道污染导致）→ 直接看**有没有报 `FunctionNotFound`** 和 **`Test-Path` 是不是 `False`**，这两条才是重点。

### 22:00–27:00　⑤ 存量迁移：curl / HAR / Postman / OpenAPI → 一键变用例

**【说】**

> 前面都是"新写用例"。但我知道在座各位手里**已经有资产**了——Postman 集合、抓包记录、Swagger/OpenAPI 契约。
> 重新手写一遍是最蠢的做法。这个框架有个导入器 `hconvert`，四条通道：curl、HAR、Postman、OpenAPI。
> 它有一个我特别喜欢的规矩：**导出即验证**——生成完立刻做一次加载、一次干跑、一次语法检查，**过不了就报错，宁可不产出。**

**【做】** 用仓库里的 curl 示例演示：

```powershell
hconvert --from curl --in examples\data\curl\curl_examples.txt --out .tmp_demo_converted
```

**【应看到】**（节选，注意这几行 **WARNING**）

```
INFO | 已生成用例：.tmp_demo_converted\curl_examples.yml（6 个步骤、0 条断言、0 个 schema 文件）
INFO | 导出即验证通过：load_testcase + hmake 干跑 + 语法检查
WARNING | [curl_examples] curl 命令里没有响应内容 → 本用例只生成了**请求**、没有生成任何断言
          hint: 断言请按被测接口写：JSON 用 jsonschema_match、XML/SOAP 用 xpath_match……
                或者改用能录到响应的 HAR/Postman 源（hconvert --from har）。
WARNING | [curl_examples] [step 3（第 5 行）] Authorization: Bearer 已替换为 `Bearer ${AUTH_TOKEN}`（值从环境变量读取，明文不入库）
```

**【做】** 看产物：

```powershell
Get-ChildItem .tmp_demo_converted
Get-Content .tmp_demo_converted\curl_examples.yml
```

**【应看到】** 目录里有 `curl_examples.yml`、`curl_examples_test.py`、**`debugtalk.py`**、`__init__.py`；YAML 里 `Authorization: Bearer ${AUTH_TOKEN}`，而 `AUTH_TOKEN` 在 `config.variables` 里写成 `${ENV(AUTH_TOKEN)}`。

> **【说】**：三个点请注意：
> 一，**它主动告诉我"没生成断言"**，而不是默默给我一条永远绿的用例——**这条提示比多生成几条垃圾断言值钱**；
> 二，**敏感信息被占位了**：`Authorization` 的值变成 `${AUTH_TOKEN}`，值从环境变量读，**明文不入库**；
> 三，它顺手**建了 `debugtalk.py`**——那是"项目门牌号"，没有它，相对路径会跟着你敲命令的目录漂，换个目录跑就报文件不存在。
>
> 迁移这一步**有一件事必须人做**：录制/契约里造出来的骨架值（时间戳、UUID、示例值）得按业务替换、业务断言得补。**我们不假装这是全自动的**——`--report` 可以把"要人工补什么"列成清单给你。

**【翻车预案】**
- 输出目录已存在同名文件 → 先 `Remove-Item -Recurse -Force .tmp_demo_converted` 再跑（**别用真实业务目录演示**，避免覆盖）。
- 想看更漂亮的产物（带 schema 的）→ 用 HAR 源：`hconvert --from har --in examples\data\har\demo.har --out .tmp_demo_har`（仓库里就有这个样本）。
- ★**不要把 `hconvert` 的输出用管道过滤**（如 `| Select-String`）：它的一部分日志走 stderr，Windows PowerShell 5.1 下经管道可能**丢掉 `INFO | 已生成用例…` 和 `INFO | 导出即验证通过…` 这两行**（本稿实测踩到）。**直接让它原样打印**。

### 27:00–34:00　⑥ AI 协作层：提效，但不失控

**【说】**（先把承诺边界讲清，这是加分项）

> 最后一块是 AI。**我先把边界说清楚，再说能力**：
> 这个东西**不承诺**"文档丢进去、无人审核自动进 CI"。它只承诺一件事：把 Markdown 接口文档变成**可复核的用例初稿**。
> 为什么这么保守？因为模型会编——编字段、编端点、把示例值当期望值。把它包装成"自动进 CI"，等于**把幻觉直接变成生产事故**。
>
> 所以它的设计是：**AI 只产草稿；判定永远在内核；草稿进 `cases/` 必须人工确认，且留痕。**

#### 6.1 先看"安全闸门"：没配模型时它绝不偷偷出网

**【做】**（先确认没有配模型）

```powershell
Remove-Item Env:INTERFACETESTER_AI_BASE_URL -ErrorAction SilentlyContinue
Remove-Item Env:INTERFACETESTER_AI_MODEL -ErrorAction SilentlyContinue
haify gen "project-three\统一文件服务平台-接入应用接口文档-测试1.md"
"exit=$LASTEXITCODE"
```

**【应看到】** 一大段**配置指引**（告诉你该设哪些环境变量、为什么不用项目 `.env`、为什么回环地址也必须显式开沙盒），结尾：

```
未配置时本工具 **不会隐式出网** —— 这是刻意的默认值。
exit=2
```

> **【说】**：**退出码 2，一个请求都不发。** 安全策略不是写在文档里的，是写在代码里的：没配就一定不出网，真出网还要显式开沙盒、非回环主机还要显式列白名单。**拒绝是响亮的，不会静默降级。**

#### 6.2 不调模型也能出草稿：确定性通路（离线、可复现）

**【做】**

```powershell
python -m interfacetester_ai gen "project-three\统一文件服务平台-接入应用接口文档-测试1.md" --assertions-only
```

**【应看到】**（节选）

```
✓ _api_directory_create
    · 断言 4 条 / 覆盖字段 4 个（文档声明字段 5 个）；本次降级/拒掉 0 条
    · 质量状态：needs_review · unknown-critical
    · 草稿    ：.ai/draft/_api_directory_create.yml
    · unknowns：.ai/draft/_api_directory_create.unknowns.json
    · ⚠ 产物**只在 `.ai/draft/`** —— 进 `cases/` 必须先人工确认
✗ _oauth2_token
    · 质量状态：rejected · structure-rejected
    · 需人工  ：.ai/failed/_oauth2_token/NEEDS_HUMAN.md
```

> **【说】**：注意这份输出里的几个"反常识"的点：
> 一，它是**按接口段逐片**出的：文档里 N 个接口 → N 条草稿，每条**只带自己那一段**的字段断言（**断言错位会被写进 unknowns，而不是悄悄塞进别的用例**）；
> 二，它给了**质量状态**和 **blocker**：`needs_review · unknown-critical` 意思是"能看，但有一条必须人处理的未知项"；`rejected · structure-rejected` 意思是"**闸门拒了，别用**"，并指向一份 `NEEDS_HUMAN.md` 告诉你人该干什么；
> 三，**退出码 0 只代表"草稿产出完成"，不代表能进 CI。**

#### 6.3 转正：唯一的进 `cases/` 通道

**【做】**

```powershell
haify review --list
```

**【应看到】** 每条草稿的**质量状态 + blocker + 下一步动作**（例如：`rejected · structure-rejected；★闸门**硬结论**（点名处置覆盖不了）→ 按 NEEDS_HUMAN.md 改好文档后重新生成`）。

> **【说】**：转正的命令是 `haify review --approve <草稿> --approver <姓名>`。
> 两个硬规矩：**`--approver` 必填**（"谁确认的"是留痕的全部意义）；**blocker 必须逐条点名处置**（`--resolve-blocker`），**自由文本备注"我看了"不算处置**——否则闸门就退化成橡皮图章。
> 而且留痕里带**内容哈希**：确认之后又改了一行，**留痕失效，必须重新确认**。
